# 统一登录入口与原型对齐（2026-10-21）

用户确认：企业超管和子账号共用一个入口；邀请码仅企业超管首次开通时填写，已开通账号后续登录免填。本要求替代 10/20 下线登录邀请码入口的决定；10/19 取消登录后超管专属码二次校验的决定继续生效。

## 页面与认证

- 去掉“企业超管 · MX 登录 / 子账号登录”切换，共用账号、密码、邀请码（选填）和登录按钮。账号保持当前 MX / 子账号真实格式，不强制邮箱；无注册入口。
- 沿用只读原型的品牌、盾牌图标、760px / 280px 桌面双栏、52px 40px 36px 表单内边距、32px 标题间距和28px字段间距。手机单栏内边距36px 24px 28px，保留可见视口约束、表单滚动和法律链接。
- 邀请提示：“企业超管首次开通数港时填写，已开通账号及子账号无需填写。”仅通过既有 MX 密码认证后的 DataPort 专用邀请准入，不创建企业、赋予角色、修改密码或恢复超管专属码。
- 子账号继续由 Hub 的 `dataport.local_credentials/local_sessions` 验证及创建 HttpOnly Cookie，保留首次改密、有效企业/成员/角色、Origin、CSRF 与网关隔离。MX 回调成功后清除可能遗留的本地账号 Cookie，避免沿用错误身份。

## 接口与数据流

1. 新增 `POST /auth/login/prepare`，只接受 `{login}`。离开账号字段且未填密码/邀请码时，识别 MX 账号并建立原有 OIDC 浏览器往返；本地/未知账号返回 `{ready:true}`，不提交密码、登录或兑换邀请。连接结束后本地表单恢复密码焦点；关闭弹窗后不会继续导航。
2. 新增 `POST /auth/login`，接受 `{login,password,inviteCode?,formId?}`，MX 提交附 `x-mx-csrf`。先核对两套账号目录：仅本地命中走原独立认证；仅 MX 命中走原 SSO 表单；两边命中返回409并提示联系管理员；未命中返回统一401。密码错误、停用、限流或任一目录服务不可用均不回退另一身份。
3. 两个目录识别接口仅服务间使用：Hub 网关保护的 `POST /internal/v1/portal/local/resolve`；Auth 的 DataPort 客户端 Basic 认证 `app-account/resolve-login` 动作。只返回是否存在，不返回账号资料、企业或凭据。保留停用、过期和重复别名占用，且执行持久限流；前端不传认证来源或租户。
4. 共享 SSO 的 `unifiedLogin` / `loginAdmission` 为仅限 `mx-harbor` 的显式选项；`loginOnly` 继续拒绝注册和飞书动作。其他应用保持原行为。已有 MX 准入直接登录，不重复兑换或扣邀请名额。
5. 无暖 SSO 表单且已通过自动填充等方式填完凭据时，第一次提交只建立浏览器 SSO 连接，返回同一表单后需再次输入密码/邀请码。只记住账号提示；密码与邀请码不存储、不进 URL、不自动重放。普通输入会在账号字段离开时提前连接。
6. 登录提交的超时、网络故障、5xx或无效回执锁定重复提交，提供“核对登录状态”只读恢复。明确的账号/密码/邀请拒绝仍可修改重试。

统一入口的目录判定需要 Auth 与 Hub 两侧接口就绪；任一不可验证时拒绝判定。旧独立账号登录接口和已有会话读取继续兼容；未修改全局账号策略、既有权限、网络或其他应用登录。
