# 数港原型对齐与企业权限

2026-10-15 增量：平台管理员现可使用数港网页「平台管理」添加企业及超管、配置专属邀请码；原 Admin Token 接口保留为运维通道。账号角色、Secret 挂载和 migration 151 的新部署步骤见 [平台管理说明](platform-administration.md)，替代下文仅支持 Admin Token 配码的旧入口说明。

本次实现范围为 DataPort、Hub 数港服务端和 Launcher/Auth 账号链路。原型目录未修改；MX-H2I、罗盘和其他应用的账号登录、网络与原授权保持原有实现。未执行生产部署、真实付费查询或付款。

## 已实现

- 恢复原型的 16px rem 基准；主导航为新建查询、用量概览、API Keys、我的订阅、账单与发票、接口文档。企业账号、日志审阅和消息放到账户菜单，底部保留联系客服。
- 页面入口、直接 URL、支付返回、BFF 和 Hub 使用企业权限；每次 Hub 请求重新验证身份、有效成员关系、角色与超管会话。客户端聚焦及每 30 秒刷新权限，受限页面先拦截再加载业务数据。
- 统一 MX 账号登录。数港停止自助注册和旧首次入场码兑换；不会影响其他 MX 应用的注册策略。数港不再通过登录自动创建个人企业。
- 企业超管新登录后验证专属邀请码。只保存加盐 scrypt 摘要；校验许可绑定 BFF 生成的会话摘要，最多保留 30 天并始终受真实 SSO 会话有效性限制。新登录、更换账号、网关凭证或邀请码轮换后不能复用旧许可。连续 15 分钟内失败 5 次后限流。
- 超管创建 MX 员工账号或关联已有账号。新建员工仅获数港应用准入；已有账号保留原密码及其他应用资料。邀请链接 24 小时有效，指定员工登录后确认加入。企业权限仍由 Hub 管理。
- 初始密码在 Auth 用独立 AES-256-GCM 密钥加密，只能由所属企业超管查看，查看记录进入审计。员工修改实际密码后旧初始密码不可再查看。关联已有账号不提供初始密码或企业代重置。
- 固定角色可复制为企业自定义角色；角色修改使用版本号，冲突返回 409；使用中的角色不能归档。成员启停仅改变本企业成员关系。企业显示名称是企业内备注，不修改统一 MX 资料。
- 浏览器通过服务端委托查询，不获取网页查询用的 API Key。原有产品授权、Key 与调用者权限交集、订阅额度和日限额仍在原查询网关结算。每条查询保存稳定操作编号，未确认结果不会自动重发。
- 企业共享历史，服务端搜索、总数与每页 5 条；包含原产品批次结果。旧记录操作者未记录时保持空值，原 Public API 按 Key 隔离的历史接口不变。
- Excel 支持 xls/xlsx、IP 列识别、去重、500 行和 5 MB 限制、模板、逐条进度、停止后续派发及结果导出。停止时正在执行的一条继续结算；未知结果不自动重试。
- 风险等级环、基础资料、风险/网络标签、IP 复制、真实坐标地图和信息报错入口。风险参考建议依据等级规则生成，页面明确 AI 尚未接入，不补造缺失评分或坐标。
- 订阅页包含服务端实时目录、试用、购买、续订、升级和消费优先设置；账单支持搜索、状态/日期筛选、详情和导出。价格及已售权益沿用原业务服务。
- API Key 签发时完整凭证只展示一次，列表不返回完整凭证；撤销校验企业归属。工单持久化并区分本人/企业读取，审计记录实际操作者、目标、时间、结果和请求编号。
- 发票功能明确未接入并禁用；增加隐私政策、用户协议和必要 Cookie 说明。

## 角色默认权限

| 角色 | 默认能力 |
| --- | --- |
| 企业超管 | 全部数港业务权限；专享角色定义与初始密码查看 |
| 企业管理员 | 查询、批量、历史/结果导出、用量、Key、订阅读取、受限成员编辑/启停/分配、企业工单；默认无账单/审计/角色定义/开户权限 |
| 分析员 | 查询、批量、历史/结果导出、用量、文档、本人工单 |
| 财务 | 用量、订阅购买/续订/升级、账单/导出、发票入口、本人工单；无查询及 Key 权限 |
| 只读成员 | 历史、用量、文档、本人工单；无新查询和导出权限 |

现有 Hub 成员在超管明确分配数港角色前保留原授权映射；不自动降权、升级或重写原角色。自定义角色不能赋予超出操作者权限的角色；超管和自身成员关系不能通过普通成员操作更改。角色定义和初始密码查看不随自定义角色下放。

仅获订阅购买权限而无企业账单权限的成员，可在订阅页继续本人创建的待处理订单；支付返回也仅能定位本人订单。不会因此获得企业账单列表或他人订单的付款信息。未完成超管邀请码校验时，支付返回定位信息暂存，验证完成后继续读取。

## 上线配置与顺序

1. 备份 Auth 原数据和密钥、Hub 原数据库。先部署 Launcher/Auth，再执行 Hub 新迁移 `149_dataport_enterprise.sql` 并部署 Hub，最后部署 DataPort。不得修改已应用迁移。
2. 为账号服务生成独立的高熵服务令牌，分别以只读文件挂载到 Auth 和 Hub；两端配置 `MX_DATAPORT_ACCOUNT_TOKEN_FILE`。不要使用平台 Ops/Admin Token 或把令牌放进前端环境变量。
3. 仅在 Auth 挂载独立、持久化的 32 字节十六进制加密密钥文件，配置 `MX_DATAPORT_CREDENTIAL_KEY_FILE`。此文件必须随账号数据备份；不能直接轮换后遗失旧密文的解密能力。
4. Hub 配置 `MX_DATAPORT_ACCOUNT_ORIGIN` 指向 Auth Internal API 根 origin；使用 HTTPS，或现有隔离内网的 HTTP 私有地址 / Kubernetes Service FQDN。固定调用 `/internal/v1/dataport/accounts`，不开放任意账号管理代理。该接口只接受专用令牌和受限操作，配置缺失只使员工开户/密码功能返回 503，不阻塞原 SSO 或其他产品启动。
5. 平台管理员通过原 Hub Admin Token 通道调用 `POST /internal/v1/admin/dataport/owner-code`，JSON 为 `{ "tenantId": "企业 UUID", "memberId": "超管 UUID", "code": "12–128 位专属邀请码" }`。此路由不在 DataPort BFF 白名单中。邀请码不写入审计明文，由平台管理员安全交付；轮换立即使该超管原许可失效。应在切换新 DataPort 前为现有超管配置并交付邀请码。
6. 为现有成员明确分配数港角色后验收对应页面；不会改动 API Key、原订阅、历史订单、Pay 支付事实或其他 MX 应用权限。

托管账号创建跨 Auth/Hub 使用同一命令 UUID 幂等恢复。超时重试必须保持原账号、角色和操作编号。不要将未确认操作改成新编号重新开户；如角色被并发归档等导致 Hub 最终绑定失败，平台管理员应核对 Auth 已创建账号与原命令后处理，不应重建或覆盖现有账号。
