# 大屏查询详情与新建查询滚动修复

## 生产复现

2026-10-21 在已登录 goodmorning 的 Chrome 中，只回看现有历史，不执行查询、导出、付款或权限变更。页面显示历史 18 条。

实际视口 2560 × 1328。打开已有详情后，外层 `.app-main` 的 `scrollTop=313`，而可见正文 `.harbor-console` 的 `scrollTop=0`。IP 输入框顶边为 -140.80px。向上滚动后偏移不变；点击“新建查询”清除了详情，但外层仍为 313，输入框顶边为 -94.80px。

原因：`scrollIntoView` 会滚动所有可滚动祖先，包括 `overflow:hidden` 的外层。大屏正文已经全部容纳详情，正文无法再向上滚动，外层的隐藏偏移仍保留；原新建查询只重建组件，没有重置保留下来的正文滚动容器。

复现截图外置于 `screenshot/query-scroll-20261021/before-new-query.png`，不纳入 Git。

## 修复

- 外层工作区使用 `overflow:clip`，不再成为可被程序滚动的隐藏容器；正文维持原有可见滚动条和独占底部空间的页脚。
- 详情聚焦保留 `preventScroll`，定位只对当前正文滚动容器执行，不再调用跨祖先的 `scrollIntoView`。立即定位避免旧动画与新建查询重置互相竞争。
- 查询页每次挂载在绘制前重置正文至顶部，覆盖同页“新建查询”、从其他页面返回与切换空间的组件重建。
- 不修改历史、结果状态、查询请求、额度或权限。
