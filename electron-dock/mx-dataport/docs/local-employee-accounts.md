## 历史实现与运行基础（凭据规则以上节为准）

2026-10-18 用户确定：企业超管使用统一 MX 登录；企业超管创建的员工子账号不依赖 MX。此决定替代早先 Auth 托管子账号方案。

## 使用方式与边界

- 登录弹窗提供“企业超管 · MX 登录”和“子账号登录”。超管通过 Launcher 的 DataPort 专用邀请为 MX 账号首次开通数港，后续正常统一登录；每次登录的超管专属码挑战已取消，不新增平台管理员。
- 企业账号页创建数港独立子账号，用户名 3–64 位，以字母开头，仅字母、数字、点、下划线和短横线，大小写不区分。独立子账号名在数港全局唯一；与同名 MX 账号互不关联，不按名称合并身份。
- 初始密码由超管设置并确认，48小时内可用于首次登录。首次登录及超管重置后必须修改，未修改前仅可读取自身会话/账户、改密或退出，不得查询、购买或查看企业业务数据。新密码12～128位，修改后全部旧会话失效，需重新登录。超管可单独鉴权查看更新后的当前密码。
- 员工角色、自定义角色仍属于对应企业，页面与服务端都按实时权限校验。停用员工删除其数港会话，重新启用不会恢复旧会话。企业 API Key 仍独立，不因成员停用自动撤销，页面继续提醒超管检查。
- 子账号在账户菜单可进入账户安全，修改资料、密码或撤销自己的全部数港会话。子账号不获得 MX、Launcher 或 Hub 管理端的登录身份、平台权限或其他企业权限。
- “关联已有 MX 账号”仍是可选旧兼容能力，须对方使用对应 MX 账号接受邀请，原有账号桥接配置仅影响此兼容路径，不影响独立子账号。它不是新建子账号的前置条件。

## 已有托管子账号

不自动迁移、不读取 MX 密码、不删除旧记录。超管对旧托管成员确认“重置密码”时，将该成员显式转为数港独立登录：保留 memberId、企业角色、工单、消息、查询记录和审计；新初始密码仅用于数港。此后该企业不再接受该成员的 MX 数港登录，其他应用和 MX 密码保持原状。

普通“关联已有 MX 账号”的成员不能由超管重置。旧托管账号名不符合独立账号规则、与已使用的独立账号名冲突，或该成员已属于另一企业独立凭据时，迁移拒绝并保持原状，需单独处理，不自动合并/转移。旧账号创建结果未确认的请求，仍须先核对原 Auth/Hub 受理记录，不能用新操作编号重复创建来替代核对。

## 存储与运行配置

Hub migration `159_dataport_local_accounts.sql` 只增加 `dataport` 下的凭据、会话与登录限流表，并给原 managed_accounts 增加默认 `mx` 的认证方式。旧迁移文件及旧记录保持原样。

密码使用异步 scrypt（N=32768、r=8、p=3）加盐哈希；密码密文使用 AES-256-GCM，认证附加数据绑定企业和成员，加密密钥从 **已有 Hub API Key pepper** 按数港专用用途派生。必须保留并备份原 Hub pepper，不生成新值替换它。用户改密后删除初始密码状态、同步更新当前密码密文，所属企业超管可单独鉴权查看；只保留当前密码，不保留旧密码历史。

数港 BFF 使用独立 `__Host-mx_dataport_local` Cookie（Secure、HttpOnly、SameSite=Lax），原始会话令牌不进入前端 JSON或日志；Hub 只存令牌哈希。会话最多30天、每账号最多10份，同时校验凭据版本、成员、企业状态及角色。登录在数据库中按账号最多10次/15分钟、共享总预算600次/15分钟，密码操作验证最多10次/15分钟；每进程最多同时4个密码派生，满载拒绝而不排队。登录失败使用统一文案，限流不修改账号密码或状态。

沿用现有 DataPort SSO profile（提供固定站点 Origin）、BFF→Hub 专用 gateway 凭证和 Hub 数据库，无需创建新的 Auth 账号服务 Secret。独立子账号请求不访问 Auth/UserInfo；超管 MX 登录仍访问原认证服务。原有 Portal/Public/Hub Admin 隔离、订阅、支付、Key 和查询计费保持原规则。

前轮新增的 Launcher 三文件和 Hub/Auth 专用 Secret 挂载已恢复；删除前轮 `accounts status/configure` 初始化 CLI。**不要删除线上已有 Secret、MX 账号、密码记录或旧加密密钥**，它们可能仍属于历史托管记录或其他使用方。
