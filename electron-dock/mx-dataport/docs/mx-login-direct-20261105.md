# MX 登录弹窗显示修复

2026-11-05 用户明确本轮只修复数港登录显示。上一版新增的 Auth 密码证明协议、共享 SSO 扩展和数港服务端启用标记全部撤回，恢复到 `ad0a43b0` 之前的认证实现。此前要求发布 Launcher/Auth 的说明由本文替代。

## 当前行为

- 切换到企业超管登录后保留同一个弹窗框架，显示账号、密码及首次准入邀请码，MX 初始化期间输入和提交暂不可用，避免输入后被原有浏览器认证跳转清空。
- 沿用既有 `/auth/sso/form` 读取、`/auth/sso/start` 初始化和 MX 浏览器 OIDC 往返。初始化自动衔接，无需点击“继续 MX 登录”。有效表单直接填写、提交；过期自动回调保留重试入口，防止导航循环。
- 闪烁的显示因素包括：App 原先首帧将弹窗设为关闭，等副作用才打开；返回时再次播放遮罩和弹窗淡入动画。现在根据 `account` 参数在首帧打开弹窗，去除登录专属的重复入场动画；其他业务弹窗动画保留。
- 登录准备期间结构不切换成另一张卡片，进入既有认证跳转时保持连接状态。切回子账号或关闭弹窗后的迟到响应不执行跳转；密码不保存、不重放。子账号继续使用原独立登录接口。

## 修改范围及发布

新增功能改动仅在数港前端及对应测试。Launcher/Auth、共享 SSO、数港服务端与 API 类型相对 `5c026ed1` 已完全恢复；没有新增账号协议、角色权限、Secret 或迁移。

**本次只需发布数港，不要求更新 Launcher/Auth 或 Hub。** Git 中的 Launcher/shared 文件差异是撤回上一版误扩大的实现，不是新增功能。

## 验证

真实 AccountDialog 组件交互测试覆盖：切换不关闭弹窗、加载中保持字段框架、原初始化自动衔接、跳转前不提前启用表单、错误后重试、过期回调不循环、快速切回忽略迟到结果、原端点提交及重复点击保护。App 首屏渲染测试在不执行副作用时验证 `?account=1` 已打开登录，而普通访问仍保持关闭。

运行数港相关登录/会话测试及类型/生产构建。浏览器视觉验收仍待部署后进行；测试不代表已验证实际浏览器所有跨文档加载帧。截图和验证产物放在外置 `screenshot/login-presentation-20261105/`。
