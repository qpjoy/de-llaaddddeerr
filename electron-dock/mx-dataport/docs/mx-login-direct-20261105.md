# MX 登录直接填写账号密码

2026-11-05：替代此前“继续 MX 登录”的中间入口。切换到“企业超管 · MX 登录”立即显示账号、密码和首次开通专用邀请码；读取表单准备信息不跳转、不卸载输入框。点击“登录”才提交并进入统一 MX 认证。

## 实现与边界

- DataPort BFF 为匿名表单签发五分钟有效的 HttpOnly 登录事务和独立 CSRF。首次提交校验 Origin、CSRF、表单 ID，原子领取事务，防止并发重复提交。
- Auth 仍验证统一 MX 账号、密码、尝试频率、应用准入及首次专用邀请码。凭据错误保留表单供用户修改，不自动重试。
- 凭据通过后，Auth 只保留随机、一次性、两分钟有效且绑定客户端及 OIDC state 的证明；DataPort 用已有加密 SSO 存储保留该证明。密码不进入数据库、浏览器存储、URL 或跨页面重放。
- 点击登录后的浏览器导航仍通过原 Auth 交互 Cookie、OIDC state/nonce、PKCE、授权码与回调校验建立会话。证明不能代替浏览器交互 Cookie或直接签发数港会话。完成时再次检查账号状态与应用准入。
- 仅 DataPort 显式启用，其他 MX 应用保持原登录方式。旧版已初始化的 MX 表单仍兼容；过期表单读取可重新准备，不自动导航。员工独立登录不变。

## 发布

按 **Launcher/Auth → DataPort** 发布本次 `pro`。Hub 无需重新部署，无数据库迁移、Secret 新增或密钥轮换；无需重新 enroll 或初始化账号。Auth 需要先更新，旧版本不会提供本次凭据证明能力，数港会明确提示服务需要更新。

沿用服务器现有发布方式和环境参数。Launcher 发布时保留 `MX_INSIGHT_HUB_DEPLOY=0`，避免连带发布 Hub；仅发布数港前端不足以启用本次完整流程。

## 本地验证与发布后验收

本地：实际 AccountDialog 交互测试、BFF 员工/会话测试；Auth 原生处理器测试；隔离 PostgreSQL + HTTPS + 真实 OIDC Provider 全链路测试；数港及 Launcher Server 类型/生产构建。覆盖立即显示输入框、无切换跳转、错误后手动重试、并发提交只成功一次、首次准入、证明重放/过期/跨客户端/错 state/撤权拒绝，以及其他应用兼容。

本地浏览器预览仍依既有约束未执行。部署后需检查：无 MX 初始化状态下切换入口直接填写；输入不会被准备完成覆盖；错误密码和邀请码原位提示；正确填写一次完成登录；子账号切换及首次改密正常。不得将本地协议测试称为生产页面验收。
