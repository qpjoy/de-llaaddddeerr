本轮落实 UI 复查中的明确差异，以及用户已确认的成员停用提示、托管子账号密码重置、客服工单处理和通知流程。修改范围为 DataPort、Hub 数港模块及 Auth 数港账号命令；原型只读，没有连接真实供应商、执行线上账号变更、查询、付款或部署。

- Key 列表补权限和创建时间，保留正式有效期；固定列宽、表格边框、同行名称及撤销样式。签发替代 Key 保留原 Key 的授权集合和环境，不自动撤销原 Key。空名称不能提交；完整凭证仍仅在创建成功时展示。
- 历史、工单、日志和订单表格列宽不再随样例内容任意漂移。日志恢复双行操作者、中文刷新及 IP 目标展示，搜索/导出均采用查询 IP。

- 文档增加 JavaScript、Python 示例；本地示例演示仅按授权 OpenAPI 生成合成示例，不发送请求、不扣额度。实际接口定义与路径保持不变。

## 服务端与权限

1. **托管密码重置**：新增 Auth 专用命令 `reset-password`。Hub 必须先校验本企业已验证超管、有效非 owner 托管成员和稳定命令 UUID。Auth 再校验原始托管企业、数港开户来源、普通 MX 用户角色和独占数港准入。现有 MX 账号、其他企业账号、已提权或跨应用账号不能走该命令。
2. Auth 生成新密码并使用既有 AES-GCM 持久密钥加密；只返回 `reset:true`，不在命令或审计中保存明文。旧密码失效，设置统一 Web 会话失效时间并撤销原用户令牌。使用原命令重试不会再重置一次；新初始密码仍须超管单独请求查看，员工自行改密后失效。
3. **工单闭环**：新增追加式回复/状态记录、版本检查与命令去重，支持已提交、处理中、已关闭。工单变更、审计和通知在同一数据库事务中提交。普通成员只能查看本人，企业工单读取权限可查看本企业。
4. **平台处理网页**：Hub 既有 Admin Token 会话可进入 `#/dataport/support`。企业超管、Launcher 普通会话和 DataPort BFF 均不能调用平台处理接口。未新增数港平台管理员角色。
5. **通知**：工单更新仅向提交人发送状态与工单编号，不向全企业广播问题内容；读取、单条/全部已读均同时校验企业与接收人。原订阅消息继续使用原生命周期采集方式。
6. **邀请码网页**：Hub 既有 Admin Token 会话可进入 `#/dataport/owners`，为已绑定 owner 的成员配置专属邀请码。沿用原受限接口和摘要存储，不创建账号、不提升角色、不保存邀请码明文。
7. **企业改名**：仅已验证超管能修改当前企业名，并记录审计；不修改统一 MX 用户资料。
8. **日志与成员**：IP 检索覆盖 `detail.ip`，同时覆盖企业备注名、登录账号和请求编号；成员列表服务端分页、搜索，员工总数与当前页条数独立。

## 有意保留或尚未开放

- 统一 MX 登录、超管会话校验、自定义企业角色、真实商品价格/期限/额度及支付交付继续沿用现有规则。
- 联系方式仍选填，未强制所有统一 MX 用户必须有邮箱。
- 成员操作通知的事件与接收范围尚未确定；本轮通知范围为原订阅提醒和本人工单更新。
- 发票真实申请/交付、对公转账核款、取消/退款流程仍未开放，没有加入无实际后端的操作按钮。
- 本地演示不等于线上免费沙箱。API 历史继续包含既有网页及 API 批次，API 记录没有员工身份时不伪造归因。

## 发布顺序

本次不能只部署前端：需要 **Auth → Hub（含 migration 154）→ DataPort**，沿用原账号服务令牌和加密密钥，不重复 enroll、不轮换原密钥。

先把本地 `pro` 提交推送到远端；服务器在仓库根目录确认工作区后同步：

```bash
git switch pro
git pull --ff-only origin pro
```

沿用服务器原发布参数，依次在各自目录执行：

```bash
# electron-dock/mx-launcher：沿用原 Auth/Launcher 发布参数
bash scripts/manage.sh ops internal-production deploy

# electron-dock/mx-insight-hub：发布数港服务端并自动执行新增迁移
MX_INSIGHT_SYNC_LAUNCHER=0 MX_SMOKE_DATA=0 \
  MX_INSIGHT_BUILD_PROXY=http://127.0.0.1:7788 \
  bash scripts/manage.sh ops internal-production deploy

# electron-dock/mx-dataport
MX_HARBOR_BUILD_PROXY=http://127.0.0.1:7788 \
  bash scripts/manage.sh ops internal-production deploy
```

示例代理端口采用本次服务器记录的 7788，部署时以服务器已验证配置为准。逐步确认服务就绪再继续，不执行真实查询或付款作为部署探针。

Hub 新增 `154_dataport_support.sql`，不修改已应用迁移。发布窗口先暂停客服处理，待 Hub 全部相关副本和 DataPort 更新、浏览器刷新后再处理工单；旧通知读取代码不认识新增工单类型和接收人字段，不应与新处理端混跑。保留数据库与原加密密钥，回退时不要删除迁移或回复/消息记录，应保留新版消息读取兼容逻辑。
