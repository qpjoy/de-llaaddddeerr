# 未开通订阅时的 Key 创建提示

用户手工完成 shugangtestA 的新企业 owner 绑定后，签发 Key 返回“请先开通企业订阅”，同时被追加“核对上次创建结果”。

代码核对：Hub `dataport-routes.mjs` 在调用 `createApiKey` 前，查找当前企业专用的 `commerce:ip-risk:<tenantId>` 活跃调用者；找不到时明确返回 HTTP409 / `subscription_required`。这个分支未创建 Key。该调用者由 IP 试用或套餐权益交付创建，无需手工创建普通调用者来绕过订阅流程。未通过浏览器或生产 SQL 核实该企业的订单/订阅，因此不能将提示等同于“肯定没有购买记录”；若已有已生效订阅，应继续查交付状态和服务身份。

前端此前对任何 Key 创建失败都追加不确定结果提示。现将明确业务拒绝与不确定响应分开：`subscription_required` 说明前往“我的订阅”领取试用或开通 IP 套餐；其他明确拒绝保留原提示；网络异常、408、5xx 与无效响应继续要求先核对 Key 列表，不自动重放签发请求。

新增 3 项请求边界测试，与既有成员写入和企业界面测试共 14 项通过，无跳过。类型检查、生产构建通过，资源为 `main-BBnxdudv.js`。仅 DataPort 前端变更；无 Hub、账号权限、真实 Key、查询、订单或付款操作。生产提示待部署后复验。
