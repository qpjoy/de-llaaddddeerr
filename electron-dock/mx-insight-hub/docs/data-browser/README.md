## 运行约束

- PostgreSQL 是数据真相；本次不使用 ES、不创建索引版本、不重放 outbox、不调用上游和模型。
- 每个进程每个 store 最多同时接受 2 个浏览查询，超出返回独立 429；每次聚合在独立只读 repeatable-read 事务内完成，普通读取 statement timeout 为 3 秒，账号/热点全量聚合为 15 秒，超时返回独立 503，不伪装成零数据。列表只取 200 字正文预览；详情按 UUID 读取完整当前字段。
- 参数由 Zod 白名单验证，拒绝重复字段、DSL/索引名等未知字段；账号筛选必须带平台；SQL 参数化。每页 1–50，最多 500 页。
- 全量聚合可能扫描大表。有界超时只是失败边界，不是容量保证。上线前必须在脱敏生产规模副本执行 EXPLAIN (ANALYZE, BUFFERS)，检查 CPU、连接等待、p95 和并发影响。高基数数据应迁入独立增量统计表或只读副本；不要取消超时硬扛。
- 列表返回 `total: null`、`totalStatus: not_computed`，不等待全库精确计数；不同页面属于实时读取，期间入库可能让 offset 分页移动。未来超大规模导出用绑定过滤和快照的 cursor，不能把目前列表当完整导出。
- 普通 UI 复用现有 Data Center 可见性投影，隐藏供应商和 raw 管理字段；权威记录不被重写。完整原始证据继续由原 Admin 数据中心接口管理。
- 内存开发模式返回明确“需要 PostgreSQL”错误；不自动生成样例或假统计。浏览器夹具只用于测试，不进入产品代码。

## 仍需交付的数据分析链

先完成 [Agent 与检索可行性](./agent-search-feasibility.md) 中的执行和评估闭环，再接入画像和事件分析。建议拆分：

1. `account-profile`: 已采集资料＋有上限的作品样本 → 标签候选＋证据 ID/revision。画像单独版本化，不改 canonical。
2. `account-relations`: 入库变更触发候选召回＋周期修复，关系含类型、方向、置信度、证据和有效期。稳定身份关联与“内容相似”分开；不得自动合并账号。
3. `content-analysis`: 摘要、主题、情感、质量和结构化实体；明示样本/评论覆盖率。来源文本不能成为工具执行指令。
4. `event-clustering`: 时间窗口＋关键词/向量召回＋去重与聚类 → 事件候选；同标签不是事件合并依据。
5. `signal-detection`: 以时间序列计算增量/加速度/异常分位数；缺少基线显示“证据不足”，禁止零分冒充无风险。提示“需关注”而不是未经评估的预测。

拟增表：`analysis.runs`、`analysis.results`、`analysis.relations`、`analysis.events`、`analysis.event_members`、`analysis.signal_snapshots`。共同保存 input revision/hash、artifact/sequence 版本、evidence IDs、confidence、generatedAt、expiresAt、status、错误分类。`proposed/accepted/rejected/stale` 与运行成功/失败是不同轴。查询时 revision 不匹配标 stale；删除与撤销通过 outbox 使分析失效。

画像幂等键为 `agent + artifactHash + subjectId + inputRevision + policyVersion`。周期任务只处理变更、过期或漏算对象，租约抢占、重试退避和预算均在 Worker；原入库事务只发分析意向，不等待 LLM。跨账号关系保存双方 revision。上线应先离线评估和 shadow，小比例灰度，保留一键停用 Worker 和回退旧结果。

## 历史：2026-09-16 第一轮账号超时修复（查询方案已由下节替代）

原账号名称查询对每个账号的全部历史名称执行有序 `array_agg`，最终只取第一项；这会放大全量聚合的排序与内存成本。改为 `max(text[])` 保存 UTC 采集时间、记录 ID、名称这一份最大候选，每组只保留一个状态。未知采集时间不会覆盖最新已知时间的名称，空名称仍忽略，稳定 ID/平台分组、精确总数和按记录数排序不变。

账号/热点独立使用 15 秒有界预算，不修改其他路由的超时。每个 store 仍最多两个实际查询，相同筛选的在途请求共享执行；成功的聚合页在进程内复用 30 秒（最多 32 个条目，每条最大 64 KiB），失败不缓存。重启自然清空；不是持久化快照。页面显示统计生成时间，不把缓存统计称作逐请求实时结果。详情和内容查询不进入缓存。

本地嵌入式 PostgreSQL 50 万条记录/1 万账号比较：单次旧查询 1193ms、新查询 728ms，结果一致；这是开发环境单次观察，不是线上 SLA。验证覆盖缓存隔离、过期、失败后重试、并发合并与未知日期。若更大规模仍超过预算，应以真实 EXPLAIN/规模证据建设持久化增量账号统计；不能无限放宽超时。


## 基础查询：索引分页、组合搜索与导出（界面已由下节更新）

第一轮只优化账号名称聚合，内容列表仍在分页前全量物化正文并计数，且 `collected_at` 排序与既有索引不符。当前内容列表先在 `canonical_records_admin_feed_idx` 上按 `coalesce(event_time,collected_at,last_seen_at,first_seen_at), id` 读取 pageSize+1 个 ID，再按主键取当前页正文/标签。没有发布日的记录仍能浏览；显式发布日期过滤会排除无日期记录。列表显示本页条数，不能把未计算的全库总数显示为零。

账号默认目录排序为平台＋稳定 ID，使用新增 `canonical_browser_accounts_v1_idx` 分组分页；名称在确定当前页账号后逐个索引查最新非空名称，不聚合所有名称。内容数量排名需要显式选择，仍是全量聚合。账号标签/日期汇总改为点击“加载账号标签汇总”后独立查询，其超时不阻塞内容列表。

新增 `scripts/data-browser-serving-indexes.sql`：建立账号和事件时间索引，使用 CONCURRENTLY、2 秒锁等待、15 分钟维护预算，修复中断后遗留的无效同名索引。K8s `manage.sh` 在部署 API 前执行；其他部署方式需要由数据库管理员以独立 psql 会话执行该文件（不能放入事务 migration）。未执行索引脚本的环境不能期待账号目录加速。无需 ES 全量重索引，无需修改 Launcher。

筛选契约：`q`（账号名称/ID或内容标题/正文的字面子串，不是任意 DSL）、`platform`、`objectType`、`contentType`、`tag`（精确）、`from/to`（北京时间发布日，结束日包含整天）、`sort`。平台和类型有常用菜单，也可输入未列出的标识；类型按入库规范字段精确匹配，不根据文件 URL 猜测。热点原有 7 天窗口与日期筛选取交集。关键词使用独立 title/body ILIKE 条件，允许既有 trigram 索引参与；百分号、下划线和反斜杠按字面搜索。

所有列表共用 `GET /internal/v1/admin/data-browser/export`，沿用 Admin Token 权限和可见性投影。`format=csv|json`、`maxRows=1..500`（默认 200），其余字段与列表一致。从已应用筛选第一条开始，在一个只读事务内生成有界快照；内容字段包含完整正文。CSV 处理逗号、引号、多行、UTF-8 BOM 和公式注入；JSON 保留对象与筛选/时间/范围元数据。超过条数时返回 `truncated: true`，文件名含 `partial`，UI 明确“不是全量导出”；超过 16 MiB 整体拒绝，不生成悄然截断文件。详情支持单条 JSON 导出。尚无无限量后台导出任务。

Agent 卡片现在为“智能分析能力 / 尚未接入”，附有画像、相似账号、摘要/主题/情感、事件关联与趋势预测的具体说明。`analysis: not_integrated` 不是任务队列状态，也不宣称没有其他 Hub Agent 运行。

验证：99 项数据浏览/导出/旧数据中心/身份/转发/Sites测试通过；50 万条长正文记录的嵌入式 PG EXPLAIN 确认首屏命中索引，单次内容读取约 3ms、账号约 10ms（本地观测，不是线上 SLA）；桌面与 390px 页面使用明确夹具验证组合筛选、真实 CSV 下载、详情、懒加载汇总和热点跳转。`manage-script.test.sh` 的已有 Docker proxy snapshot 断言与 HEAD 中 `30-public-api.yaml` 的现状不一致而失败，此处没有改动该 manifest 或断言。未执行生产部署或生产数据库变更。

### 精确总数与分页

新增 Admin Token 专属 `GET /internal/v1/admin/data-browser/statistics`，接收与列表相同的 Zod 筛选参数。`total` 为当前筛选的精确账号/记录/热点标签数，附 `totalStatus: exact`、`computedAt`、`cacheMaxAgeSeconds: 120`。统计键排除 page/pageSize/sort/summary，翻页不重复全库计数；不同平台、账号、类型、关键词、日期、标签保持隔离。

列表仍先返回有界分页结果，随后独立请求计数。UI 在结果头部显示总条数、当前页/总页数，在底部提供上下页及跳页。总量加载或失败不清空列表，失败有单独重试入口。计算尚未完成绝不显示 0。总页数不截断成 500；若实际超过 500 页，仍展示真实页数，同时提示可直接浏览前 500 页。offset 列表与总数属于不同读取快照，持续入库时会变化；缓存时间明示。

计数最多每 store 同时执行 1 条查询，独立于既有 2 个列表/画像/导出槽位；15 秒 statement timeout，只读 repeatable-read，成功缓存 120 秒，最多 32 项，重复在途请求合并，失败不缓存。计数不读取正文返回值，也不对全库 JSON 进行展示型物化；关键词本身仍可能需要扫描匹配字段。总数接口不属于上游转发路径。

### 索引与上线

在原在线索引脚本中补充 `canonical_browser_profiles_v1_idx`，只索引未删除资料对象的 `(platform, accountId, collected_at DESC, id DESC)`，避免大账号查资料时遍历全部内容。延续 CONCURRENTLY 和受控锁等待，索引共三项。无需 ES 索引变更/全量重建，也没有新增 canonical 写入或入库触发器。

### 不补造的分析能力

来源标签统计可作为第一版内容画像，但不是模型生成的兴趣或人群标签。粉丝增长、互动趋势需要历史观测序列；相似账号需要版本化分析结果、证据与评估；情感、受众和舆情预测缺少结果时不显示分数。原“尚未运行”改为具体的“Agent 画像尚未接入”能力说明，并保留后续 Agent 规划文档。本次不触碰 MX-H2I 登录、网络、公共转发与账本。
