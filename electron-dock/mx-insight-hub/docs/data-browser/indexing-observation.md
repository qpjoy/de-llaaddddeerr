# 索引任务 ETA 与瓶颈观察

数据中心的搜索重建和向量化区域显示真实运行指标。迁移 `089_indexing_observation.sql` 只添加观测字段；部署不启动重建、不启用后台向量化，也不更改预算、并发、HanLP 后端或模型路由。

## 如何使用

由操作员按原有按钮启动任务，连续取得约 30–60 秒的有效进度后显示 ETA。无需额外运行模型测试或容量扫描。暂停、预算用完、无在线 Worker、观测过期、进度停滞时隐藏 ETA 并解释原因。

| 任务 | ETA 口径 |
| --- | --- |
| 全文重建 | 当前投影首轮构建剩余数量 ÷ 最近实际确认速度。content 与 chunks 分开采样；续跑先记录原有 checkpoint，旧进度不计入本次速度。后续增量追平、别名操作、删除校验没有可靠分母，因此不宣称整个操作的完成时间。 |
| 历史向量初始化 | 固定 manifest 的 pending ÷ 最近已处理与 superseded 的合计消化速度。版本变化转增量仍单独展示，不宣称成功生成了向量。新记录不扩大初始化范围。 |
| 日常增量 | 当前 pending + running 队列 ÷ 最近 done 数量变化。队列持续入库、合并或重试时估计会变化；计数倒退重新采样。失败队列另外显示，不表示这些记录已完成。 |

ETA 是吞吐外推，不是承诺。向量进度沿用缓存的 30 秒统计，不新增全库扫描；Admin 进程重新启动或切换到尚无样本的副本后会重新采样。配置变化亦重新采样。最近超过 90 秒没有新完成样本时不继续展示乐观倒计时。刚重新出现进度时，近 5 分钟窗口仍可能包含之前等待时间，估计会逐渐稳定。

## 指标和调整依据

- PostgreSQL：连接获取、SQL 往返、事务与锁等待。先看慢 SQL、连接池、I/O，不能只靠增加 Worker。
- Embedding：完整模型调用耗时，包含路由内部重试。检查 TPM/RPM、429、模型吞吐，再决定是否增加任务并发。
- HanLP：严格分词调用耗时，包含批处理等待与重试。检查推理并发、批量、排队和 CPU；不切换备用分词器。
- Elasticsearch：bulk 和索引管理请求的等待。检查磁盘水位、merge、写队列及 429。

表格覆盖最近约 5 分钟的已结束调用，并显示仍在等待的调用及已等待时间。累计等待最多是排查线索，不是精确的 CPU 瓶颈证明；并发调用时间可重叠，不能当成耗时占比相加。重试在依赖内部成功时只算一次完整调用；HTTP 成功但 bulk 单项失败，以现有任务错误记录为准。

向量区显示 `min(配置并发上限,在线 Worker 数)`，它是可承接上限，不是当前实际任务数；实际执行数仍读取队列的 running。预算等待、延后调度、待重试可重叠，失败记录须结合下方错误查看。配置或容量建议仅展示，不自动调整资源。

## 开销与安全边界

每进程采用固定时间桶，最多约 31 桶；无文本、SQL、向量、凭据或异常原文。每 Worker 10 秒复用原心跳更新一次小型 JSON，全文重建每 10 秒最多一次观测写入（切换/完成时也可能刷新）。观测写入不累积排队，失败不终止任务。指标只通过已有 Admin 接口呈现，公共调用、鉴权、计费和 MX-H2I 路径不挂载观测包装器。

全文任务最终指标持久保留在操作行；Worker 指标只保留在线观测窗口。服务器时间需同步；客户端按服务器采样点展示等待时长，不声称逐秒实测。
