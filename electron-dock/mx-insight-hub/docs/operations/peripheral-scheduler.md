# 手机外设接入与安全调度

更新：2026-10-09。入口：**系统设置 → 外设**（`#/settings/peripherals`），仅 Hub Admin Token 可见/可调用。

## 本次实现与边界

根据 `/tmp/使用文档.md` 接入 Android XHS PoC 的 `/api/state`、`/api/search`、`/api/next`、`/api/note`。此前 Hub 的小红书能力属于 TikHub/JustOne 等渠道，不等于已集成这台手机。本模块不替换它们，不经过客户计费，不自动写 Canonical，也不依赖 mx-rig。mx-rig 后续可以作为独立验收中心，不能成为当前手机可用性的前置条件。

手机 PoC 仍然只能串行。Hub 可以并发接收请求并排队，多个**不同手机、不同账号资源**可以同时执行；同一手机固定一个执行槽。注册默认暂停，运行政策、连接配置、会话、任务、恢复证据均保存在 Hub 所用 PostgreSQL（mx-common 数据平面）的 `peripherals` schema 中，不读写 Launcher 身份数据库。

已实现：

- 注册/编辑（暂停并排空后）、读取配置、显式状态检查、启用/暂停、任务队列和分页历史、完整成功响应及原始文本证据。
- 每设备 PostgreSQL 行锁、唯一运行中任务索引、幂等请求、领取令牌、60 秒执行租约、完成后至少 2 秒冷却。
- 搜索会话固定在设备上，下一页要求匹配 `sessionId + expectedPage`，同页重复提交只能复用原幂等键。切换关键词/查询详情前显式结束会话，避免 PoC 全局分页状态串线。
- 每设备最多 20 个未完成任务、排队有效期 5 分钟、搜索会话空闲有效期 10 分钟。已接受的任务不会因 UI 关闭而取消。单副本最多并行执行 4 台不同设备；当前目录上限 200 台，不代表已经做过 200 台实测。
- 所有设备调用失败、409、504、响应形状/页码/身份不匹配或租约过期都保守进入 `unknown`，设备暂停并隔离，后续未派发任务取消。不会自动重试、抢占、重启应用或重新装补丁。
- 人工恢复要求最新 revision、核验说明、近期连接检查、租约结束，以及明确确认旧执行器/手机任务已停止。恢复后仍暂停；原任务仍是 unknown。迟到响应作为 lateEvidence 留存，不改变已恢复设备或原任务的未知结论。

未实现/不能声称：真实手机验收、线上部署、手机端 taskId/幂等协议、自动故障接管、抢占式调度、跨设备迁移搜索会话、自动识别真实登录账号、租户/Public API、Canonical 入库或计费。账号资源标识/ADB 序列号由管理员如实填写；唯一索引只能约束声明，不能识别不同别名背后其实是同一手机/账号。

## 服务抽象：非抢占设备调度，不是长事务

请求保存为 Job → 短事务锁定 Device 并领取 → 提交事务 → 写入派发意图 → 调用固定 PoC 接口 → 短事务校验领取令牌并保存结果。

数据库连接不跨手机 HTTP 调用持有。多个 Hub Admin 副本共享相同数据库、相同设备 ID 和相同地址白名单；同设备所有配置/会话/任务写入使用同一行锁。不同设备不使用全局执行锁。独立小连接池将外设存储故障与 Hub 主请求连接池隔离。公共监听器不构造调度器；缺少迁移/配置只令外设模块不可用，不成为登录、健康检查或现有渠道的依赖。

这类似 CPU 的**不可抢占设备队列**，而不是时间片切走再恢复执行。数据库锁只保护 Hub 的领取事实，**无法撤销已经发出的手机操作**。租约过期不等于手机空闲；当前 PoC 没有 taskId、去重、取消/终态确认，因此不能承诺物理执行 exactly-once 或自动 HA。

暂停阻止后续领取，已领取的任务仍可能发往手机并正常收尾。只能取消 `queued`；无法中止已经领取/派发的任务。

## 服务器接入前置条件

1. 先执行 Hub migration `139_peripheral_scheduler.sql`，再更新 Hub Admin/API/UI；无需部署 mx-rig、Launcher 或 mx-pay。回滚应用可保留新增表，避免删除审计记录。
2. 手机宿主机的 ADB forward 必须固定到真实序列号，例如在**手机宿主机**执行 `adb -s SERIAL forward tcp:18081 tcp:18081`。这是运维配置步骤，Hub 不自动运行命令、不修改 VPN/DNS/防火墙。
3. Hub Pod/容器的 `127.0.0.1` 指向自身，**不是手机宿主机**。必须确认从实际 Admin 运行环境可达的私有受控 HTTP(S) 地址。多副本中同一地址必须永远指向同一台物理设备，禁止把各节点不同手机都注册成同一个 loopback origin。
4. 设置 `MX_INSIGHT_PERIPHERAL_ORIGINS` 为逗号分隔的精确 origin，例如 `http://phone-gateway.internal:18081`。不接受路径、凭证、query、hash；不跟随重定向，不接受任务自带目标地址。白名单是部署安全边界，其余运行配置在页面管理。
5. PoC 本身不提供已验证的鉴权协议。不要把 18081/ADB 5555 暴露公网，也不要用 `adb -a` 扩大暴露。使用现有受控内网/隧道、访问控制或后续设备代理，保证只有 Hub 执行器能访问。DNS/转发配置也是受信运维边界，禁止将白名单指向不可信可重绑定域名。
6. 停止其他会调用 `/search`、`/next`、`/note` 的脚本和人工旁路；否则 Hub 无法保证会话正确。不要同时对同一 PoC 运行两套独立 Hub 数据库。

`scripts/manage.sh` 在 K8s 部署时保留未显式指定的已有白名单；显式空值清空白名单，在新配置生效的副本中禁止新派发。Compose 通过同名变量传入。白名单变更需要更新所有 Admin 副本；运行中的旧副本不受新配置追溯影响，撤销访问应先页面暂停、排空并完成副本更新。移出白名单的设备会自动暂停，不影响其他设备。

没有 PostgreSQL 的普通内存运行模式不能驱动手机。界面会明确报告不可用；测试中的 MemoryPeripheralStore 仅供隔离模拟。

## 逐级验收（需要操作者明确触发）

1. **只读连通性**：注册设备 → 点击“检查连接（只读）”。只调用 `/api/state`，最多 5 秒/64 KiB；保存原始 JSON 和观察时间。文档未定义 state 的业务字段，HTTP 200/JSON 可达并不证明设备空闲、XHS 登录或补丁健康。
2. **单任务契约**：现场确认手机后启用调度 → 一次搜索 → 查看任务结果。验证关键词一致、第一页为 1、`count` 等于 items 长度、hasMore 为布尔值、detailInput 完整。设备调用总超时 35 秒、响应上限 4 MiB；超限/不完整不伪装为成功或截断结果。
3. **会话连续性**：原会话提交下一页，确保页码递增；重复同一幂等键返回原任务，不驱动第二次翻页。新关键词或详情在会话结束前被拒绝。搜索结果按受限管理员证据保存，不承诺业务完整度。
4. **详情**：结束会话 → 原样粘贴搜索返回的 `https://www.xiaohongshu.com/explore/...` detailInput → 显式提交详情。Hub 正确 URL 编码，核对返回笔记 ID；不用 GET 参数把 detailInput 传给 Hub。PoC 文档未规定详情 `type`，因此不依赖该字段。
5. **单机竞争**：在隔离测试设备/模拟服务上同时提交多个任务，确认单设备最多一个 running。同 idempotencyKey+body 始终对应同 jobId；不同 body 不能复用 key。队满返回 429，不无限等待。
6. **故障演练**：先在模拟环境断开响应/重启执行器。任务变 unknown，设备隔离，没有自动下一次执行。原请求重试提交只能读取该任务，不能重新派发。真实手机演练需要现场可恢复条件，不能靠盲目重启破坏原用户联网/登录。
7. **恢复**：先停止可能存活的旧执行器/完成网络隔离，再确认手机实际任务终止；显式检查连接、记录理由并恢复为暂停，重新启用。**人工确认不能被自动 /state 探测替代**。恢复只解除设备隔离，不声称已核实原业务结果。

上传/保存动作和实际 HTTP 派发分开：Hub 返回 202 只说明持久化接受；轮询任务状态。提交响应丢失时保留原请求和幂等键确认，不能生成新 key。UI 在当前浏览器进程中保留不确定提交（跨该页面切换），不会把含 xsec_token 的请求写入 localStorage/sessionStorage；刷新会丢失内存请求，此时先查看持久任务记录，不能盲目新建。

## 管理 API

所有地址以 `/internal/v1/admin/peripherals` 开头，必须携带原有 `X-MX-Insight-Admin-Token`。Launcher/SSO 平台管理员、租户及 Public Key 都不能访问；不扩张权限。

| 方法/路径 | 作用 |
| --- | --- |
| GET `/` | 设备目录、白名单、当前副本扫描状态；无设备调用 |
| POST `/` | name/host/serial/accountKey/origin 注册，默认暂停 |
| GET `/{id}?before={jobId}` | 设备、每页最多 50 条任务摘要、最近 50 条事件；无设备调用 |
| POST `/{id}/probe` | 显式 `/api/state` |
| POST `/{id}/control` | action + revision；configure/enable/pause/close-session/cancel/recover |
| POST `/{id}/jobs` | operation + idempotencyKey + 参数，返回 202/jobId；可安全复用原 key/body 确认 |
| GET `/{id}/jobs/{jobId}` | 完整受限任务结果/原始证据；无设备调用 |

`search` 参数 keyword；`next` 参数 sessionId、expectedPage；`note` 参数 input。调用控制动作前读取最新 revision。恢复还需 reason、confirmedStopped=true；结束会话需 sessionId；取消排队需 jobId。错误状态不会触发代理回退或重复手机请求。

## 后续机架/集群扩展

第一阶段就是当前实现：一台手机、固定设备和账号、Hub 控制面 + 现有 PoC。新增独立手机只增加设备记录和受控地址，不提高单机 capacity。

第二阶段在每个宿主机加独立 **Device Agent**：设备发现和真实 serial/账号绑定，mTLS/应用凭证，幂等 commandId，持久派发账本、任务状态/结果查询、心跳、单机互斥、检查 fencing generation、明确取消/重置。Agent 在手机操作前强制校验代际，防止旧 Hub 执行器晚到请求；即便如此，已执行的手机动作仍需明确终态核验。它可以独立部署，无需先部署 mx-rig。

第三阶段再引入能力池和工作流：按设备类型/账号/机架/健康选择资源，固定顺序原子领取 `device + account + host USB capacity`，每租户公平队列、优先级与老化、配额、排队 ETA、工作流检查点。任务可以从任意空闲设备开始，但同一搜索后续页面仍保持亲和性；不能把 PoC 全局搜索状态想当然迁移到另一台手机。

最后才接入 Hub 现有授权、成本/计费与 Canonical/outbox，并让 mx-rig承担模拟器、协议兼容测试和断电/掉线/进程崩溃演练。端到端流水线不能因为手机不可用而影响既有存储读取、Admin 登录或 MX-H2I 用户联网。

## 本地验证

运行 `node --test tests/server/peripherals.test.mjs`，默认跳过真实 PG 测试；设置 `MX_INSIGHT_PERIPHERAL_TEST_DATABASE_URL` 指向专用测试 PG 后，会新建唯一命名测试数据库、迁移并验证真实并发连接，最后删除**仅该测试库**。不要指向生产数据库。

本次验证包含本地模拟 HTTP、临时 PostgreSQL 多连接竞争，以及桌面/移动端浏览器操作。**不代表服务器手机已接通或线上已部署**。首次上线仍需实际宿主机地址、ADB serial、可达 origin、手机登录/补丁版本核对和上述验收。
