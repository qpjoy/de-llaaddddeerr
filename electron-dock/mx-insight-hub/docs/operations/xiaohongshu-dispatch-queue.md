# 小红书详情有界调度

## 使用方式

`POST /api/v1/data/xiaohongshu/notes/detail` 和原 PGY 别名共享合同。

```json
{"note_id":"6a20edfa0000000021020951","deliveryMode":"cache_first"}
```

默认 `cache_first`：5 分钟内已获取的有效结果直接交付。需要实时刷新传 `refresh`，刷新和默认查询使用不同的请求幂等身份。失败重试保持原 body 和 Idempotency-Key，服务端单次工作流最多自动尝试一次安全重试。评论/搜索/普通正文接口不使用此 PGY 队列。

## 调度算法

采用漏桶式平滑出队、有界 FIFO、单请求合并（single-flight）和有上限的延迟重试。无需引入 Redis/BullMQ。PostgreSQL 每个“供应商凭据摘要＋接口”一条状态行，短事务 `FOR UPDATE` 分配许可；不在等待或访问上游时持有连接。多实例共用队列；测试用内存实现共用同一状态机。

默认最小间隔 5000ms，额外 0–500ms 随机延迟，单接口最多一个正在采集的请求。准入用 `max(最小间隔, 已观察延迟的 EWMA)+抖动上限` 估算积压时间；预计等待达到 60000ms 或已有 12 个不同请求等待时，立即返回 HTTP 429、`external_platform_busy`、中文繁忙说明和 `Retry-After`。实际等待也受截止时间约束，不会因失败重试无限后移。60 秒是排队期限，不包含末次上游调用与落库耗时；客户端/反向代理响应超时建议至少 120 秒，较长上游超时配置需相应增加。若现有外层代理不能等待，先缩短 MAX_WAIT_MS；本补丁不修改 MX-H2I 网络配置。

相同笔记、相同上游凭据及合同版本的并发请求共享一个采集，最多接受 100 个等待同一作用域结果的跟随请求。缓存是经过合同规范化且与 canonical 入库任务同次提交的交付快照，不依赖 Elasticsearch 已完成投影。不会把其他客户的 Key、请求 ID、游标或账单塞入共享数据。每个调用者独立鉴权、额度预留、成功交付和扣费；缓存命中仍按其已有套餐/租户费率计费。采集只入库一次，不修改历史账单或旧快照。

详情单独缓存默认 5 分钟新鲜、最多 1 小时可降级。缓存过期后正常排队采集；遇到队列满或运行阻断时，cache_first 可交付已有过期快照，保留原采集时间并使用 stored_fallback/Warning 标识。refresh 不降级。没有静默收费的后台刷新。

## 重试与故障

当前唯一可自动重试的情况是 PGY 明确未计费的 HTTP 400 请求拒绝；Hub 已验证 note_id 格式，但无法保证此类拒绝都是临时错误，因此严格最多一次。重试追加到队尾、至少延后两个基础间隔，并沿用原截止时间。其他已排队请求不被插队。若已无剩余等待预算，立即结束，不额外调上游。

每次实际尝试独立写 provider_calls（primary/retry）、完整受限响应和采购成本证据；两次尝试共用一条下游请求与计费身份。重试重新检查授权、Key、运行开关、凭据、熔断、费率和采购预算。未知超时、HTTP 200 解析失败或无数据均不自动重试。客户端排队期间断开会移除等待项；已发送的调用继续留存结果与成本证据。

进程退出不会在重启时自动续跑旧付费请求。等待项到期清除，正在执行的许可到期标记未知，同查询在现有 15 分钟冷却期内拒绝重新采集。数据库不可用时拒绝放行，不退化为每个进程各自限速。只有一次定时等待/本地数据库状态检查，不会每秒向供应商探测或重试。

## 配置与部署

| 环境变量（前缀 MX_INSIGHT_TIKHUB_DETAIL_） | 默认 | 含义 |
| --- | --- | --- |
| INTERVAL_MS | 5000 | 最小派发间隔；按已确认供应商频率调整 |
| MAX_WAIT_MS | 60000 | 排队期限，最大 60000 |
| MAX_PENDING | 12 | 等待的不同采集请求上限，最大 100 |
| FRESH_TTL_MS | 300000 | 新鲜缓存时间 |
| STALE_TTL_MS | 3600000 | 降级缓存最长时间 |

先运行 migration 107，再发布所有 public API 实例和前端；旧实例不会参与新队列，混合版本期间不能保证全局频率，宜短暂停止该操作的新采集并在滚动完成后恢复原状态。迁移只新增协调表、重试角色和共享快照索引，不动客户、Key、权限、价格、余额或历史记录。大表应预建同名部分索引 CONCURRENTLY，避免迁移事务长时间阻塞。新表/索引需在实际 PostgreSQL 环境进行部署前迁移验证；本机 Docker 未启动，当前自动测试覆盖状态机、SQL 锁定协议及内存网关/计费集成。

设计依据：[NGINX 漏桶限流](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)、[AWS 重试、退避与随机延迟](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)。采用固定安全下限加随机延迟，不自动向更高频率试探。当前只有 PGY 详情接入，通用调度状态机可供后续已核验频率与重试合同的接口复用。
