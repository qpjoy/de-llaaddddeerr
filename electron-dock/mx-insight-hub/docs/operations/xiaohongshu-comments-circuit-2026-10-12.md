操作者返回的只读查询确认请求 `b97c11c2-316f-4343-a303-4c464d8f2261` 属于
LCY-delta Key `fd2f8cc9-0ff1-4052-a538-8cc8150bde83`。以下时间为北京时间：

| 时间 | 证据 |
| --- | --- |
| 10:54:08 左右 | 四笔搜索开始；返回样本中可见各自派生的 `social.posts.resolve` 正文补全 |
| 10:54:20.231–22.027 | 最近 40 条上游记录内有八条 HTTP 429，涉及补全、评论、阅读量详情；`upstream_rate_limited`、`business_code=null`、`billed=null` |
| 10:54:24.183–24.188 | 目标评论请求在 Hub 内结束，`released`、`external_platform_circuit_open`；gateway attempt 为 `circuit_rejected`/503，`provider_call_id=null` |
| 12:26:55.678 | 采样状态记录的最近成功时间；`consecutive_failures=0`、`circuit_open_until=null` |

目标评论没有派发到供应商。与最近观察到的 429（call
`930c8c49-50d9-4209-8fb3-d5c3953393aa`）完成时间相差 **2.156 秒**，
仍在内部 Key 的 10 秒限流保护内。按这条失败推算，内部期限约为 10:54:32.027；
历史库未保存该请求看到的完整熔断快照，这不是实读的历史截止时间，后续失败也可能延长保护。

查询只取最近 **40 条**，不得把八次 429 当作全量失败数，也不能据此计算完整 RPS。
HTTP 429 已证实上游限流；具体账号/接口阈值、其他同凭证调用量仍没有证据。
`billed=null` 不等于已确认供应商免费。搜索主调用成功结算也不能清除发生在其开始时间之后的新失败。

Admin 的全部上游限制视图可读，而按此请求/Key 查询返回 500。操作者直接运行
`AdmissionRecoveryService.snapshot` 得到 PostgreSQL **57014**：
`canceling statement due to statement timeout`。对应只读事务的单语句上限为 10 秒。

## 本地改动

1. 评论对**尚未派发**的可恢复速率冷却有界等待，每段最多 5 秒，累计最多 60 秒。
   同时从原预留租约中保留上游 timeout + 5 秒；等待不延长租约。
   除下述最新 LCY 专属豁免外，内部 Key 按最近限流失败 + 10 秒计算，普通 Key 保持共享期限。
   不修改数据库熔断、不让普通调用者获得豁免、不将评论放进 PGY 详情队列。
2. 等待时不占用供应商采购额度、派发锁或进程派发并发槽。醒来重新读取状态、有效身份/授权、
   活跃已发布套餐、供应商凭据与接口控制；实际派发仍经过预算、去重/未知结果保护和原有本地容量门禁。
   连接取消、租约时间不足、冷却超过预算或非速率故障仍拒绝。已经发出的 HTTP 429、未知结果和付费调用不自动重试。
3. 限制视图使用运行时同一内部策略，补上 store-authenticated `managed_full` 身份，
   正确标识其配额豁免、本地速率豁免及当前熔断策略，保留真实用量。
4. 配额 SQL 一次读取候选用量与历史授权范围，再分组统计，避免每个授权范围重复扫描账本。
   保留 Key/Consumer 隔离、历史授权集合、无集合时的旧字段兼容、状态计数、窗口、恢复标记、月度及总额语义。
   内部查询编号和随时间移动的下界不参与恢复版本摘要。
5. 保留 10 秒查询上限。超时返回明确的 `503 admission_snapshot_timeout`，缺表/字段/读取权限返回
   `503 admission_snapshot_unavailable`，避免无法解释的通用 500 或泄漏 SQL。

## 最新可用性调整：五分钟解析冷却与 LCY 429 豁免

用户随后要求“熔断改成 5 分钟，去掉 lcy-delta 的账号级 429”。运行时区分三个机制：

| 机制 | 本次调整后 |
| --- | --- |
| 响应无法标准化的端点隔离 | 默认 15 分钟缩短为 5 分钟；再次失败会从新失败时间计算 |
| 调用结果未知 / 内容不可用的同请求保护 | 仍为 15 分钟；未知是否计费不能因解析策略调整而自动重发 |
| TikHub 共享供应商熔断 | 普通调用默认 3 次失败 / 60 秒不变；原 LCY 身份跳过其中的 `upstream_rate_limited`，其他内部 Key 保留 10 秒例外 |

LCY 必须同时匹配原始 Key UUID、tenant `277bf8a4-5ed5-414d-b429-d72fcd7d36b6`、
consumer `be7d07fe-3d98-4db3-b00d-e5cbe5a76190`，且权限上下文中的 `managed_full` 来自数据库认证。
不按可变账号名匹配，也不把豁免扩散到其他 managed Key。共享失败计数、截止时间、上游 429 和计费证据继续保存。
真实供应商 429 仍返回错误；认证、余额、权限、全局容量、非限流故障和解析/未知结果保护继续执行。

新部署默认写入 `MX_INSIGHT_JUSTONE_RESPONSE_QUARANTINE_COOLDOWN_MS=300000` 和
`MX_INSIGHT_TIKHUB_RESPONSE_QUARANTINE_COOLDOWN_MS=300000`。内存、PostgreSQL 派发准入、
Admin 倒计时以及 Instagram/微博诊断使用相同解析期限。旧失败记录不改写；新进程按新期限判断是否到期。
追查本次调整前的 15 分钟历史告警时，可仅在诊断命令上设置
`MX_INSIGHT_DIAGNOSTIC_COOLDOWN_MS=900000`，该变量不改变运行时准入规则。

## 验证

后续用户授权将默认并发从 8 调整到 16，并加入有界等待队列；该变化不修改本次历史限流证据。
详见[小红书并发与等待队列](./xiaohongshu-concurrency-queue.md)。

- 真实 PGlite SQL 回归覆盖 400 个合成接口授权、4,000 条合成请求，加既有平台与历史基线；
  校验兄弟 Key、历史授权集合优先于旧字段、released 只计操作速率、独立恢复、月度/累计用量不重置。
- 同一只读事务、同一 4,001 行样本、806 个配额项的新旧 SQL 结果逐项一致。
  本机一次测量旧查询约 **1,890 ms**、新查询约 **31 ms**；这是本地对照，不是线上耗时保证。
- 定向回归覆盖内部/普通评论等待、冷却延长、租约预算、迟到唤醒、撤销权限/套餐/预算、取消、未知保护、单次派发、计费与幂等。
- Admin-only/HTTP、既有 PGY 队列及官方小红书接口回归通过；没有发起小红书付费实测。
- 内存与真实 PGlite SQL 对照验证第 4 分钟阻塞、第 6 分钟解析保护释放，但未知结果及内容不可用仍阻塞；
  Admin 截止时间与准入完全一致。LCY 新鲜 429 直接派发，同名/错 Key/错租户/错调用者不豁免，真实上游 429 仍只调用一次。

## 发布和线上验收

本轮不新增迁移、不清除共享保护、不重写历史失败，不涉及 Launcher、MX-H2I 登录联网或支付中心。
将本次 Hub 改动同步到服务器，进入 `electron-dock/mx-insight-hub`，执行：

```bash
bash scripts/manage.sh deploy
kubectl -n mx-insight-hub rollout status deployment/mx-insight-hub-public --timeout=300s
kubectl -n mx-insight-hub rollout status deployment/mx-insight-hub-admin --timeout=300s
```

发布后，在请求诊断中打开上述请求，进入“查看当前限制与恢复倒计时”。应能加载所选 Key 的限制，
内部配额显示豁免但用量仍可见；LCY 的共享 429 显示专属豁免；解析冷却为 5 分钟，过期保护不需要点恢复。若仍超时，保留明确错误码与耗时，
进一步检查线上执行计划和索引，不调高全局超时或清表。

通过后续正常业务的新评论请求观察等待和单次派发。历史 `released` 不会被改成成功，
这次本地回归不代表修复已上线，也不保证供应商未来不会再返回 429。
