## 代码中确认的阻塞与恢复缺口

当前 v1 Twitter 标准搜索经过 `HubService.search → externalDataSearch → RapidAPI gateway → runTwitterSearchFill`。供应方返回后，还需 stage evidence、finishProviderStep（归档、共享 provider state、队列记录及核验）、释放采购成本预占、可能补页，最后 commitTwitterFillDelivery。以上多次 checkout 和事务都在同步 HTTP 路径内；共享 provider 成本 advisory lock 也参与收尾释放。

- Hub 两个 PostgreSQL pool 原本没有连接获取等待上限，连接耗尽可让交付、入场和查状态互相等待。
- reserve 在写入 `reservedAt` 前需要多个授权/配额/幂等锁；只观察 `reservedAt` 会漏掉前段等待。
- 每次新请求原本做全局过期清理，旧清理锁顺序与 call→usage 的结算顺序相反，存在争锁风险。历史事故是否实际发生这种死锁，尚无 SQLSTATE 证据。
- 两个请求状态 GET 原本也触发全局清理，让故障后的核查再次依赖写事务。
- Delta v1 对 HTML 504 / 丢失响应缺少与已有 Facebook/v2 等价的原页保护。跨路由或创建新 Step 后重试可能产生新 key。只在 60 秒时查一次也不足够：155 秒才提交的原结果需要可再次 GET 的恢复入口。

## 本地修复

1. Hub 自有 pool 使用原生 `connectionTimeoutMillis=5000`，队列超时会从 pg-pool 移除；不使用可能遗留后台写操作的 Promise.race。监听 idle connection error，避免空闲连接断开造成未处理 EventEmitter error。保留原公共采购 pool 的 SQL timeout，不修改 mx-common 默认值。
2. reserve 使用事务局部 lock timeout 5 秒、每条 SQL timeout 15 秒；数据库已取消语句后回滚，返回结构化 503。COMMIT 回执丢失保留 unknown，明确按原 key 核对，不宣称原请求从未派发。
3. 过期清理每批最多 100 个 usage，按 call→usage 锁序并 `SKIP LOCKED`，同事务重检过期和 pending 状态；局部 lock timeout 500 毫秒、SQL timeout 5 秒。忙的结算留给后续批次。unknown 和客户 hold 语义保留。
4. UUID / 原 key 状态 GET 只读，不执行 reaper。reserved 可附带 `leaseExpiresAt` / `leaseExpired`；租约过期本身不证明可以重购。
5. Twitter unknown 日志只记录 request/call UUID、失败阶段、错误类别和 SQLSTATE，不记录 query、cursor、SQL 正文、凭据或上游正文。日志失败不改变原结算结果。
6. Twitter 补页后的成本清理使用有界事务和 try advisory lock，不再为释放预占排在整个供应方的成本计算后。锁忙/清理失败时保留成本预占；已有内容不足一页且仍有游标时，停止补购并交付 partial + 原 continuation。已满页、buffer 和正常耗尽不误降级。已发生的采购成本仍计入账本，客户 hold 不被跳过，供应方切换仍走原严格释放路径。
7. Delta 修复已应用到 `/Users/qpjoy/workspace/mingxi/po-infra` 的 10 个目标文件。补丁备份在 `/tmp/hub_504_2026-10-18/delta-patch/`，基于现有 dirty working tree 生成，应用前逐文件核对 baseline SHA，应用后核对目标 SHA，保留原有修改。非 Facebook v1 标准搜索每页保存原 payload/key，首次只 POST 一次；504/断连及重试页只 GET 原回执与保存交付。仅确认 committed + 原业务 ID + 平台 + HTTP 200 + items 才进入既有幂等入库。Facebook/v2 保留原路径。普通重跑在创建新 Run 前逐 stream 检查历史派发身份；原 Run/Step 仍活跃时禁止并行克隆，旧页缺身份时不另造 key。raw/search/intent 别名使用真实路由回归验证。

这些修改不等于已证明线上 504 全部消失。特别是归档/采购结算事务、数据库实际负载以及 60 秒代理来源仍需线上证据；不能靠扩大代理超时、取消财务保护或把 unknown 改成功掩盖问题。
