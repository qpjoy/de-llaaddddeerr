# 租户默认单价与接口覆盖（2026-09-23）

在「套餐与配额 → 计费策略」设置租户默认单价，初始为 0.00；设置 0.10 并启用余额门禁后，本租户所有调用者/Key 的未单独定价业务请求按每次成功交付 0.10 结算，无需先发布套餐或逐项添加价格。统一价格按填写金额直接生效，不乘套餐/租户倍率。币种需与已开通钱包一致。仅设置价格不会开启自动扣费；影子模式只记录报价。

价格优先级为：当前调用者已分配套餐的接口价格（包括 0）→ 租户默认单价（初始 0）。套餐接口价继续使用原倍率规则。如果某接口需要免费，在套餐中显式填 0；若需恢复统一价，从新套餐版本中删除该项后发布并分配。默认价为 0 不覆盖原套餐已有收费项。权限、服务运行状态、额度仍独立校验，定价不授权。

批量及聚合保持原计量单位：实际子请求各结算一次，实时聚合父请求不额外收费；登录、管理、用量/余额读取不产生新的业务计费。分页各是新请求，幂等重放不重复收费，明确失败释放冻结，结果未知保持冻结待对账。

迁移 `105_tenant_default_request_price.sql` 默认补 0，不改旧账户、密钥、权限、套餐、钱包或历史账单。请求保存来源、默认价策略修订和不可变价格快照；在途/已结算请求不随调价变化。旧客户端未提交默认价格/币种时保留已配置值。先运行迁移，再发布服务；本功能仅限 Hub，不改 MX-H2I 登录联网。

管理 API：`PUT /internal/v1/admin/tenants/{id}/billing/profile`，新增可选字段 `defaultUnitPriceMinor`（非负整数，CNY 10 表示 0.10 元）、`defaultCurrency`（如 CNY）。更新仍需 `expectedRevision`；`mode` 为 disabled/shadow/enforced，`multiplierPpm` 只影响套餐接口价。默认字段省略为保留，创建时为 0/CNY，显式 null 单价无效。

# 产品费率与组合套餐

## 操作方式

在“套餐与配额”选择租户、调用者。快捷入口“追加 IP 风险画像费率 · ¥0.05/次”会创建待发布草稿，保留当前套餐其他接口价格，并设置 `ip.risk.query` 为 CNY 5 分；小红书入口使用 v2 模板，设置六项 social 操作为 CNY 10 分：笔记搜索、正文与标签、用户资料、用户笔记、详情与阅读量、笔记评论。旧 v1 四项模板及已分配套餐不变。这里是基础价，界面会按现有租户倍率展示最终成交价。充值不自动开通扣费。

发布窗口可从下拉框添加预设产品或任意已发布的有价套餐。同接口同价合并，不重复扣费；遇到不同价格时先在最终价目表确认价格，再添加来源。删除最终表中的条目意味着该操作未配置价格，已授权时保持免费。组合不会授予能力、扩大 Key 权限或决定文档目录。合同权限仍在开放能力及 Key 授权管理。

确认后可只发布版本，或显式发布、分配并启用扣费。后者会给当前调用者分配新套餐，并将该租户自动扣费设为启用：同租户其他调用者仍按自己的套餐，但也受租户计费开关影响。已有余额不重复充值，已有租户倍率不重置，历史调用不补扣。出现部分成功提示时按界面提示继续分配或启用，不要重复发布。

## 绑定与改价

兼容原有 `consumer_plan_assignments`：**套餐绑定调用者，同调用者所有 Key 共用费率**，不是每个 Key 独立绑定。要给不同 Key 不同合同价格，应使用不同调用者；本次不迁移旧 Key、不自动更新旧套餐。Key 本身的授权、次数/频率上限继续独立生效。

组合来源固定到产品模板版本或已发布套餐 versionId；最终套餐持久化 `pricing.components` 来源数组和一份完整不可变 price book。来源清单用于追溯，费用以最终价目表为准。更改模板或发布来源套餐新版本不会自动改价；运营需发布新的最终套餐，再显式分配。既有套餐目录仍可用于复用、发布和分配版本。

API 发布 `/internal/v1/admin/plans` 可带 `components`：`{type:"feature",key:"ip-risk",version:1}` 或 `{type:"plan",versionId:"..."}`。最多 32 个不重复来源，必须币种一致。没有显式 entries 时服务端合并来源并拒绝价格冲突；提供非空 `priceBook.entries` 时它是**完整最终价目表**，不是增量补丁。服务端验证每个最终价格、重复计费键、来源存在及版本状态。配额和倍率以最终套餐表单为准，不相加、不取来源的默认倍率。

## 运行时及部署

请求沿用单份已分配价目表的计费键查价和事务账本，不遍历套餐来源。IP 单条成功扣一次（含有效 no_data），批量按成功子项分别扣费；确定失败释放冻结，结果未知保留冻结待对账。显式幂等成功重放不再次扣费；普通再次请求是新查询。供应商采购成本仍未知，与客户销售定价分开展示。

组合来源利用已有 plan_versions.pricing JSONB；本次不新增数据库迁移，也不改历史 migration。部署仍使用 `bash scripts/manage.sh ops internal-production deploy`（已有迁移需正常完成）。更新前端和 Public/Admin 服务后，旧分配照常工作；运营在界面发布并分配新组合才应用新费率。

验证使用模拟上游与内存账本，不代表真实支付或上游联调。生产 PostgreSQL 部署和实际客户改价由运营执行。

## 启信宝价格模板（2026-09-17）

新增 `qixin` v1 模板：260 个公开标价接口，来自逐页获取的官方价格快照，14 个面议接口禁止调用并排除。可传入 `{type:"feature",key:"qixin",version:1,multiplierPpm:1200000}` 表示官方原价加 20%；900000 表示九折。该倍率只作用于产品基础价；钱包的租户倍率仍独立生效。价格以整数分向上取整，避免浮点误差。显式完整 `entries` 仍是最终合同表，允许审阅后的逐接口修订。

## 产品工作台、消费记录与采购基础方案（2026-09-23）

“套餐与配额”选择调用者后，可在产品工作台复用标准已发布套餐，也可将产品费率追加到当前草稿。标准套餐可给多个调用者使用；调价仍需新版本与明确分配。产品权限按钮只补调用者缺失授权，随后到 Key 管理核对或更新原 Key；不会因为价格或目录变化自动扩权。

默认“消费记录”每笔请求一行，展开看完整冻结/结算/释放。冻结 ¥0.10 与成功结算 ¥0.10 是同笔消费的两个阶段，不能相加成 ¥0.20；原始账本保留充值、调整和逐步资金变化。

外部数据平台的“采购基础方案与接口例外”先填原币种单价、预算、证据日期和原因，再预览并应用。已有独立价格默认保护；只有选中覆盖才纳入基础方案。后续独立修改或手动暂停会打断该操作的自动继承资格，继续保留为例外。所有更新仍按操作审计和修订检查，部分失败显示具体结果后重新预览即可续办。

客户价格与采购成本分别维护。聚合搜索预览按调用者当前套餐/倍率逐源估算本批价格，实时父请求不另收费；每次后续页单独估算。预览不产生采集或冻结，执行时重新检查，不代表锁价或硬上限。
