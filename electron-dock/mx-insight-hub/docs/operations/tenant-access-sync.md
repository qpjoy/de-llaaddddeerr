# 租户授权与已有 Key 同步

日期：2026-09-30。用户明确修订此前“租户新增权限不扩展旧 Key”的行为。本次交付源码与隔离验收，未发布线上、未批量改写生产授权。

## 保存语义

- 开放能力 → 租户授权：当前已选的数据域、业务操作、兼容接口和 Web Search 渠道全部补齐到该租户所有已有 Key，覆盖所有调用者。重新保存相同配置也可以补齐历史 Key。
- 移除集合 = 上次已保存的租户范围 − 本次已选范围。只有这个集合会从调用者与 Key 中删除。租户清单从未管理过的 Key 额外范围保留，不以租户表单覆盖完整 Key。
- 新 Key 仍可按调用者当前权限签发子集；下一次保存租户授权会按以上规则补齐它。新租户默认空授权；登记新供应商或能力不会自行开通。
- 原密钥、到期日、状态（包括已撤销/过期）、独立限额、历史用量、钱包与套餐价格保留。被同步的历史 dynamic Key 会转成明确快照，原有独立授权与额度保留。
- Web Search Key 独立顺序保留，仅剔除本次确实移除的渠道。未设置 Key 顺序时沿用租户顺序，新增已授权渠道按运行时规则补充。
- “调用者配置”是单个调用者的高级授权与额度入口，继续以调用者授权约束 Key；其单项新增不执行租户全体 Key 同步。租户统一开放请使用“租户授权”。

示例：租户原为 `[A,B]`，Key 原为 `[A,B,C]`，租户改为 `[A,D]`，则 Key 变为 `[A,C,D]`。另一把 Key 原为 `[C]`，同次保存后为 `[A,C,D]`。`C` 始终不受此次租户配置影响。

## 操作与保护

页面分为租户授权、调用者配置、Key 限额三个工作区。租户授权提供分类、搜索、已选/未选筛选、分页、快捷产品勾选、独立 Web Search 排序、可展开的默认额度和变更摘要。调用者的数据域、操作、兼容接口及产品说明分开呈现，取消重复堆叠表单。

1. 选择租户、调整勾选、填写原因，点击“预览变更”。
2. 预览列出全部已有 Key、每把 Key 新增/移除的权限和保留的额外权限。Key 原值不可在预览中改写。
3. 涉及移除时，显示能力标识与受影响的 Key，必须勾选“我已确认移除以上权限”。未确认时前端禁止提交，后端同样拒绝。
4. 确认同步。任何租户版本、Key 清单、状态、范围或顺序在预览后变化，提交返回 409，重新预览即可。没有自动重试移除操作。
5. 下游继续使用原 Key。产品调试页刷新调用身份后读取新权限。

## API 与事务

- `GET /internal/v1/admin/tenants/:tenantId/service-access`：读取租户范围与 revision。
- `POST .../service-access/preview`：与 PUT 相同的配置和原因，仅平台管理员可调用，返回 no-store 的变更预览和 `previewToken`；不改变授权。
- `PUT .../service-access`：提交配置、revision、previewToken；移除还需 `confirmRemovals: true`。旧客户端的纯增加保存继续支持，但无法绕过移除确认。
- PostgreSQL 单事务包含租户配置、调用者授权、Key 范围与各自审计。租户 advisory lock 与 Key 行锁串行化已有 Key 编辑、Key 签发及消费者继承；预览以一致性只读事务读取，提交在锁内重新计算完整影响。
- 只读预览不返回 Key 明文或 digest。使用现有 tenant-service-access 和 api_key_scope_events 审计表，无新 migration；要求已应用现有 119（Web Search 顺序字段）。不会通过迁移静默扩展生产 Key。
