# 数据产品中的接口、限速与价格管理

2026-10-15。本次把配置操作放入数据产品的「管理」页，使用同一套供应商配置与审计。只有 Hub Admin Token 可以读取或修改；普通调用 Key、租户会话及 Launcher/SSO 管理身份不获得这些权限。

## 页面入口

企业数据、策略搜索、Web Search、社媒内容、电商、微信系列、小红书系列和 IP 风险画像的管理页支持：

- 按产品筛选供应商接口，查看期望状态、实际状态、阻止执行的原因。
- 修改供应商普通并发、单调用者并发、每分钟请求数、最长等待时间和最大等待请求数。
- 查看运行采购估值、带日期和来源的官方价格快照；复用现有接口启停与采购价目表单。
- 选择调用者，查看当前套餐版本、计价项、币种、倍率及执行单价，并进入现有套餐调价页面。
- 继续进入凭据、出口、调用证据、服务授权及使用记录等现有工具。IP 页面还保留百度渠道每日额度和最小间隔设置。

页面读取、刷新及保存配置不会调用供应商采集。没有登记供应商的存量或派生产品只展示已有工具，不虚构速率或采购价。

## 默认值和真实作用范围

下面是没有数据库覆盖、且部署环境没有指定其他值时的默认值。已保存策略优先于部署默认值。

| 供应商/渠道 | 网关实例总并发 | 单调用者并发 | RPM |
| --- | ---: | ---: | ---: |
| 企业 Qixin | 10 | 10 | 30 |
| JustOne | 32 | 8 | 50 |
| TikHub | 16 | 8 | 50 |
| RapidAPI | **6（原 3）** | **4（原 2）** | 60 |
| 各 Web Search 供应商 | **6（原 3）** | **4（原 2）** | 60 |
| IP 外层网关（IPSearch / 百度） | **6（原 3）** | 6 | 60 |

普通等待队列默认仍为 10 秒、32 个等待请求。只有原本允许等待的入口使用队列，设置等待时间不会让所有入口都变成异步任务。供应商 RPM 没有统一提高；它是 Hub 主动控制调用频率的设置，不代表上游承诺容量。TikHub 的短时突发限制仍然保留，调高 RPM 不等于允许同时突发任意数量调用。

**限速策略按供应商共享，不能把同一供应商的每个接口设置成互相矛盾的 RPM。** 在企业产品修改 Qixin，会影响该供应商的所有企业接口；在小红书修改 TikHub，也会影响使用 TikHub 的其他产品。每个 Web Search 供应商有独立策略。

RPM 使用现有的供应商共享数据库令牌桶；并发沿用各网关对象/进程的计数，**不是整个集群的总并发上限**。单调用者并发也是该网关实例内的上限。管理界面分别标明这两个范围。

保存后，后续准入、队列恢复校验及后续供应商分页读取当前策略。已开始的准入或已派发请求可以继续完成；不会取消在途请求或清空计数。较旧的并发读取结果不能覆盖进程已经观察到的较新修订。策略读取失败返回明确错误，不默默退回较宽松的旧配置；已经获得的多页内容沿用部分成功规则。

## 限速与其他约束分开管理

保存限速只修改限速策略。接口启停、采购价、调用授权、套餐、余额、采购预算、未知结果保护、去重及历史账本继续独立生效。

- [LCY-delta 限制开关](lcy-hub-limit-switch.md)已显式开启时，继续按原规则豁免普通 Hub 限制。这里不自动开启或关闭该 Key 的开关。
- Facebook RapidAPI 已购额度和单笔派发记账顺序保持原状。
- 小红书 PGY 的共享派发队列、租约、去重和未知结果保护保持原状。
- 百度 IP 渠道的每日上限、最小间隔、令牌频率及上游冷却独立生效，外层并发提高不能覆盖它们。订阅权益按已购合同检查。
- 供应商真实限流仍返回可区分来源的错误。主 HTTP/错误码保持既有合同；Hub 准入拒绝和已确认上游拒绝不能混为一谈，详见 [Hub 并发准入](hub-concurrency-admission.md)及 [LCY 错误语义](lcy-hub-limit-switch.md#上游限流的错误语义)。不自动重试已经派发的付费请求。

## 价格含义

运行采购价目表使用最小货币单位估算采购预算，可能向上取整。官方参考价保留仓库中已核验快照的原始小数、币种、观察日期和来源；**两者都不是本次实际扣费，也不声称价格已实时刷新**。供应商未提供价格时显示缺失，不按免费处理。

下游价按选中的调用者当前有效套餐和租户计费配置计算，使用已有计费函数；明确的零价优先于默认费率，套餐倍率只应用于合同价格。没有选择调用者或没有有效套餐时，不展示伪造的零价。未启用实际扣费时同时展示配置价与实际零扣费。IP v2 按订阅权益展示，不伪装成单次售价。

标准 `/api/v1/data/search` 按实际平台计价项展示，原生接口按各自操作计价项展示，账号内容/资料使用各自的计价项。一条客户请求可能包含多次上游调用，因此采购单价和下游单价不能直接相减推算利润。页面不换算币种；实际发送时仍重新检查有效价格、授权及余额。

## 管理 API

认证使用已有 `x-mx-insight-admin-token`，仅 Admin 管理监听器开放，响应 `Cache-Control: no-store`。

```text
GET /internal/v1/admin/data-products/management?path=/data-products/enterprise&consumerId=<UUID>
GET /internal/v1/admin/external-platforms/:provider/admission-policy
PUT /internal/v1/admin/external-platforms/:provider/admission-policy
```

`consumerId` 可省略。产品接口返回 `product`、`consumers`、`customer`、`providers`、`customerPrices`、`notes` 和 `observedAt`，只投影管理所需字段，不返回供应商密钥或运行时凭据。

限速 GET/PUT 的 `data` 返回 `providerKey`、`source`（`deployment`/`database`）、`revision`、`limits`、`defaults`、`updatedAt`、`scope`。首次读取的版本为 0。PUT 示例：

```json
{
  "expectedRevision": 0,
  "reason": "根据企业查询并发需求调整容量",
  "limits": {
    "maxConcurrency": 20,
    "maxConsumerConcurrency": 10,
    "maxRequestsPerMinute": 30,
    "maxWaitMs": 10000,
    "maxPending": 32
  }
}
```

并发与等待数允许 1–256，RPM 允许 1–60000，等待时间允许 1–60000 毫秒；单调用者并发不得超过实例总并发。部署中原有较大正整数仍可读取和运行，界面新保存受上述范围约束。每次保存必须提交完整五字段、刚读取的修订号及变更原因。

`409 external_admission_policy_changed` 表示版本冲突，重新读取后再编辑。数据库读取或保存不可用返回 `503 external_admission_policy_unavailable`。网络丢失可能发生在事务已提交之后，页面要求重新读取，不自动重发 PUT。变更与不可变审计在同一事务提交，包括前后值、修订、原因、操作者和请求 ID。

## 发布与验证

迁移 `154_external_platform_admission_policy.sql` 仅创建空策略表和审计表，不预置覆盖行，不修改现有启停、价格或令牌桶。部署需包含迁移、所有 Public/Admin 实例和新前端；旧实例不读取新策略，不能在新旧实例长期混跑时宣称配置完全生效。

本轮相关回归共 637 项通过、8 项因未配置独立 PostgreSQL 测试库跳过；新增策略持久化、审计和版本冲突已用 PGlite 验证。类型检查与生产构建通过；模拟管理 API 的真实浏览器验证覆盖桌面/手机、保存、版本冲突、响应丢失、调用者与供应商切换，以及 10 个产品入口，没有触发业务查询。

本轮仅本地实现与验证，没有生产部署、线上调价、自动开启 LCY 豁免或付费采集。MX-H2I 登录与联网代码未修改。由操作者在 Hub 目录按现有流程发布：

```bash
MX_INSIGHT_SYNC_LAUNCHER=0 MX_SMOKE_DATA=0 \
  bash scripts/manage.sh ops internal-production deploy
```

发布后先在管理页读取当前值，选择产品/供应商并保存明确的限速变更原因；再从使用记录核对实际准入。配置保存本身不触发业务查询。
