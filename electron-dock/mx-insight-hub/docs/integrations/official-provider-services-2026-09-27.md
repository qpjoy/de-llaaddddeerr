# 官方接口目录、Hub 数据服务与定价

日期：2026-09-27。状态：本地代码与验证完成，尚未部署本批变更。此前已部署版本不因此改变。

## 1. 本批交付与数量口径

在 Night-All 源码首批 50 个固定接口基础上，读取 TikHub 官方 OpenAPI 和 JustOne 官方 API 索引对应的 293 份规格，新增 **987 个固定只读接口合同**。接口经过 Hub 的身份、范围、价格、运行策略、钱包、配额、采购预算、幂等及归档链路执行；不是开放 URL 的通用代理。

| 范围 | 官方目录中的唯一 method + path | 已有固定执行合同覆盖的唯一路径 | Hub 固定接口标识数量 |
| --- | ---: | ---: | ---: |
| TikHub | 1050 | 757 | 757 |
| JustOne | 293 | 275 | 280 |
| 合计 | 1343 | 1032 | 1037 |

JustOne 的历史跨平台搜索存在同一个 HTTP path、不同固定 source 的逻辑合同，所以标识数与唯一路径数不同。目录数量不能作为可用平台数、完整数据覆盖或实时健康证明。

新增合同只纳入固定 GET、标量 query 参数、已知数据平台和无客户端凭据的读取操作。已有 50 个合同的参数、路径及行为保持兼容，只补充可匹配的显示名称。请求中的 URL、方法和端点由服务端固定；不接受任意转发地址，不重试、不补页、不自动换供应商。

仍有 **311 个官方目录项没有固定执行合同**：238 项需另审方法或 body，16 项涉及凭据或非 query 参数，13 项有复杂 schema，21 项是非业务控制接口，21 项需操作性质审核，2 项已弃用。导入器本身排除了 315 项，其中 4 项已有旧的专用合同。这些项在 Admin 目录标注原因，不虚报接入，也不因目录注册而开放调用。

## 2. 面向调用方的产品与文档

- 数据服务增加 **社媒与内容数据**：内容、账号、评论、榜单、创作者等固定接口；商品类进入既有 **电商数据**。1688、速卖通、抖音电商、小红书电商等使用 ecommerce 数据域。
- 页面顺序为“接口调试 / 产品展示 / 接入指南”。调试目录按业务平台分类，支持搜索、编号分页及接口深链；参数与默认值来自同一 OpenAPI 合同。选择、筛选、切换标签和打开文档不会付费采集。
- 每个固定接口都有参数文档与对应调试入口，两处双向定位。租户文档、OpenAPI 与服务端执行使用同一平台及能力范围；所选 Key 还需落在调用者当前授权内。
- 企业文档和普通服务文档不再显示采购官网价格、采购链接或供应商来源；企业采购参考只有 Admin-token 会话可展开，Launcher 管理身份不等于此权限。
- 保留既有 native 标识和原生业务字段，不能声称已完全消除可推断的供应商接口特征。新的业务命名兼容合同应另行版本化，不静默删除现有字段。

## 3. 普通用户也能查看 Hub 官方定价

新增只读接口：

```http
GET /api/v1/data/services/pricing?path=/api/v1/data/native/<接口标识>
Authorization: Bearer <HUB_API_KEY>
```

同样支持企业查询、IP 风险查询和电商商品搜索的已登记路径。按当前 Key 与调用者的有效授权校验；不会访问供应商、预留余额、记查询用量或扣费，返回 no-store。

| 展示信息 | 含义 | 可见范围 |
| --- | --- | --- |
| Hub 官方定价 | 当前调用者已分配的 Hub 发布价格表条目 | 有接口授权的普通 Key 与 Admin 执行身份 |
| 账户执行价 | 按当前租户倍率、默认费率和计费模式计算的报价 | 同上 |
| 采购参考、币种、来源、观察日期 | 已核实的供应商参考价；不等于实际扣费 | Admin-token 管理面 |

当前系统没有独立于客户套餐的“全站统一零售价表”；所以接口明确标记 `hubPrice.scope=current_price_book`，不杜撰一份全局售价。企业、渠道客户可有不同价格表，同一 consumer 的多把 Key 使用同一份套餐，Key 不单独设结算倍率。

明确的零价格与缺失价格分开表示。条目缺失时显示“未发布单价”，账户执行价遵循已有默认费率规则；关闭实际扣费时同时保留配置报价并明确展示计费状态。报价不锁价，发送时重新检查，最终以执行账单为准。

## 4. TikHub 与 JustOne 的采购价格证据

按用户指定，从默认 Chrome 已登录的新账户价格页核实逐项价格，未假设所有接口均为 USD 0.001。

- 页面显示总数 1463；读取到 1360 个唯一完整路径后遇到页面频率限制，停止继续翻页。
- 972 个价格路径匹配官方文档，其中 **710 个匹配已封装的 Hub 固定接口**，可加载为采购价格草稿。
- 精确保留原始四位小数，例如 USD 0.0010 / 0.0060 / 0.2500；价格快照明确 `complete=false`、数量与停止原因。它是新账户显示参考价，不推测批量折扣、免费试用额度或供应商实际扣费。
- JustOne 文档已登记，但本次没有获得可核实的账户逐接口价格；保持“待核价”，支持 Admin 导入或填写草稿，不从 TikHub 或相似接口推算。
- 价格资料只进入管理参考，不自动覆盖已审核采购价，不发布客户售价、不变更现有套餐分配。管理员可通过已有批量开通向导选择全部或部分已核价接口，预览影响后提交。

采购参考使用精确微单位；既有预算与客户账务仍采用整数最小货币单位。USD 0.001 生成的保守预算为 1 cent，不能解释成供应商真实收费 USD 0.01。跨币种转换与全链路采购微单位结算尚未实施。

## 5. 批量开通与目录迁移

批量目录现有 **1326 个操作**。为支持一次开通某个供应商，单批上限从 400 提升至 1500，显式能力范围上限统一为 2048，平台范围仍为 128。保留明确列表，不使用通配权限；无论多少新接口，都不会自动扩大已有 Key。

原流程的事务、15 分钟预览、并发修订检查、回执重放、原 Key 更新、暂停审核、同 consumer 的价格影响和其他 Key 的范围保护全部保留。超过 400 项的一批开通已通过合成测试，并验证重放与 sibling Key 不变。

- **114** 注册新增操作 release 与初始 disabled 策略；存在记录时保留人工状态。
- **115** 增加 Lemon8、皮皮虾、优酷、IMDb、视觉中国、Pixabay、腾讯互选、巨量星图，基础目录从 215 增至 223。初始为覆盖未知、已规划、待审核，保留名称占用和已有人工状态。
- 其余供应商业务平台通过稳定 sourceKey 关联已有目录；`health`、供应商账户、hybrid、快捷指令、demo、跨平台 search 不是一个真实发布平台，不伪造目录归属。
- Admin “上游供应商”矩阵展示官方清单、原接口、Hub 接口、实现/延期原因、目录绑定、已审核价格和当前运行策略。采购参考与文档链接仅在此管理投影返回。
- 目录刷新读取 Hub 本地代码及管理状态，不触发供应商请求。人工覆盖、固定合同、启用状态和实测健康分轴呈现。新接口没有实测样本时继续标记未知。

## 6. 三个 Night-All 接口的下一迁移批次

本批没有整体切换 `/api/v1/search/raw`、`crawl`、`user-info`。固定原生合同建立了受控执行基础，但原生 `data` 不能直接当成旧 `raw_data`。下一批按以下次序实施：

| 顺序 | 最小迁移单元 | 必须交付的兼容证据 |
| --- | --- | --- |
| 1 | JustOne 微信公众号/社媒单次关键词搜索，以及已知 TikHub 搜索请求形状 | 对照 Night-All 默认参数与供应商选择，匹配 raw_data、计数、空结果、错误及下一页；固定时间窗口 |
| 2 | 按已知 ID 查询的 user-info | 不混入 username 解析；raw_info、缺字段、头像/主页字段与费用一致 |
| 3 | 单次用户动态，再处理复合 crawl | raw_info + raw_data、活动类型、逐调用预算和多阶段超时一致 |
| 4 | username 解析、补详情、RapidAPI、TGStat 与 Web 供应商 | 单独登记请求图、价格、错误计费与响应投影；不照搬未知结果重试 |

每一形状先建立离线 golden fixture，再发布 Hub 路由版本，对获授权调用者灰度。对比只用已有归档，不能默认双发付费请求。历史游标留在原分支，新游标绑定路由版本、查询指纹与身份；一个查询轮次不暗中换供应商。Twitter/Facebook 无标题规则、完整正文、计数与幂等账单保持。

SearXNG、本地抓取、正文抽取、Agent/CLI 运行环境及 Night-All 候选端点循环继续单列。纯固定转发完成前述参数/投影/分页/费用审核后才能进入聚合搜索，不能把 1037 个详情、评论、榜单接口一律加入关键词扇出。现有聚合 JSON/SSE、存量搜索和清洗计划保持原行为。
