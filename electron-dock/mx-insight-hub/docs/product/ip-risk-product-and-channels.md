# IP 风险画像产品与数据渠道设计

状态：2026-10-01。产品界面已实现；新增供应商、独立 IP 渠道代理绑定与跨渠道比对属于后续设计，未启用。本文覆盖客服/产品的查询工作台及可复用于 Web Search 的渠道模型。

## 1. 现状与边界

- 产品：Hub 的 `ip_risk` 数据域、`ip.risk.query` 能力；单个 `/api/v1/data/ip/risk`、批量 `/api/v1/data/ip/risk/batch`，维持 v1 合约与已分配权限、套餐、限额。
- 当前物理来源：`ipsearch`，服务端 `IpSearchAdapter` 固定调用 IP 数据云 SDK 0.1.0 对应接口。启信宝/启信慧眼是 `enterprise` 企业数据来源，并非 IP 风险来源。
- 百度参考：[IP 风险画像页面](https://cloud.baidu.com/product-s/afd_s/ip-threat.html?s=223.160.165.241&t=1790586718655)。2026-10-01 浏览器可访问，借鉴搜索、风险总览和标签层次；页面参考不等于可调用 API、采购授权或字段合约。
- 当前 IP adapter 直接使用既有服务端 fetch，没有绑定 Hub System Proxy。不把 Web Search/TikHub 的代理配置冒充 IP 风险的有效出口。
- MX-H2I V2 / Internal 是操作与配置中心。Hub 仅拥有产品、数据、权限、计量与渠道治理；不改变 Launcher/MX-H2I 登录、network lease、WireGuard、DNS、Domestic/Internal 路由、Luopan standalone 行为。供应商不可用只影响对应 Hub 数据能力，不成为登录或部署 readiness 依赖。
- Night-All docs/specs 用于理解历史采集与平台边界；当前 Hub 已直接实现的供应商能力以 Hub 代码为准，不倒退为 Night-All 转发，不执行旧文档中的部署动作。

## 2. 页面信息架构（已实现）

标签顺序固定为 **风险画像 → 接口调用 → 接口文档 → 渠道与接入**，默认首个标签。主画面复用 Neon Void 的明暗主题、侧栏、身份与 DropdownField；身份面板在选中身份后保持紧凑。仅 IP 页面改变默认顺序，其他产品不受影响。

### 风险画像

1. 单个/批量切换，分别保留输入。单个接受严格 IPv4，批量 1–100 项，以换行、空格、中英文逗号或分号分隔。显示无效项序号和重复项数；只有用户点击“去除重复项”才去重。API 仍保留输入顺序和重复项，每个重复项独立计量。
2. 搜索按钮是唯一采集入口。Enter 可提交单个，批量 textarea Enter 只换行。提交时立即锁定按钮与参数；切换外层标签不撤销在途请求，也不会再次发送。
3. 概览显示 IP、数据状态、原始风险等级、风险评分、秒拨概率、真人概率、代理类型、获取时间与交付方式。风险环是分类标记，不是评分进度。不存在统一评分范围/阈值，禁止展示伪造的 `/100` 或按分值计算等级。
4. 标签保留 name/code/last_seen；超过 8 项后搜索并分页。未做未经证实的“行为/设备/事件”分类映射，后续渠道拥有明确 taxonomy 才能分组。标签时间保留原文与未声明时区；Hub 获取时间以浏览器本地时间显示，两者不能混同。
5. 字段警告默认折叠，可展开查看对应字段及原始警告码。缺失 `null` 显示“未提供”；数值 0 与空数组 `[]` 都有独立语义。不补造归属地、运营商、机构、经纬度、地图或 AI 结论。
6. 复制摘要、导出单项原始 Hub JSON；服务端历史记录可按 IP/代理/标签/请求或批次编号搜索，按数据状态、原始风险等级筛选。每页 10 项，以游标翻页。历史列表导出本页概要 CSV；本次结果导出完整 CSV（含标签 JSON、警告和编号，处理表格公式前缀），历史详情支持原始 JSON。查看、翻页、筛选、导出不调用供应商。
7. 历史从既有数据库用量与批次响应快照读取，刷新、离开页面或重新登录后仍可回溯；范围严格为当前 tenant + consumer + 真实 Key ID，临时凭据续期不改变真实 Key。切换身份只切换可见范围，不删除服务器数据。浏览器仅保留最多 200 项详情缓存，不把结果或凭据持久化到 localStorage，不发布 IP 查询意图到共享 canonical/ES。内存演示环境在页面刷新后可恢复，但服务进程重启会清空，界面明确提示。
8. 单条详情和批次结果都显示请求编号；批次另保留 batchId、输入序号和逐项错误码。画像上方直接提供可搜索的批次 IP 选择器、上一项/下一项及当前位置，不必下滚至历史列表。按本次提交身份与原始输入序号切换，重复 IP、失败/未知项均可查看；查看旧批次时只切换该批次，不混入新批次或同 batchId 的另一次回放。历史淘汰后明示当前保留数量。整批耗时明确标注“整批”，不伪装为子项耗时。

### 状态矩阵

| 状态 | 展示与操作 |
| --- | --- |
| 尚未查询 | 说明输入方法，不自动发送示例，不放推测风险 |
| 查询中 | 禁止重复提交；已有记录仍可读；批量完成后统一显示，不编造百分比进度 |
| 查询成功 | 响应已通过校验；允许字段为空，不承诺字段齐全或无风险。未返回等级时显示“未评级”，评分为 0 时明确不等于无风险 |
| 部分数据 | 可用字段照常展示，缺失/异常字段附质量提示 |
| 暂无数据 | 明示不等于无风险；有效 no_data 按既有套餐结算 |
| 结果待核对 | 网络中断、409/未知结果、不可用响应等保留请求/批次编号；不自动重试；本页禁止再派发记录中待核对的相同 IP |
| 权限不足 / 身份失效 | 使用现有身份重新检查入口；业务授权和 Key 快照分别诊断，不自动授予权限 |
| 服务未就绪 | 已授权但 runtime ready=false 时禁发；Admin 指向当前平台配置，租户联系管理员 |
| 余额不足 / 达到限额 | 显示相应提示及编号，不伪装为无风险或无数据 |
| 未派发 | 批次预算不足的项明确显示未派发，不自动补跑 |
| 查询失败 | 保留错误码与编号，不自动重试或整批重跑 |
| 筛选无匹配 | 说明当前身份的已保存历史中无匹配项，不调用供应商 |
| 历史读取失败 | 显示读取失败及重新检查身份入口，不能误报记录为空 |

后端对于相同未知请求的防重与计费状态仍是权威；页面临时阻止重复提交不能替代服务器结算。服务恢复后用户通过已有用量/诊断流程核对，再决定后续新查询。

### 接口调用与文档

接口调用页提供单/批切换、参数、明确的 POST 路径、多语言请求预览与复制、完整 JSON 响应；与画像页共用输入、请求锁和已返回记录。修改输入后保留原响应并提示“上一次提交”。复制预览隐藏 Key，复制可运行命令时明确包含当前凭据和失效时间。普通请求继续无需 Idempotency-Key，每次主动发送是新查询。

第三标签嵌入现有受认证保护的文档页面，按首次打开加载，不复制一份可能漂移的文档。切换标签保留查询结果。文档/API/产品均遵守同一身份授权，不改变登录守卫。

## 3. 渠道模型（后续设计，不是新增运行能力）

避免将“产品”“供应商公司”“渠道”“HTTP 操作”和“代理”混为一个配置。建议复用已有供应商、凭据、operation policy、System Proxy 和证据存储，按渠道增加绑定和路由版本，不建立第二套密钥/代理目录。

| 层次 | 示例 | 所有权与职责 |
| --- | --- | --- |
| 数据产品 | `ip_risk`、`web_search` | Hub 业务合约、用户交互、授权、客户价格 |
| 供应商 | `ipsearch`、`baidu`、`qixin` | Admin 供应商档案、采购证据、账户与凭据引用 |
| 服务渠道 | `ip-risk.ipsearch.v1`、`ip-risk.baidu.v1`、`web-search.baidu.v1`（建议标识） | 一组兼容业务能力、独立运行状态、字段覆盖与路由策略 |
| 操作/适配器 | `ip.risk.query` + adapter release | 固定目标/参数白名单、签名、规范化、业务错误、单次派发 |
| 出口绑定 | channelId → egress policy | 当前渠道独立的 system-egress / proxy-sequence / 显式 inherit；不按公司名称推断 |
| 请求证据 | requestId / batchId / index | 固定渠道、适配器版本、凭据修订、出口与策略修订、原始归档和各自费用 |

同一家百度的搜索与风控可有不同凭据、域名、采购币种、计费单位和代理；不共享默认开关，不因百度搜索已接入便声称百度 IP 已可用。多个渠道可显式引用同一个 Proxy Sequence，但某渠道更改绑定不能更改其他渠道的绑定。

### 配置与路由

建议渠道字段：`channelId/productKey/providerKey/adapterRelease/operationKeys/credentialRef/egressBinding/fieldCoverage/rolloutPolicy/procurementEvidence/customerMeter/limits/revision`。字段覆盖注明已实现/已验收/未支持，运行健康另存时间戳和探测证据；“有凭据”“可连通”“成功交付”“数据完整”是不同状态。

默认路由绑定在 Hub 服务端，Admin 修改需 revision/CAS 与审计。租户普通请求保持 provider-neutral；当前 v1 严格拒绝 supplier/proxy/custom-url 等额外字段。未来若要提供渠道选择或比较，先定义新的版本化请求/授权能力，不能暗中放宽当前接口，也不能自动扩大已有 Key 权限。Web Search 既有公开 provider 选择和供应商 scope 是已发布例外，保持其现有语义。

派发流程：

1. 核验当前租户、调用者、Key、产品能力及请求参数。
2. 按请求形状、字段要求、授权、运行状态和预算，在**尚未派发**时选一个渠道；不合条件则返回明确阻断。
3. 冻结该次渠道、合约/路由/凭据修订与客户/采购金额依据。批次先固定策略版本，子项各有 requestId 和实际渠道记录。
4. 按当前渠道出口策略选择 System Proxy；只对已审核的固定目标做无凭据连通性探测。探测不请求风险业务接口，不等于数据健康；无已验证安全探测端点时先停留在人工验证阶段。
5. 完成准入后派发一次。空数据、部分数据、拒绝、超时或未知结果均不自动尝试另一个供应商或代理。连接探测可在派发前切换，已发出的付费请求不可换路重试。
6. 原始业务证据原样归档，独立规范化/客户结算；重放使用原交付与渠道，不按新的路由再次查询。

代理绑定默认保持既有实际行为，不能迁移时将 ipsearch 偷换成 TikHub 的 7788 或 global LLM proxy。控制台配置在 Internal 的 Hub Admin 操作面管理；不修改宿主机代理、系统网络或 Launcher 配置。

### 多渠道比对

先交付单渠道选择，再考虑用户明确发起的比对。每个渠道有独立 requestId、采集时间、评分定义、完整性和费用；并列显示分歧，不平均不同量纲的评分，不拼接成无来源的“最全画像”。缺字段默认不触发另一渠道补查。用户看清调用数量/价格后主动查询，未知子项单独核对。

## 4. 接入路线与验收

| 阶段 | 交付 | 本次状态 |
| --- | --- | --- |
| P0 | 产品首屏、单/批查询、状态、筛选导出、接口调用与现有文档、只读渠道信息 | 已实现 |
| P1 | 渠道注册与按渠道代理绑定；ipsearch 原行为等价迁移；修订审计、固定目标探测 | 设计完成，未实现/迁移 |
| P2 | 百度正式 API、授权/采购、字段/时间/评分语义、错误计费、原始证据与契约测试 | 候选，待正式接口资料，不作可用承诺 |
| P3 | 显式渠道比对、历史保留/删除策略 | 待独立需求与合约；当前身份历史检索已实现 |

P1/P2 验收至少覆盖：两个渠道独立 proxy；编辑 A 不影响 B；新渠道默认关闭且无隐式 grants/prices；无效配置只阻断该渠道；未知/空结果不自动换渠道；切换路由后旧请求仍重放原证据；生产暂停/自定义策略保留；密钥/采购只在 Admin Token 界面出现；MX-H2I 登录与联网不变。

历史回溯新增 migration 121，只增加身份与时间检索索引，不更改原始结果、服务器 dispatch、授权、价格或部署策略。回归使用内存存储、模拟 HTTP 与隔离 PostgreSQL 引擎，未调用真实付费供应商。相关实现与旧操作说明见 [IP 风险运行说明](../operations/ip-risk.md)、[Web Search](../integrations/web-search.md)、[Launcher/Hub 边界](../../../mx-launcher/docs/26-mx-insight-hub-integration-architecture.md)。

## 5. 2026-10-01 零评分与未评级排查

已读取管理台既有批次的 Hub JSON：两项均为 `risk_score: 0`、`risk_level: null`、`rapid_rotation_probability_percent: 0`、`human_probability_percent: 70`、`risk_tags: []`。它们不是前端把缺失字段补零的结果，也不等于供应商认定“无风险”。此前 UI 将 `success` 标为“完整数据”容易误读，现改为“查询成功”，不改变 API 状态、历史响应、计量或结算。

与 [ipsearch 官方字段说明](https://www.ipdatacloud.com/doc/iphuaxiang/) 和当前 adapter 对照，映射仍为 `risk_score → risk_score`、`risk_level → risk_level`、`mb_rate → rapid_rotation_probability_percent`、`real → human_probability_percent`。空等级转换为 null；缺失/非法评分不回填为 0，真人概率不默认填 70。回归覆盖官方非零评分/标签样例、零分空等级、显式 null、缺失字段，以及按传入 IP 分别派发。

此次未取得该线上批次在 PostgreSQL 中的供应商受限原始归档，不能仅凭 Hub JSON 判定是渠道覆盖、账户套餐、上游默认值或线上版本差异。进一步核对应先以 requestId 对照已有受限归档中的 `data.risk` 与交付快照，再检查供应商账户的画像服务权限/数据覆盖说明；无需重新购买查询。原始字段相同才能将原因定位到供应商返回，不能用另一渠道的风险等级反推本渠道映射错误。

## 6. 2026-10-01 历史回溯实现

新增只读 `GET /api/v1/data/ip/risk/history` 和 `GET /api/v1/data/ip/risk/history/{single|batch}/{id}`。读取历史仍需有效 Live Key 的 `ip_risk` 与 `ip.risk.query` 双重授权，但不依赖供应商凭据或实时就绪状态。列表按原提交时间倒序，批次按输入序号展开，重复 IP 独立保留；已完成批次的子请求不重复列为单条。

点击“回看画像”恢复原交付响应、时间、requestId、batchId 和整批逐项状态，并可直接用上方选择器切换全部 IP。界面显示“历史快照 · 未重新查询”。不会使用 POST 幂等回放、不触发采集/预留/计费，不重新解释或覆盖旧评分。未完整保存的批次显示待核对且禁止整批回看，已保存子请求可独立核对；不会为补齐历史重新派发。未进入用量或批次持久化的认证/前置校验失败没有可恢复画像。

升级后即可读取已有同身份数据库记录，无需回填或再次查询。范围不跨 Key；换用其他 Key 或权限被撤销后不能读取原 Key 数据。历史列表概要不含全部标签/警告，完整内容通过详情原始 JSON 回看。当前未新增自动清理或保留天数，依赖既有响应快照保留策略；已删除或从未落库的数据不能由界面恢复。
