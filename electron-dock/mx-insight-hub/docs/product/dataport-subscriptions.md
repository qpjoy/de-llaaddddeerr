# DataPort 商品、订阅与消费规则

2026-10-12，当前实现。用户已确认域名使用 `dataport.minsight-ai.com`、保留旧 Harbor 迁移入口；升级采用“新购高档套餐，旧订阅保留”。本页取代历史文档中“全部续订顺延”和“补差价升级待选”的描述。

## 职责与模型

Hub 是商品定义、销售状态、业务订单、订阅权益、消费分配和审计的唯一来源。订阅服务是数据商城的一种商品，不再建一套平行的订阅商品管理。Hub 管理端编辑商品，Hub Portal 与 DataPort 共用订单和权益 API；DataPort 只提供客户展示和操作入口。Pay 保持独立，只提供支付订单及可信付款事实，Hub 在验证事件后幂等交付订阅。本轮未改支付协议、钱包和支付来源。

商品配置包括名称、说明、分币售价、有效月数、总次数、每日上限（空为不限）、生效方式（立即/顺延）、销售状态、DataPort 上架开关及乐观修订号。修改只影响之后创建的订单。订单保存不可变商品快照；交付的订阅保存 quota、daily_limit、起止时间。旧订单和订阅不按新商品重新计算。

## 多订阅与每日额度

消费范围为原空间产品订阅；遗留调用者订阅保留原 consumer 范围。自动选择当前已生效、未到期且总额度/当日额度都可用的订阅，按最早到期排序，同到期按开始时间和 ID 稳定排序。

空间管理员/所有者可设置一个优先订阅，也可恢复自动选择；需要原有 billing.read + apikey.write 权限。优先订阅临时不可用时回退到其余可用订阅；次日恢复额度后再次优先。偏好在空间内共享，因此影响网页和 API 的新请求。越权空间、未生效、已到期或当前耗尽的订阅不能新设为优先。

每天按 Asia/Shanghai 00:00 划分。总次数和当日次数均在请求预留时检查；并发预留使用同一空间/渠道事务锁，避免最后一次超卖。成功与有效无数据消耗次数；明确失败释放，结果未知仍占用。请求归属与日期在预留时固定，跨日或切换订阅不会把处理中请求转扣到新订阅，已开始请求完成后仍结算原记录。历史回看和幂等重放沿用原规则，不发起新消费。

商品每日额度是每份订阅的限制，多份可用订阅的额度独立；不是用户全局日限额。没有可用权益时返回 subscription_required、quota_exhausted 或 daily_limit_exhausted；每日耗尽明确提示北京时间零点恢复。

## 升级

升级是独立全价订单。目标必须是当前已上架的同类空间商品，价格和总次数更高，月数及每日额度不降低；无限每日额度不允许降为有限。服务端验证旧订阅归属、有效期和目标修订，客户端不能选择价格。

未付款不改变消费偏好或权益。验证付款并交付后，新订阅立即起算、设为优先；旧订阅的用量、剩余额度、开始/到期时间全部保留。升级意图保存在订单内，重复付款通知不会重复发权益。不做折抵、退款或钱包余额调整。用户仍可切回可用的旧订阅。

## 接口与运行边界

- 管理商品：沿用 `/internal/v1/admin/commerce/products`，只允许原管理身份；普通 Portal 不能编辑价格、发布商品或创建验收价订单。
- 选择订阅：`POST /internal/v1/admin/commerce/tenants/:tenantId/subscription-selection`，body 为 `{subscriptionId: UUID | null}`。Portal/BFF 精确允许相应客户路径，保留会话、Origin、CSRF 和租户权限验证。
- 客户列表返回订单商品快照、总/日 used 与 held、preferred/selected/available。最多 100 条且当前消费、可用订阅优先展示。
- 匿名定价：DataPort `/bff/v1/catalog` 只以服务端网关凭据读取 Hub Admin listener 的 `/internal/v1/portal/catalog`。仅返回已发布且对外上架商品的销售字段，不返回消费者、订单、供应商、渠道或凭据，不开放任意查询参数。
- 数据库变更只有新增字段/表/索引、候选选择函数和原预留触发器升级；旧快照不回填日限额。保留原消费结算函数、已有 Key 授权和支付账本。

部署顺序和兼容标识见 [DataPort 发布清单](../../../mx-dataport/dataport.setup.md)。本机集成测试覆盖每日末次并发、失败释放、跨日、原订阅结算、租户权限、商品快照、升级幂等及双应用身份隔离；生产支付、供应商和 MX-H2I 真实联网需按原上线验收执行。
