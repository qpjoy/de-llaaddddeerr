# 租户控制台与按次计费

本次改动仅在 Hub，未修改 Launcher、MX-H2I、HDO、WireGuard、DNS、登录协议或线上数据库。

## Lyon 的 0.1 元/次配置

截图中的 100000 元已是钱包入账，但计费模式未启用、Launch 1M 未配置费率，因此不会自动扣款。无需再次充值。

管理员进入“套餐与配额”，选中 Lyon 和对应调用者，点击“配置小红书专属套餐 · ¥0.10/次”。表单预填小红书搜索、详情、用户资料、用户笔记四个计量键，每次基础价格 0.10 元，可删除不用的业务或调整合同价格。核对租户倍率：倍率为 1 时实际价格才是 0.10 元。勾选的“发布后分配并启用自动扣费”依次发布不可变版本、分配给当前调用者、启用租户 enforced 模式。不会重复充值或自动扩大 Key 权限。

这些步骤不是一个数据库事务：中途失败会报告已完成步骤，请在已有套餐目录中继续分配或在计费策略中启用，勿再次发布。响应丢失时先刷新核对服务器状态。

100000 / 0.1 = 1000000 次，仅是假设全部用于同价接口的余额估算；月上限、滑动窗口、Key 限制、其他业务消费仍分别生效。计费单位为 Hub 逻辑请求，不是返回笔记条数。成功交付扣费，确定失败释放，结果未知保留冻结并对账；已有幂等请求不重复收费。历史 disabled/shadow 请求不会因启用计费自动补扣。

## 套餐和调价

钱包、计费模式、租户倍率是租户级，多个调用者共用余额；套餐按调用者绑定。可为每个客户创建独立套餐标识，也可让多个客户使用统一版本；不同业务可绑定不同套餐或在一个价目表中逐接口定价。

发布新版本不会影响已有绑定。涨价须显式分配新版本，或修改租户倍率（会影响该租户所有适用业务），历史请求保持价格快照。目前没有余额用完自动换版本、按充值批次锁价或定时生效机制。若合同要求旧价用完，需要运营到约定时点手动换绑，不能把“月请求配额”当成一次性购买次数。

## 租户界面和演示

租户首页显示调用次数、成功次数、实际扣费、待结算次数和自己有 usage.read 权限的账户余额。套餐页显示当前合同价格、余额估算次数和流水，不展示管理员套餐目录。运营导航隐藏，服务可用性从首页进入。

数据产品是分类与入口，数据源目录继续是管理员统一治理目录；Key 是实际调用的权限身份。租户所有者或管理员无需填写 Key：只有一把可用 Live Key 时自动选中，多把时只展示自己的 Key 供选择。浏览器使用绑定成员的短期签名引用，不读取原始 Key；成员停用、降级或移出租户后，已发出的引用也失效。正常机器 Key 和 Admin Token 默认演示身份保持原有行为。演示调用仍走原来的授权、配额、运行开关与计费。

截图“我的接入”的提示是 social.users.posts 运行开关关闭，不是页面异常。自有 Key 不能绕过平台停用。对于 external_platform_* 报错，管理员需按请求 ID 检查“外部数据平台”中对应 operation 的运行状态、凭据和合约前置条件；不能仅凭截图确定具体错误码。本次没有修改线上运行开关或触发付费上游调用。


## 本次截图的修复路径

### 只给 Lyon 设置 0.10 元/次

1. 以平台管理员进入“套餐与配额”，选择 Lyon 和其小红书业务。
2. 点击“配置小红书专属套餐 · ¥0.10/次”。使用 Lyon 业务独有的套餐标识，保留已有 100000 元充值。
3. 检查四项 social.* 价格及新增的“当前租户成交价”列，确保需要的接口最终价格是 0.10 元。如果租户已有倍率，基础价和实际成交价可能不同，勿把基础价当成交价。
4. 勾选发布后分配并启用，提交。此操作只换绑当前调用者；计费模式、倍率、余额属于 Lyon 租户，不修改其他租户。管理员通过某个数据 Key 演示时，仍按那个 Key 所属业务计费；管理登录身份本身不是免费套餐。

现有模型足够：套餐版本定义价格/限额，调用者绑定版本相当于当前业务合同。只有需要周期续订、合同起止日期、到期换价或分批余额锁价时，才需要进一步设计订阅/合同生命周期。当前没有自动续订或余额耗尽后自动换版本。

### platform_not_granted

这来自实际 Key 的小红书有效数据授权检查，不是计费错误。有效授权是调用者当前授权与 Key 签发快照的交集。图4的“已授权”是调用者侧能力，不证明图3所用 Key 包含小红书数据域。

管理员先确认 Lyon 对应调用者的数据域包含 xiaohongshu。然后在“API Keys”检查实际 Key 的授权范围：原 Key 如果没有 xiaohongshu，点击“签发 API Key”创建新 Key，使用新增的“勾选已开通的小红书画卷权限”。应包含 xiaohongshu 数据域，以及需要的 social.posts.search、social.posts.resolve、social.users.resolve、social.users.posts 和 compat.xiaohongshu.app_v2。这个按钮只能勾选调用者已经开通的权限。

旧 Key 的快照不会被自动扩大；“签发替代 Key”保持旧范围，因此缺权限时应创建新 Key。确认签发后，在画卷的“我的 Key”中选择新 Key。不要自动撤销旧 Key，以免影响正在使用它的外部客户端。

### 运行时未就绪

截图明确是 social.users.posts 的运行开关关闭。管理员进入“数据清洗中心 → 外部数据平台 → TikHub”，找到“社交用户笔记”的运行策略。核对凭据、合同发布和采购价目证据都满足后，可以先用“灰度 / canary”仅允许 Lyon 的调用者 ID，再保存变更原因；不必为所有租户全局启用。如果前置条件不满足，按该操作显示的阻断项补齐，不能只改业务授权勾选框。

画卷现在按当前操作诊断：用户笔记未就绪只阻止用户笔记查询，不影响已就绪的搜索和详情。修改授权/运行策略后点击“重新检查”。缺少 Key 快照授权时依然需要选择新 Key；刷新不能扩大旧 Key。此次代码修改未对线上调用者授权或运行开关做写入。

部署时需同步更新 Hub Admin 与 Public listener：租户临时身份使用独立前缀，旧版 Public 会拒绝它，避免旧版忽略成员绑定检查。无需修改 Launcher 或数据库结构。
