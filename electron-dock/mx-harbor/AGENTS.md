# Harbor product boundary

- Harbor（数港）对外，Hub 对内；布局、颜色、密度和组件沿用 `/tmp/dataport` 及已抽取的 `ui-design`，技术栈、SSO 和部署沿用当前 MX 项目。原型中的价格、假订单和单独账号后端不是生产业务授权。
- Launcher/Auth 拥有统一账号，Harbor 拥有自己的会话，Hub 拥有空间、权限、订单、订阅和用量，mx-pay 独立拥有支付事实。不得影响 MX-H2I 已有用户登录或联网，不得把数据/支付/提醒就绪作为其依赖。
- 普通客户只能走明确的 BFF/Portal 客户路由、当前空间权限与原 Key 交集。不能把 Hub 管理接口直接转发出去；保留真实订单、支付返回、幂等和未知结果处理。
- 2026-10-11 已加入订阅期内再购买提示和客户站内消息（Hub migration 144）。消息按空间隔离、已读按成员隔离；供应商告警仍 Admin-only。定时收集不调 Pay/供应商、不改变期限或额度、不发送外部通知。
- “新购立即生效、最近可用订阅优先”仍是待选择方案，本次暂保留已有顺延续期，不推定用户确认了消费策略变更。不重写已售订单或已发权益。见 docs/architecture-and-rollout.md 同日小节。
- 本地数据库和样例浏览器验证必须与生产发布、实际付款、真实查询分开报告；操作步骤直接写在回复中。修改后运行类型/生产构建、相关边界测试和必要的浏览器验证。

- 2026-10-11 六项界面跟进：不要恢复页底重复品牌；用量按当前空间全量聚合且区别订阅消耗。空间权限页展示真实成员和服务端角色矩阵，不能为外部客户提供 Hub 管理令牌/平台成员列表或失效的邀请按钮。
- IP GIS 只读已交付坐标，缺失不补造；未确认坐标系仅做区域参考，不能推定百度坐标属于 WGS84。地图显式加载且不重查/计费，只给底图传地理范围。
- 商品的数港上下架由 Hub 商品管理的 harborListed 控制，展示与新购买都在服务端执行；旧订单、幂等恢复和权益保持不变。新商品默认未对外上架，旧管理端遗漏字段不能覆盖已保存设置。
- Harbor 文档必须显式按当前 tenantId 校验，空间之间及不同 consumer 的 platform/capability 不得合成授权；保留 Key 的独立授权与订阅门禁。公开文档是已有合同的租户视图，不等于目录中出现就必然可调用。
