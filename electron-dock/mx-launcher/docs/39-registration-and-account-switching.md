# 账号切换与统一注册：第一批交付

日期：2026-10-03。接续文档 33、35、37。本批代码尚未部署生产；现有私网 issuer、证书、账号、Hub 租户及 H2I/Luopan 登录和联网配置保留。

## 本批验收入口

管理员使用已有个人管理账号，或原 Internal Ops Token，打开「成员与访问 → 用户与账号 → 注册与邀请」。普通个人账号登录成功但没有 `mx-admin` 时，页面显示「已登录，等待管理授权」及授权路径，不再把 403 显示为服务离线。已有管理员可在用户编辑中授予 MX Admin；部署不自动提权，也不使用已公开默认密码的 demo 账号作为个人管理员。

1. 注册方式提供关闭、邀请码注册、开放注册。首次无记录时为邀请码模式；没有有效邀请码就不能注册。后续配置存数据库，deploy 不覆盖，无需新增环境变量。
2. 邀请可设置名称、名额（1–1000）、有效天数（1–90），查看最近 100 条的使用量和到期状态，并停用。完整码仅生成时返回，关闭窗口即清除；列表、审计不保存明文码。当前邀请范围为统一 MX 账号，不包含指定 Hub 租户、管理角色或付费权益。
3. 个人登录页按策略显示「使用邀请码注册」或「创建账号」。账号以字母开头，3–64 位，新注册密码 8–128 位，需二次确认；登录不增加最低长度限制，已有密码继续有效。登录、注册页使用 Neon Void 配色与紧凑表单，适配桌面和手机。不收集未验证邮箱，不基于显示名、邮箱域名合并旧身份。
4. 注册后自动完成当前登录，创建普通 `mx-user`；不写管理角色、网络授权、Hub membership 或财务权益。工作台管理权仍需已有管理员授予。已有应用的独立准入策略继续生效。
5. 关闭注册、停用邀请码只阻止新开户，保留已注册账号及其既有权限。提交旧表单时重读当前策略并检查版本。

注册从当前已验证 OIDC 交互中取得 client 和 transaction，表单不能自报来源应用、角色、tenant 或 userId。当前只登记了 Launcher 管理客户端；本批没有声称 Hub 已接入 OIDC 或已实现产品默认方案自动开通。

## 退出、重新验证与切换

工作台退出撤销本站会话和登录事务；新增「切换账号」先退出本站，再发起交互登录。Launcher 的显式登录和重新验证均使用 `prompt=login`，不再因身份站点保留最近会话而悄悄返回旧账号。[OIDC prompt 定义](https://openid.net/specs/openid-connect-core-1_0.html#AuthRequest)

重新验证保留原主体约束，不允许在一次管理操作中换人；需要换账号时使用切换按钮。未声称已实现跨所有应用的全局退出。

真实浏览器验收还发现并修复两处账号切换阻塞：身份引擎的自动提交表单需要显式 `script-src` 才能附加精确脚本 SHA-256 授权；适配器 `revokeByGrantId` 必须限定当前 token model，不能把仍在进行的 Interaction 一并删除。没有开放任意内联脚本，也没有跳过 CSRF、PKCE 或 TLS 验证。

## 持久化与原子性

账号的唯一写入者仍是 Launcher Internal API。Identity 进程继续只读原账号/密码，通过固定内部注册端点调用 Internal API；这个端点不会被当前 HTTPS 代理转发给浏览器。请求使用现有托管客户端秘密进行限定用途 HMAC，绑定整个消息、客户端、动作与 30 秒时间窗口，不增加新的人工 key。Identity 只会提交已经验证过交互 Cookie、Origin 和 CSRF 的表单。

`mx_platform_records` 新增 `registration-policy / registration-invite / registration-redemption` 记录种类，账号/密码沿用原种类、哈希格式及 userId 体系。新账号、密码、邀请名额、兑换记录和审计同事务提交。重复交互只返回原账号，不再次扣名额；密码或账号不同的重放拒绝。失败回滚不残留半个账号。原管理员创建账号与注册共享账号创建锁，避免并发创建同名主体；原创建行为、密码更新和可选 Oversea 开通语义保留。

注册限流与原密码登录分开计数。停用账号仍不能通过兑换重试恢复登录。新记录由现有完整 PostgreSQL 备份覆盖；身份密钥继续在宿主机 profile 和既有恢复快照中，Docker 重建不重置注册策略、邀请码或账号。

本批是内网账号注册验收，不是公网身份系统全部能力完成。联系方式验证、自助找回、MFA、全局撤销、多产品默认开通和账号归并仍按后续阶段实现；内网账号恢复暂沿用现有管理员用户中心流程。

## Hub 公网注册、Launcher 管理面保持私网

可以复用 MX 账号权威，不需要开放 Launcher 管理面。但公网浏览器必须能访问身份授权/注册页面；Hub 后端能访问内网不代表浏览器也能访问 `10.88.88.88`。

| 入口 | 目标可达范围 | 边界 |
| --- | --- | --- |
| Launcher Admin 与运维 API | 原内网/VPN | 不增加公网反代或全局 Ops Token 分发 |
| 公网 Identity（地址待定） | 公网 HTTPS | 只发布必要的 OIDC、登录、注册、身份源回调；不转发 `/admin/`、`/internal/`、`/admin-api/`、`/identity-backend/` |
| 公网 Hub | 公网 HTTPS | 独立 OIDC 客户端、精确回调、服务端会话；数据和租户权限由 Hub 判断 |
| 账号写入与应用开通 | 受认证的后端通道 | Internal 创建/关联原账号；Hub 幂等创建或复用本地业务成员 |

不能仅给现有 18443 增加一个公网域名反代：当前 issuer 和回调仍是私网地址，且该监听还代理管理页面。后续新增独立公网身份部署档案/监听和严格路由允许列表，保留现有私网 issuer；不会直接修改现有 profile 或轮换密钥。公网 issuer 到稳定 MX userId 的信任与映射必须显式登记，不能按邮箱自动绑定。

下一验收批按顺序完成：

1. 公网身份实例及 OIDC 应用登记，集中保存 issuer、客户端和精确回调；对既有私网管理入口做兼容测试。
2. Hub BFF 的 OIDC 登录/回调/退出。可信原 userId 预绑定到既有 member，保留其 tenant、membership、Key、钱包和角色。缺映射或冲突时保留旧登录，不静默建第二个旧用户。
3. 新 Hub 注册绑定服务端来源应用，按配置创建受限个人空间或加入被明确邀请的原租户。账号已创建而 Hub 开通失败时记录 onboarding 阶段并幂等恢复，不反复创建账号/租户。
4. 复用 H2I 飞书应用新增 Web 回调，保留原客户端回调、飞书网络身份及凭据；再实现本地/飞书双向身份验证后的账号绑定。邮箱相同不自动归并。

Hub 当前有独立支付相关未提交工作，本批未修改 Hub 文件，也未触发 Hub 生产升级。公网域名、证书和回调地址确定后进入真实公网验收；本地注册成功不等于公网 Hub 已可自助开通。
