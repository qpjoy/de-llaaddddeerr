# Hub 独立注册策略与可信来源

状态：2026-10-04，本地实现，未部署生产。延续文档 33 的身份边界，只交付当前需要的注册控制与来源追踪；不引入统一租户平台或跨中心权限服务。

## 管理员怎么使用

Internal → 成员与访问 → 用户与账号 →「注册与邀请」：

- **默认注册方式**：沿用关闭 / 邀请码 / 开放；关闭是统一账号新注册的总开关。
- **Hub 注册方式**：跟随默认 / 关闭 / 邀请码 / 开放。升级前未设置时跟随默认，不自动开放。
- **只开放 Hub**：默认保持“邀请码注册”，Hub 选择“开放注册”。Launcher Auth 入口仍需邀请码；H2I/Luopan 原 SDK、飞书及业务注册入口不接入这个 Web 开关。
- **关闭 Hub 注册**：只限制经 Hub Auth 事务新建账号，已有账号仍可登录。Hub 企业邀请也不能绕过该应用关闭或平台总关闭。

Hub 的独立设置可以覆盖默认的邀请码/开放模式；平台总关闭始终优先。保存任一设置递增同一个策略版本，旧表单提交需要刷新。旧管理客户端省略 `hubMode` 时保留已保存值，不将它清空。恢复“跟随默认”必须明确保存 `inherit`。

用户详情新增“首次注册来源（只读）”。原 `Registered By` 标为兼容归属，保留原行为，避免改变现有 AppCenter 按归属匹配的访问规则。

## 来源怎么确定

Auth 从已验证的 OIDC interaction 和静态客户端登记确定 `issuer / clientId / appId / appOrigin`，随原签名后端通道传递。注册写入者核验来源格式及签名通道对应的 issuer。页面提交的 `source`、Referer、任意 URL 参数不能替代该来源。

新用户的原 `iam-user` JSON 增加可选 `registration`：

```json
{
  "source": {
    "issuer": "https://auth.example/identity",
    "clientId": "hub-public",
    "appId": "mx-insight-hub",
    "appOrigin": "https://hub.example"
  },
  "method": "password",
  "policyVersion": 1,
  "registeredAt": "2026-10-04T00:00:00.000Z"
}
```

`appOrigin` 标识此次注册的应用实例；不是另建实例目录。绑定飞书的新注册记录 `method=feishu`。来源与账号、凭据、兑换记录、审计同一事务保存。重复提交返回原账号，普通资料编辑保留首次来源；历史账号不回填、不从兼容归属或邮箱猜测，也不重新分类。没有来源的旧 Auth 注册在跟随默认时维持兼容，不编造来源；显式启用 Hub 独立策略后，新注册必须携带可信来源，防止旧 Auth 绕过应用关闭。

本批只记录首次注册。后续登录来源、通用应用开通任务和跨中心组织映射没有在这批扩展。

## 新 Hub 账号的默认边界

新 Hub 注册账号沿用原最小 `mx-user`，不会授予 Launcher `mx-admin`。在创建时写入已有应用拒绝机制：`deniedAppIds = ["mx-h2i", "luopan"]`，因此不能借通用 SDK 登录再申请这两个产品的网络租约。邀请码额外应用目录授权也不能覆盖明确拒绝。

这是**只针对新 Hub 注册账号的创建默认值**，不是根据来源在每次登录时重新施加禁用。以后需要加入 H2I/Luopan 时，管理员可使用原成员应用访问设置明确解除对应拒绝，再按产品原规则准入；不要仅添加 Allowed Apps 而保留 Denied Apps。无新产品网络准入引擎。

已有 H2I/Luopan 用户、之前注册的 Hub 用户、原 token、lease、peer 不回填或变更。Hub 的原 member/tenant/Key/钱包不迁移。普通 Hub 注册按原个人空间策略开通；企业邀请注册按文档 43 显式加入指定租户；两者都不自动发 Key、余额或付费额度。

## 部署和验收

沿用现有 Launcher/Auth/Hub 服务、数据库及备份。新增字段落在既有 JSONB 记录，**不新增表、迁移脚本、环境变量、密钥、队列或常驻进程**。

这里描述的是本批增量；若与尚未上线的文档 43 企业邀请一起发布，仍须按文档 43 部署 Hub 并执行 migration 125，不能省略前批迁移。

按原流程先更新 Launcher API 与全部 Auth 副本，再使用新版 Internal 设置 Hub 策略。实际回退到不识别独立策略的旧版本会忽略该设置，不能承诺保留 Hub 单独关闭效果；回退前需用旧版本认识的平台总关闭暂停新注册，已有账号仍可登录。不要在新旧 Auth 混合时宣布应用策略验收完成。

验收覆盖：

1. 默认兼容、Hub 单独开放/关闭、平台总关闭、策略版本冲突、旧管理客户端保存及重启恢复。
2. 原账号字段不变；来源在账号与审计中一致，编辑不覆盖；普通来源数据由真实 Auth 事务决定，伪造表单来源无效。
3. 新 Hub 账号的 H2I/Luopan SDK 登录及用通用 token 申请网络租约被拒绝；原产品登录、网络隔离与 lease 身份回归。
4. 真实 HTTPS/OIDC + 临时 PostgreSQL + Chrome：Hub 无邀请码开放注册，按原策略建立个人空间；随后关闭 Hub 注册，原账号仍能登录；企业邀请流程保持。
5. Launcher 实际静态页面配合隔离接口夹具：桌面/390px 设置保存与重开、来源只读展示；服务端策略与授权由真实 PostgreSQL 测试单独验证。

生产开关本批不修改，线上飞书、原 H2I/Luopan 连接仍需按原发布流程验收。没有把本地测试写成生产已上线。
