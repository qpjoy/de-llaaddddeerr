# 浏览器账号选择与应用切换

状态：2026-10-04，本地实现；上线需先更新 Launcher/Auth，再更新 Hub。沿用 42、45 的身份及会话边界，不新增数据库迁移、环境变量或服务，mx-common 无需独立部署。

## 入口与体验

- Hub 登录页、退出页、右上角和「我的账号」直接提供「切换账号」，不必经过管理员入口或展开账号选项。
- Launcher 登录页直接提供「选择或切换账号」，已有账号菜单同样进入 Auth 选择页。发起选择不会提前销毁原 Launcher 会话；选择完成后替换应用会话，取消可返回。
- Auth 按可信 OIDC client 展示目标应用，列出当前浏览器成功使用过的账号。有效的当前 Auth 账号显示「已登录 · 继续」；历史账号显示「重新登录」，选中后带入账号，但仍需密码或飞书验证。Hub 的重新验证表单继续显示在 Hub 中。
- 「使用其他账号」可以登录或按原策略注册新账号；历史账号的「移除」只忘记此浏览器的记录，不删除用户、成员或租户。当前有效账号不显示移除操作。
- 普通登录继续保留 SSO 自动复用。即使 Hub 账号有有效 Auth 会话，也必须经过 Launcher 自己的管理授权判断；普通 Hub 注册用户不会自动变成 Launcher 管理员。

本版只有一个当前有效的 Auth 会话，并提供最多 8 个历史账号提示；不声称支持 Google 式多个账号同时免密保活。切换到其他账号需要重新验证。切换不等于撤销所有应用会话，其他已经打开的应用按其原会话规则运行；需要全面退出时使用现有的「退出所有网页登录」。

## 可复用协议

应用 BFF 向标准授权端点发送 `prompt=select_account` 即可进入公共账号选择页。仍使用原 state、nonce、PKCE 与已登记回调，无需增加客户端或回调地址。现有应用入口：

```text
Launcher: /auth/admin/login?select=1
Hub:      /auth/sso/login?surface=application&select=1&ui=%2Fadmin%2F
```

Auth 完成选择后按原 OIDC 回调返回应用。选择历史账号时，原生应用通过现有 options API 获得可选 `loginHint`；该值来自 Auth 解密后查验的浏览器记录，不是凭据或授权。不同应用不需要复制账号历史存储，也没有新增跨域账号枚举接口。

原 `switch=1` / `prompt=login` 保留强制重新验证语义，用于原有敏感操作、账号绑定等场景；与 `select_account` 分开。继续当前账号保留原 `auth_time`，不延长敏感写操作的近期验证窗口。Hub 的 `return=account` 仍校验原 subject，不允许借选择换成另一个人完成绑定。

## 存储与安全

Auth 的 `__Host-mx_accounts` Cookie 只保存账号 ID 和最近使用时间，使用 AES-256-GCM 加密认证，并绑定 issuer；Secure、HttpOnly、SameSite=Lax、无 Domain。复用现有 Cookie 密钥并支持轮换，不保存密码、令牌或独立认证证明，不写 localStorage。记录有效期 30 天，清除浏览器 Cookie 后消失，不跨浏览器同步。

只有实际完成密码、飞书、注册或有效当前会话的 OIDC 交互才记住账号。旧版有效 Auth 会话也能在选择页识别当前账号；无法追溯升级前已退出的历史账号。Cookie 解密失败或过期仅丢失提示，不影响原账号登录。

每次选择都从 Auth 重新确认用户状态、应用禁止访问规则及真实当前 Session；停用、密码更改和设备撤销按原策略生效。只有历史 Cookie 无法登录，即使复制到其他浏览器也需要验证。选择和移除使用绑定交互 Cookie 的 POST、Origin 和 CSRF 校验。提示中的账号不等于应用授权，业务租户与权限继续由应用判断。

## 验收边界

本地隔离验收使用真实 PostgreSQL、HTTPS OIDC 和 Chrome，覆盖当前账号继续且验证时间不变、跨账号重新验证、回到 Hub 原生表单并预填、退出页直接切换、移除后刷新、复制提示 Cookie 不能登录、CSRF 拒绝及撤销后不再显示已登录。根路径和模拟线上丢弃查询参数的 `/admin/` 均须通过，亮暗主题及移动宽度须无溢出。

另回归原账号/注册、Launcher 管理授权与近期验证、SDK 登录和网络隔离、MX-H2I 检查。上述本地结果不等于线上已发布，也不代表已验证真实飞书或现有用户的在线网络连接。

本次验收：Launcher 65 项、桌面会话/应急入口 9 项通过；Hub 根路径与 `/admin/` 的完整原生账号浏览器用例均通过，原托管 SSO、企业邀请和路由隔离回归通过。Launcher 类型检查/构建、Hub 构建、MX-H2I check 通过。账号提示 Cookie 的密钥轮换、issuer 隔离、篡改拒绝、独立过期和数量上限已覆盖；亮暗、390px 和 1440px 截图已检查。
