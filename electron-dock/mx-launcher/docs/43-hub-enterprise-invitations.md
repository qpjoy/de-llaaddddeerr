# Hub 企业邀请与自动租户绑定

状态：2026-10-04，本地实现及隔离验收；未部署生产。补充 [33 §6.1](33-mx-platform-identity-and-sustainable-architecture.md#61-邀请加入现有企业)，沿用文档 40–42 的原账号、SSO 和会话生命周期。

## 解决的流程

原先需要管理员建租户 → 用户先登录 → 管理员再找到该账号并绑定租户。现在可以：

1. 平台管理员或租户 owner 打开 Hub「团队邀请」；平台管理员的「调用者」页也保留入口。
2. 选择已有租户、角色、备注、1–30 天有效期，生成并复制一次性链接。平台管理员还可以选择「新建企业租户并邀请」，同时创建租户与首位负责人的邀请。
3. 受邀人打开链接，使用自己的原 MX 账号登录；允许注册且平台未关闭注册时，可直接创建新 MX 账号，无需再索取第二个注册邀请码。
4. 页面展示目标租户、拟授角色及当前账号；明确点击「确认接受并加入」后，Hub 自动绑定原 member 与指定租户，并进入该租户页面。财务角色进入支付页。

未登录不会加入，登录本身也不会接受邀请。可以先切换账号；已有成员保留原角色，停用的成员关系不会通过邀请恢复。原手工绑定入口继续保留。

本批为**管理员自行分享的单次持有者链接**，不校验指定邮箱或手机号。备注只帮助管理，不限定接收账号；链接应只发给目标成员。未实现邮件/短信投递、实名企业认领或联系方式验证。文档 33 的这些目标仍单独待办。

## 授权与数据归属

| 对象 | 当前行为 |
| --- | --- |
| 邀请管理 | Hub 平台管理员或目标租户现有 `membership.write` 持有者；当前租户角色中只有 owner 可邀请，普通 admin 不扩权 |
| 创建企业租户 | 仅平台管理员；与首次邀请在同一 Hub PostgreSQL 事务内提交 |
| 邀请角色 | owner / admin / analyst / viewer / billing，复用 Hub 既有能力矩阵 |
| 原账号 | Auth 验证 Launcher 原账号；注册仍由 Launcher 原注册仓库写入，不新建第二套密码 |
| 新账号 | 仅最小 `mx-user`；企业邀请不会额外发放应用 grant、网络权益、API Key、付费额度或余额 |
| 原业务记录 | 原 userId、member、tenant、membership、Key、钱包和历史记录保留；不同账号不按邮箱/备注自动归并 |
| 个人空间 | 从企业邀请发起的此次 SSO 回调不自动新建个人租户；已有个人空间与其他成员关系不删除 |
| MX-H2I / Luopan | 原密码、飞书、访客、SDK Token 与 ProductNetwork/lease/peer 路径保持；本批邀请不访问或改写客户端网络记录 |

## 安全与重试

- 32 字节随机链接秘密放在 URL fragment；页面以同源 POST 换取 30 分钟 Secure、HttpOnly、Host Cookie 上下文，再移除地址中的秘密。不放入 localStorage/sessionStorage。打开链接受独立限流保护。
- 数据库以 SHA-256 查找链接；另用已有 Hub SSO 会话密钥加密保存秘密，仅供原创建请求幂等重试返回同一链接。列表、审计不返回秘密；UI 仅创建成功时展示。
- 接受要求原 SSO 会话、同源 POST、CSRF 及实时 Auth 身份核验。锁定邀请和成员关系，在同一事务内写入 membership、消费邀请及审计。并发只能一个账号接受；同账号重试不重复绑定，不恢复已停用的关系，租户停用后重试也拒绝。
- 接受请求携带页面展示的邀请 ID，与 Cookie 上下文核对；另一标签页切换邀请后，旧页面必须重新检查目标，不能静默加入另一个租户。
- 首次接受、注册证明、重复创建均重验到期、撤回、租户状态及邀请人的 **Hub 当前权限**。人员邀请重验 Hub 成员状态、平台管理员或 owner 关系；Admin Token 邀请绑定其摘要，Token 轮换使未接受邀请失效。这里不是对邀请人 Launcher 账号的额外实时远程轮询。
- 撤回只阻止尚未接受的邀请；已加入成员需要通过原成员管理撤权。新增的身份注册审计记录企业邀请的来源与 ID，不记录链接秘密。

## 无需第二个注册码的实现

邀请登录生成独立的 5 分钟 `invitation-registration` 上下文，经 OIDC 参数 `mx_invitation` 传给 Auth；该值不能当作接受成员邀请的凭据。Auth 只访问静态客户端登记中的 Hub HTTPS origin，使用已有 OIDC client secret 做 HMAC 验证，由 Hub 返回当前有效的邀请证明。Auth 在展示注册页和提交注册时均检查证明，再经既有认证后端通道交给 Launcher。浏览器不能自行提交可信企业邀请证明。

Launcher 仍执行注册模式和策略版本检查：`closed` 拒绝新注册，`invite_code` 可用企业证明替代普通注册码，已有账号登录不受影响。平台级账号写锁与持久兑换记录确保每条企业邀请最多注册一个账号；同一账号/密码重试返回原 userId，其他账号拒绝。

注册与租户接受不是跨库大事务：注册成功后关页或邀请随后失效，可能留下最小 MX 账号，尚无企业成员权限；用户可使用该原账号恢复流程，不删除账号补偿，也不重复建账号。邀请注册上下文超时需回到原链接重新发起登录。

## 发布与验收

无需新增 env key、证书或密钥；沿用现有 SSO 配置。先部署包含 Auth 的 **mx-launcher**，再部署 **mx-insight-hub**。Hub 执行增量 migration `125_tenant_invitations.sql`，新增邀请表并扩展已存在的 SSO 上下文类型约束；不重建业务数据。混合旧版本期间不能验收免第二码注册。Auth 到登记的 Hub HTTPS 地址必须可达且证书可信；旧环境还需确认已具备文档 40、41 的 SSO 基础配置。

本地验证使用临时 PostgreSQL、临时 HTTPS 证书、真实 Auth/OIDC 与原注册仓库：

- `tenant-invitations.test.mjs`：owner/admin/跨租户权限、建租户幂等与事务回滚、两账号竞争、已有角色不覆盖、停用/撤回/到期/邀请人降权/Token 轮换、审计失败回滚、重启与零 Key 发放。
- `browser-sso-routes.test.mjs`：真实 Hub 路由装配、Admin/Public listener 隔离、原凭据优先级与 principal 传递。
- `tenant-invitation-journey.test.mjs`：独立短期证明、签名拒绝、已打开注册页后的撤回；可选 Chrome 流程覆盖管理页生成链接 → 注册免第二码 → 显式接受 → 正确租户回跳。桌面 1440px、窄屏 390px、亮暗主题，校验无意外个人租户、无新 Key、无页面异常。
- 原 SSO、注册、身份、密码/飞书 SDK、ProductNetwork 隔离、lease 身份测试，以及 MX-H2I `check`。

执行 PostgreSQL 测试需设置仅指向本地临时库且库名含 `sso_test` 的 `MX_SSO_TEST_DATABASE_URL`。浏览器步骤还需先构建 Hub，并将 `MX_SSO_BROWSER_MODULE` 指向环境已有 Playwright 模块（使用 Chrome）；无此变量时仅验证后端协议，不应宣称浏览器验收。生产 DNS/TLS、真实飞书、正在使用的 H2I 连接和线上 Luopan 仍需部署环境验收。本批没有连接生产数据库或部署服务。
