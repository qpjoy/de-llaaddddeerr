# 网页登录会话与旧账号兼容

状态：2026-10-04，本地实现与隔离验收。本批未部署生产。本文补充文档 33 §5.3，延续文档 40、41 的原账号 SSO，不替代历史部署记录。

## 用户可以做什么

Launcher 右上角个人账号菜单新增「网页登录会话」，Hub 右上角提供同名入口，前往 Auth 的 `/identity/sessions`。页面跟随系统亮暗主题，支持窄屏，列出最近 100 个有效的浏览器登录：浏览器/系统、登录与到期时间、关联应用和当前浏览器标记。这是浏览器会话列表，不是硬件设备识别。

- **退出此浏览器**：撤销所选 Auth 浏览器会话及其关联的 Launcher、Hub 网页登录。
- **退出全部网页登录**：撤销该账号、当前环境内所有托管 Auth issuer 的既有网页登录，包括当前浏览器。新验证身份后可以重新登录。
- **现有应用退出**：原 Launcher/Hub 退出入口仍按各自原语义工作，不自动扩大成全局退出。
- **修改密码**：原有改密接口或管理员为已有账号保存新密码后，原 Web 会话需要重新验证；只改显示名称、角色等资料不会设置密码撤销时间。

撤销要求最近 5 分钟内重新验证身份，使用同源 POST、服务端 CSRF、独立限流和服务端归属校验。其他账号的会话 ID 不能被操作。相同认证事务下重复提交同一撤销动作不会误撤销后来的新登录。

升级前未携带浏览器关联 ID 的 Launcher 会话继续按原绝对期限使用，可以用「退出全部网页登录」或改密撤销；重新登录后支持单独管理。未配置托管 SSO、外部 IdP 和 Ops/Admin Token 不展示这个个人会话入口。Ops/Admin Token 仍按自己的轮换与退出规则管理。

## 生效范围与兼容边界

| 对象 | 本批行为 |
| --- | --- |
| Auth Session / AuthorizationCode / AccessToken | 读取时验证账号状态、改密时间和全局/单浏览器撤销记录；已撤销的证明不能继续兑换或查询身份 |
| Launcher 个人 BFF 会话 | 每次请求核验原用户、改密时间及托管身份撤销记录；浏览器关联来自已验证签名的 ID Token |
| Hub SSO 会话 | 写请求与会话状态查询实时向 Auth 核验；普通读取的已有验证缓存最多 30 秒；明确失效后立即清除本进程的旧缓存 |
| MX-H2I / Luopan 客户端 Token、lease、peer | 网页退出不读取、不修改这些记录；原密码/飞书/访客协议和联网路径保留 |
| 原密码更新 | 保留此前已有的 SDK 用户 Token 撤销语义，同时原子保存密码和 Web 撤销时间；本批不是让「网页登录退出」触发改密 |
| Hub member / tenant / membership / Key / 余额 | 登录身份及业务记录不迁移、不重建；网页退出不撤销机器 API Key |

撤销约束后续身份验证，不能撤回已经执行的业务动作，也不会远程擦除另一台浏览器已显示的页面。Hub 其他进程的读缓存仍受上述 30 秒上限约束。当前实现为服务端查询撤销状态，没有宣称已实现向任意第三方 RP 推送退出通知、离线通知队列或全平台确认看板。

## 存储与并发

- 改密截止时间 `webSessionsInvalidBefore` 附加在原 `iam-user` JSON 中，只在明确修改已有账号密码时写入；升级不回填，不重写旧 Cookie/Token 到期时间。
- PostgreSQL 原密码更新、既有 SDK Token 撤销、Web 截止时间及原审计在一个事务中提交。失败全部回滚。Auth 密码验证使用原账号写锁的共享锁，避免在改密提交期间读取旧密码并赋予较新的认证时间；并发 Web 登录可共享读取，原 SDK 登录代码不变。
- 浏览器撤销与幂等动作保存在既有 `mx_identity_records`，使用独立的环境级 `web-security` scope。保留 90 天，覆盖当前最长 30 天会话；过期清理不触碰业务表。不同 issuer 的浏览器 ID 带 scope 摘要，互不混淆。
- 新认证携带实际验证开始时间，后续授权码兑换不能把旧证明的认证时间刷新成兑换时间。撤销记录取最大截止时间，重复/乱序保存不能恢复旧会话。
- 沿用现有数据库备份和恢复，不新增数据库、注册模式、env key、证书或身份密钥。

## 发布与验收

同步完整代码后，先按原流程部署 **mx-launcher（包含 Auth 和 BFF）**，再部署 **mx-insight-hub**，保持原部署参数、网络、数据库和密钥档案。已经完成文档 41 登记的环境不需要重新执行 `identity public`。所有 Auth/Launcher/Hub 副本更新完成后才验收新的撤销语义；混合旧版本期间不能保证全链路遵守新撤销记录。回退到不识别这些记录的旧版本也不能承诺保留撤销效果。

验收至少覆盖：

1. 原账号、密码和飞书入口继续使用原 userId，Hub 使用原 member/tenant；MX-H2I 已有连接保持，新登录和新连接正常。
2. 两个隔离浏览器登录同一账号，在会话页退出其中一个；被撤销浏览器的受保护写请求拒绝，另一个继续可用。
3. 全局退出后 Launcher 旧请求拒绝、Hub 写请求拒绝、读缓存到期后拒绝；重新登录成功，租户和余额不变化。
4. 用现有入口改密后旧 Web 会话拒绝，新密码正常；单独编辑资料不会批量退出。
5. Auth/Launcher/Hub 重启后旧会话不复活；未退出的其他账号和原客户端网络不受网页撤销影响。

本地证据：临时真实 PostgreSQL、真实 HTTPS/OIDC、Launcher BFF、Hub SSO、Chrome 双浏览器/桌面/390px 窄屏。回归覆盖旧密码/飞书 SDK、ProductNetwork 隔离、lease 用户身份、原 member/tenant、跨 issuer、旧 Cookie、CSRF/越权、幂等撤销、重启、改密事务故障回滚与并发密码验证。线上网络与真实飞书仍需目标环境验收，不能用本地测试替代。

### 为什么有企业邀请

企业邀请是**加入指定 Hub 租户**的成员授权流程。例如公司 A 的 owner 邀请同事以只读角色加入 A；同事使用自己的原 MX 账号接受，Hub 给原 member 增加 A 的 membership，不另建密码、不自动获得公司 B 的数据。邀请固定租户、角色、接收约束和截止时间，接受时重新检查邀请人权限、租户状态及是否重复接受。

注册邀请码控制「谁能新建 MX 账号」，企业邀请控制「哪个已有/新账号可以加入哪个团队」，两者可以独立使用。企业邀请不是 SSO 的前置条件。当前由平台管理员配置租户成员也能正常使用；只有需要客户自助邀请同事、限定角色、查看接受状态及撤回未接受邀请时，才有必要建设该流程。

后续实施更新（2026-10-04）：一次性企业邀请、受邀注册免第二码、显式接受及自动租户绑定已完成本地实现，见 [43](43-hub-enterprise-invitations.md)。采用管理员自行分享的持有者链接，尚无指定邮箱/手机号核验或邮件/短信投递；普通 Hub admin 的权限不扩大，未部署生产。
