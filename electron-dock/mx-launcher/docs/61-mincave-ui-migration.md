# MinCave UI 迁移方案

将 `demos/mx-h2i` 的客户端界面对齐到 `MinCave-ui/MinCave`，采用原型的登录页、浅色侧栏、员工工作台、应用卡片和弹窗设计，继续由现有 Electron 主进程承载身份、网络、更新和系统操作。建议分阶段引入 React 渲染层，仅迁移当前客户端已有功能。原型中缺少真实数据来源或可执行链路的展示与操作，本次直接移除，不列为补开发任务。

当前两者不是可以直接覆盖的同构项目。原型的身份、网络、权限和管理数据主要由浏览器内的演示状态驱动；现有客户端则有真实的连接恢复、系统授权、飞书 OAuth、插件运行和 Release Center 更新流程。迁移复用原型的布局、颜色、组件和交互样式，为现有真实能力建立页面和状态映射。数据与功能范围以当前源码为准，不按原型补造业务能力。

### 本次迁移范围

采用“现有功能换 UI”的范围：只有当前客户端已具备真实状态来源和执行链路的功能才进入迁移。仅有类型、服务端模块、目录记录、mock 数据或“即将推出”按钮，不视为客户端已经实现。

- 有真实字段和动作：迁移对应展示及交互。
- 只有现有只读字段：可以展示真实值，不增加原型中的管理或授权操作。
- 无数据来源或无执行链路：移除整个展示区域及入口，不留“待接入”、固定数字或无效按钮。
- 已实现功能在加载、离线或失败时：保留必要的状态及重试操作，不展示原型之外的解释性提示；不把临时无数据误判为未实现。
- 本次不新增业务 API，不为原型补齐权限模型、网关切换、Web 应用启动或管理后台。构建、窗口和状态适配属于 UI 迁移工作。

| 原型展示或操作 | 本次处理 | 依据 |
| --- | --- | --- |
| 欢迎姓名 | 保留真实姓名 | `identity.displayName` |
| 飞书按钮点击后的登录流程 | 保留项目现有流程，不对齐原型 | 继续使用现有 OAuth；不出现演示员工选择弹窗 |
| 入职日期、在职天数、部门、员工／管理员标签 | 移除 | 当前客户端没有完整可信的资料读取链路 |
| 通知铃铛、未读红点、通知弹窗 | 移除 | 没有真实通知中心链路 |
| 办公网络状态及连接恢复操作 | 保留 | 现有 connection、networkOperation 与 IPC |
| 首页办公网络延迟 | 移除指标及单位 | 没有已确认的同义实时指标，不能借用 H2O 节点延迟 |
| 今日流量、月度用量及对应趋势图 | 不展示，移除卡片、图表及时间筛选 | 现有中继快照与代理内核计数不等于完整日／月累计用量 |
| H2O 已有上传总量、下载总量 | 保留在 H2O 页面 | 使用现有代理内核计数，不标注为今日、本月或全网用量 |
| 城市网关列表、选择及切换 | 移除 | 没有对应的网关目录与切换命令 |
| Delta、Nightall、Hub、Sandbox 固定四卡 | 移除固定数据 | 原型演示记录不代表已实现可用入口 |
| Luo 及其他仅“即将推出”的应用 | 移除占位卡片 | 当前 `appPrimaryAction` 无真实启动动作 |
| AppCenter、H2O 及其已有管理功能 | 保留 | 已有安装、启用、启动及管理链路 |
| 当前设备标识及实际租约 IP | 保留真实字段 | installation、connection；字段不存在时隐藏相应行 |
| “设备已授权”、固定设备名和固定 IP | 移除 | 不能从安装身份推导授权结论，不能沿用演示值 |
| 原型内嵌管理台及总览指标、图表、部门策略等 | 移除页面与切换器 | 未接入当前客户端，服务端基础不等于页面已实现 |
| 现有外部管理入口 | 保留 | 复用 `openAdmin`，沿用现有管理端鉴权 |
| 独立退出登录、断网后保留会话 | 移除原型行为 | 当前没有独立 logout，保留既有 disconnect 语义 |
| 真实版本更新、进度、安装包及 ASAR 状态 | 保留 | 现有 Release Center 与 updater |
| 取消更新下载、模拟安装重启、演示权限拦截 | 移除 | 无对应取消 IPC；其余是原型模拟逻辑 |

## 3 页面与功能迁移清单

### 登录页

视觉目标采用 `pages/Login.tsx`：小蛇及轨道主视觉、标题“MinCave，探索从这里开始”、副标题“企业内网，统一访问。”、蓝紫渐变飞书按钮。登录页仅对齐这些视觉元素，飞书按钮点击后的登录流程以当前项目为准，不对齐原型的演示员工选择。

点击“使用飞书登录”后，直接调用现有 `startFeishuLogin`，继续由系统浏览器完成真实授权，再按现有回调、身份交换与网络连接流程返回客户端。等待、失败、拒绝、超时、取消及已有连接保留行为均沿用当前实现。不引入原型的成员列表、演示身份弹窗、默认演示账号或选择员工后直接进入工作台的逻辑。

| 当前入口或状态 | 迁移后的呈现 | 接入方式 |
| --- | --- | --- |
| 飞书登录 | 主按钮，显示等待浏览器授权、交换身份、建立连接等阶段 | `startFeishuLogin`、`authFlow`、`cancelFeishuLogin` |
| 密码登录 | 新界面不展示入口，底层能力与旧界面保持兼容 | `loginEmployee`；保留账号历史，不保存密码 |
| 匿名连接 | 按产品策略放入主入口、高级入口或隐藏 | 保留 `anonymousUiVisibility` 与 `anonymousEnrollmentPolicy` |
| 登录失败或拒绝 | 登录卡片内的明确错误与重试 | 使用真实 `feedback` 和 `authFlow` |
| 已认证但网络降级 | 进入工作台显示修复状态，避免重复登录表单 | 复用 retained employee 判断 |

飞书授权继续由主进程打开系统浏览器，保留 loopback、state、PKCE 和服务端交换流程。视觉改版无需改变这条链路。

### 员工工作台与侧栏

迁移 `Shell.tsx` 和 `Portal.tsx` 的整体布局：左侧工作台、当前设备，左下账号菜单；右侧欢迎区、连接条和已有应用。移除原型的员工／管理控制台切换器、通知入口、入职天数与部门／角色标签，删除后让内容自然上移，不保留空白占位。

工作台及账号菜单规则如下：

- 姓名使用现有 `identity.displayName`；不使用原型成员表补默认姓名或资料。
- 应用只列已有可执行入口，数量与分类由真实条目计算；不凑四张卡片。
- 账号菜单保留设置、真实版本更新及现有外部管理入口。原型的独立“退出登录”、演示更新、演示权限项移除。
- 网络条保留“断开连接”，沿用现有认证结束语义；不再新增一个名称不同但行为相同的退出动作。
- 原型已有的搜索和网格／列表属于展示逻辑，可以应用于已有真实条目，不要求新增后端能力。

### 网络连接条

首页只显示“Minsight办公网络”、连接状态及连接或断开操作。移除延迟数值、`ms` 单位及对应分隔线；现有网关或 IP 的真实信息按需要放入设置或设备详情。原型只有 `connected` 布尔值；新 UI 必须保留当前客户端的完整状态。

| 真实状态或条件 | 连接条文案建议 | 允许操作与约束 |
| --- | --- | --- |
| 初始加载 | 正在读取客户端状态 | 先等待 `getState`，不使用默认已连接 |
| `idle` | 未连接 | 员工认证连接；匿名入口遵从产品策略 |
| `connecting` 或前台操作运行中 | 正在连接或修复 | 显示阶段进度，取消独立可用，阻止冲突操作 |
| `lease-only` | 连接未完成，租约已保留 | 显示授权或恢复引导，不能显示可访问 |
| `tunnel-only` | 网络需要修复 | 保留身份，提供修复和断开 |
| `server-unavailable` | 内网服务暂不可达 | 显示重试或修复，不清空保留身份 |
| `network-unavailable` | 当前网络不可用 | 保留连接状态 |
| `forbidden` 或应用准入被拒绝 | 当前账号无访问权限 | 显示实际拒绝原因；不循环触发重连 |
| `networkOperation.status = paused` | 后续恢复已停止 | 显式重试才恢复；不等同断开 |
| `connected` | 已连接 | 依现有健康和诊断结论启用资源操作 |
| 断开操作尚未完成 | 正在断开或清理未完成 | 等待主进程确认，不能提前切成未连接 |

“取消本次连接”调用 `cancelNetworkOperation`，不能调用 `disconnect`。保留已有的操作 ID、互斥和旧请求结果失效机制，防止取消后旧请求覆盖新状态。系统权限弹窗已打开时，保留当前平台的说明和取消语义；后台检查不因 UI 重渲染触发新的授权。

本次不迁移办公网络延迟指标，不留“— ms”占位。H2O 已有的节点或订阅相关延迟保留在其原有上下文中，不挪作首页办公网络指标。

### 应用目录

沿用原型的卡片外观、名称搜索、网格与列表切换、居中布局和空状态。分类使用当前 `appCenterCategories()` 的“全部应用、网络工具、工具箱、测试工具、可更新”等已有语义，只展示有实际条目的分类；不照搬“中台应用／测试环境”。

当前 `appCatalog()` 包含 H2O、动态 embed 应用、Diagnostics、Luo 等记录，但“有目录记录”不代表有可执行功能。迁移时按实际动作过滤：

| 条目或能力 | 本次处理 |
| --- | --- |
| AppCenter | 保留安装和进入已有目录的入口 |
| H2O | 保留安装、启用、启动及管理入口，接现有专用 IPC |
| H2O 代理模式、节点、订阅、规则、TUN、测试和日志 | 保留已有功能，可先进入兼容页面再换肤 |
| Diagnostics 中已实现的检查更新 | 统一收进版本设置或诊断入口，不复制合成的应用版本、安装等占位元数据 |
| Luo、动态应用等仅返回 `select-app`／“即将推出”的项 | 从用户目录移除卡片；不因为有 manifest 或 entrypoint 就新增启动能力 |
| Delta、Nightall、Hub、Sandbox | 不迁入原型的固定卡片、空 URL 和模拟访问弹窗 |
| 通用 Web 应用打开、通用插件启动 | 本次不新增，无真实启动链路的条目不展示 |

卡片状态来自现有 installed、enabled、runtimeState 和实际动作结果，不统一写“可访问／打开”。网络未就绪时按既有逻辑禁用操作，保留真实状态与可用动作；不增加原型之外的原因说明或错误提示条。应用计数、分类计数均基于过滤后的真实条目。

四列是宽屏布局上限。按实际数量展示，不添加 Sandbox 或其他示例来补齐。

### 流量展示

本次不展示原型中的“今日流量”“月度用量”，同时移除对应的上传／下载日月汇总、趋势图、时间范围筛选、单位和占位区域，不通过中继快照或 H2O 内核计数推算这些指标。

H2O 页面仅保留当前已经实现的“上传总量”“下载总量”，沿用真实代理内核计数及既有更新逻辑，不扩展为日／月累计统计，也不将其放到首页作为办公网络或全网使用量。服务端流量采集与历史记录保持现状，不因移除展示而删除。

### 设备与设置

设备页仅使用 `installation` 的安全字段与 `connection.localIp`，显示当前安装／设备标识、实际设备标签及实际租约 IP。缺少可选字段时隐藏对应行；断网时可显示现有网络状态，但不展示原型固定的 `10.8.0.24` 或“已授权”结论。不新增设备授权、解绑或设备列表管理。

设置分为普通设置与高级诊断。普通设置显示真实连接状态、协议、身份来源和版本更新；高级诊断保留运行配置、系统网络修复、Windows 残留声明清理、日志目录、诊断包与安装身份。状态备份读取／恢复已有 IPC，但原客户端未提供操作 UI，本次不新增入口，保留接口不变。

原型的城市网关名称、地区、延迟、维护状态、选择弹窗及“切换网关”按钮全部移除。已有 Bootstrap、Domestic、Internal、路由偏好等设置仍使用原字段及保存行为，不将其改造成城市选择器。

### 管理入口

本次移除 `Admin.tsx` 内嵌页面、员工／管理端切换器，以及原型中的总览数字、流量图、网络拓扑、安全概况、成员编辑、节点维护、部门策略、日志 CSV 和飞书配置表单。即使仓库服务端有相关基础，也不将其视为当前客户端已经接入的功能，不在本次迁移中补开发。

保留既有 `openAdmin` 外部入口，由现有 `/admin/` 页面继续执行原有身份与权限校验。此次不改外部管理端，不导入原型 `canAccess`、本地员工／管理员角色或 Workspace 管理数据。

## 4 登录态与网络态的关键差异

当前 `disconnect` 在确认系统网络清理和 ownership 释放后，将连接设为 idle 并清空 `runtime.auth`。原型的断开只改变 `connected`，保留已登录的 `member`。preload 也没有独立 `logout` 方法。

本次保持当前 `disconnect` 的真实语义：成功后回到登录态；按用户要求不额外增加断开认证说明。断开失败或用户取消系统授权时，按主进程返回值保留身份和连接，不先跳转登录页。

原型独立“退出登录”和“断开后继续停留工作台”的行为本次移除，不新增 logout 命令，也不拆分会话生命周期。“重置本地网络身份”保留原有高级操作语义，不能当作退出按钮使用。

## 5 更新弹窗迁移

保留原型 `UpdateNotice.tsx` 的版本信息、说明、步骤、进度、失败重试和完成态外观。更新源仍为现有 Release Center，版本号从运行版本读取，避免导入原型 `1.0.0` 或演示 `1.1.0`。

| 现有状态或属性 | 新 UI 表达 | 动作 |
| --- | --- | --- |
| 未连接、`needs-connection` | 连接办公网络后检查 | 保持连接门禁，不轮询原型 `release.json` |
| `up-to-date` | 已是最新版本 | 设置内可手动检查 |
| `update-available` | 发现新版本 | 依据 deliveryMode 弹窗、红点或静默处理 |
| `blocked` | 更新暂不可用 | 不提供绕过 Gate 的安装操作 |
| `downloading` | 下载与校验进度 | 使用 `downloadProgress`，总量未知时不伪造百分比 |
| `download-failed`、`failed` | 失败原因及重试 | 复用真实更新动作 |
| `ready-to-install` | 安装包已就绪 | “打开安装包”；失败时可重试或打开目录 |
| `installer-opened` | 安装器已打开 | 保留真实安装阶段，不宣称已经安装成功 |
| `staged` | ASAR 已暂存 | 按 restartRequired、restartPrompt 和策略提供重新启动动作 |

首页连接条移除更新按钮，设置内保留版本、检查更新、历史与回滚入口。保留 `silent-download-next-start`、`manual-download`、`prompt-download-restart` 的区别，以及当前连接后检查机制。

原型支持下载取消，但当前 preload 没有更新下载取消接口。本次移除下载取消按钮，仅在现有状态允许时提供关闭弹窗或稍后处理；关闭弹窗不表示停止下载。不新增取消下载契约，网络操作的 cancel 不能复用于下载取消。

不迁入原型的演示 ZIP、浏览器保存二进制流程、定时模拟安装或重启，也不以改变前端状态作为更新成功证据。保留现有制品校验、ASAR bootstrap、安装器和失败回退流程。

## 6 技术实施方案

### 渲染层选型

建议采用 React 与 TypeScript 迁移渲染层，复用原型组件层次，保留现有 CommonJS 主进程与 preload。相较把原型 JSX 手工改写成模板字符串，这样更适合工作台和弹窗维护。实施时不整体替换原型 `package.json`，Electron、原生依赖、工作区依赖和发布脚本继续按现有客户端管理。

新增一个独立的渲染源码目录，以下名称为建议：

```text
demos/mx-h2i/
  ui/
    main.tsx
    App.tsx
    bridge/              # window.mxH2i 类型及调用封装
    state/               # runtime 订阅、命令执行、ViewModel
    components/          # Shell、原生窗口控件、状态条、弹窗
    pages/               # Login、Workbench、Devices、Settings
    styles/              # token、布局和组件样式
    assets/              # 小蛇及应用图标
  src/
    main.cjs             # 保留 ASAR 选择入口
    main-runtime.cjs     # 保留业务运行时，适配窗口与渲染入口
    preload.cjs          # 复用现有白名单桥接，不新增业务方法
    renderer-dist/       # 建议的 Vite 构建输出
    index.html           # 过渡期旧渲染入口
    renderer.js          # 过渡期旧界面与兼容能力
```

主链为 `React 页面 → bridge 命令 → preload 白名单 IPC → main-runtime → 既有平台与网络能力`；状态从 `visibleRuntime → onState → UI store → ViewModel → 页面` 返回。UI 自己只保存搜索、分类、布局、菜单等展示状态，身份、连接、更新和权限结果以主进程及服务端为准。

1. 在当前客户端包中新增 `build:ui`，输出建议放到 `src/renderer-dist`，Vite 使用适合 `file://` 的相对资源基路径。将原型 `/snake.svg` 等绝对路径改为打包可解析的导入或相对路径。

6. 通过真实打包运行验证后，沿用现有 Release Center 灰度。保留旧渲染入口和切换开关直到灰度验收完成；回退必须能读取原有配置，不依赖演示 localStorage。

## 15 复用当前 H2I 登录，免二次验证（最新）

用户明确要求管理控制台直接复用当前 H2I 登录。客户端已移除验证窗口及验证按钮，主进程自动以当前登录的 Bearer 向固定的 HTTPS 管理入口建立会话；不会复用另一账号或 Ops Token 的浏览器 Cookie，不接受服务器响应指向其他域名。退出或切换账号期间的旧响应被丢弃。原飞书 OAuth、系统网络授权及网络连接流程不变。

服务端新增 `POST /auth/admin/desktop-session`，与原 SSO 同样经过管理入口、来源和频率限制。通过持久化 Token 校验 `mx-sdk` audience、`mx-h2i` appId、用户类型、`auth.read`、原始签发时间及到期时间，并读取当前用户的 `mx-admin` 角色；不采信请求体的 userId、角色或 authTime，不赋予普通员工管理权限。会话只保存 Token 摘要，且绑定同一个 Token；每次访问再次校验原 Token、账号状态、应用禁用和会话撤销。管理 BFF、CSRF、审计和当前角色校验沿用原实现。

`GET /auth/admin/session` 新增能力字段 `desktopLogin: h2i-v1`；桌面会话返回 `authMethod: h2i-desktop`。Token introspection 增加来自已核验持久化记录的 appId／issuedAt。管理会话到期不超过原 Token 到期，不通过换取会话刷新原认证时间。原有写操作要求最近 5 分钟登录的规则保留；超时需重新登录 H2I，不弹出独立管理登录。原浏览器 SSO、Ops 应急入口和旧客户端不变。

发布顺序：先更新 Launcher 管理服务，再使用新客户端。无需数据库迁移、新增凭据或配置。旧服务没有能力字段时，新客户端停止管理请求并显示“管理服务需更新后才能复用当前登录”，不静默回退到二次登录或模拟数据。服务端生产改动范围为 `server/src/admin-sso/middleware.ts`、`server/src/store/domain.ts`、`server/src/types.ts`，附对应测试。回退服务时原浏览器管理入口仍可用，新客户端的管理页会显示需更新状态；员工工作台不依赖新增接口。

验证结果（本地）：完整 demo `pnpm check` 通过，含 32 项 UI／桥接测试和既有网络、飞书、更新检查；server `pnpm typecheck`、`pnpm build` 通过；4 项无监听端口的真实 middleware 桌面会话测试通过；16 项既有飞书／密码认证测试通过。完整 HTTP SSO 集成套件因执行沙箱禁止监听 `127.0.0.1`（EPERM）未能运行，Postgres 集成测试因未配置测试数据库跳过，不将其记为通过。

## 18 设备页与账号设备历史（最新）

按追加要求，设备页从本机技术信息列表改为原型横向卡片，并扩展为当前登录账号的全部可查设备历史。展示设备名称、当前／历史标记、真实本机连接状态及虚拟地址；隐藏设备标识、安装标识、站点标识。当前设备优先，历史设备按最近使用排序。历史租约不代表在线，历史卡片只显示“已绑定”和“最近虚拟地址”。

原有 `POST /internal/v1/mincave/session` 可附带本机设备元数据，旧客户端空请求兼容；新增本人专用 `GET /internal/v1/mincave/devices`。服务端从已验证的飞书 Bearer 确定账号，校验明悉科技企业及当前 MinCave 使用权限，不接受客户端指定账号。两种角色均可读本人设备；员工不因此获得管理控制台权限。主进程保存凭据并处理接口，渲染层仅接收展示数据；账号切换和迟到响应隔离。

设备记录保存在既有通用表 `mincave-device`，按账号＋稳定设备 ID 去重并保留首次／最近使用时间。会话登记时合并当前账号仍可查到的员工租约历史（含过期、释放），持久保存后不依赖旧租约继续存在。旧数据中没有记录、已覆盖或已删除的登录历史不能补造。重装生成新设备身份时可能出现新的历史卡片。

发布顺序：后端与精确网关路由 → 客户端；无需新增 SQL 表或配置项。未部署时不能直接读取线上历史。实现未改动原飞书 OAuth、租约申请、系统网络授权及隧道连接流程。
