# 十槽调度实验室与指令级任务

2026-10-10 本地实现；尚未部署、没有调用服务器或手机。用户截图中的 `docker exec / adb am start` 仅作为启动 App 的能力参考，没有执行。改动范围只有 mx-device。

## 本轮可直接体验

登录默认进入「调度实验室」。点击「开始 20 任务演示」创建或复用一座十槽模拟机架，同时提交 5 个大循环、15 个小任务。初始 5 个大循环为小红书搜索第 1–10 页、微博连续搜索 5 次；小任务包含微博列表/搜索/点赞、小红书列表/详情/OCR。机架限额、暂停、排空与既有冷却仍有效。

这次演示有意给部分任务指定插槽，以便稳定复现同槽排队、插入上限和上下文恢复；不是吞吐最优配置。内置场景固定使用迁移中的 v1 定义，便于重复比较；新保存的版本由「提交定义任务」选择，默认显示最新版本。该表单默认由中心选择设备，也可指定插槽。系统没有把多个外部请求折叠成一份成功结果：每个请求保留自己的 Job、幂等键与回执；连续执行和定义中的重复指令构成批次。跨请求结果缓存/自动合并尚未实现。

- 十槽卡片：当前 App、指令码、大循环进度、已插入次数、分别冷却的截止时间。
- 时间线：实心段代表实际记录的模拟指令起止时间，颜色区分 App；细虚线代表保存过的随机冷却区间。点击查看本任务的完整证据。
- 插槽详情：累计指令用时、任务窗口计数、随机冷却历史、近期指令流水，以及等待原因。
- 循环策略：插入个数、插入预算、统计窗口、大小循环阈值、随机冷却上下限、每条模拟指令时长。
- 定义编辑：从模板复制，用已登记指令组合新流程；同代码保存为新版本，已提交任务不受影响。

任务运行中可暂停新领取；保留中的大任务会继续到结束，不再插入新小任务。重新启用需等设备空闲。整机间隔和 App 固定冷却仍可在既有机架/设备界面配置。

## 调度与所有权

`Job → Attempt → Command → Receipt` 是四层记录。Job 在提交时冻结定义版本、展开后的指令及参数；Attempt 记录一次设备分配；每个 Command 有唯一 ID、任务/尝试/设备/App 身份、步骤、页码与实际时间；Receipt 是执行结果。大循环不等于数据库长事务：每次领取与回执各用短事务，等待和执行在事务外。

同槽最多一个执行中的指令、一个 running Attempt、一个 running/yielded 大循环。大循环到达已验证的读操作检查点后，Attempt 可变成 `yielded`，Job 仍为 `running`，Device 仍被该大循环保留。其他 worker 可以继续同一 Attempt，每次恢复递增执行代次；旧代次不能派发后续指令。不能把 yielded 当作空闲手机、普通重试或任务完成。

小任务插入要同时满足：定义声明可恢复、处在安全读检查点、没有在途执行、设备未暂停/排空/预留、任务设备与 App 匹配、App 和整机冷却已过、次数和累计预算允许。未绑定小任务有兼容空闲插槽时，优先直接分配；需要插入时，候选沿用优先级、等待提升与预计耗时排序。子 Attempt 保存 `parentAttemptId`。

默认每个大任务最多插入 **3 个**小任务（界面允许 0–5），累计插入预算 **15 秒**。准入成本取「命令默认预计用时之和」与「命令数 × 当前模拟时长」较大值，并预留一次恢复指令时间；同时检查已经实际消耗的插入等待时间。已经执行的小任务不会被硬中断；调度延迟和必须遵守的 App 冷却可能让实际延迟超出预算，所以预算是下一次插入的准入约束，不是强制完成 SLA。达到上限后继续父任务，剩余小任务等大循环结束。

跨 App 或同 App 插入后，父任务先执行 `session.restore` 并验证保存的步骤/App，再从已确认的页码继续。这里是模拟器可验证的恢复能力；真实 Mobile-Agent/旧 PoC 没有因此获得恢复能力。大任务已领取的插入策略与模拟时长使用快照；新领取任务使用最新策略。

## 冷却与数据库

同一手机一个物理执行槽，App/固定账号各自记账。满足整机限制时，小红书冷却不会直接阻止微博。一个大任务完成记一次大循环，每个插入的小任务完成记一次小循环，内部指令不冒充独立任务。

默认在 60 秒统计窗口内，某 App 累计完成 3 个小循环或 1 个大循环，抽取 **4–8 秒**随机冷却。抽样只在完成事务中发生一次，保存实际 duration、until、触发计数和策略版本；刷新、读取、重启不会重抽。达到阈值后清空这一轮 burst 计数，历史计数仍保留；这是「窗口内触发后开始下一批」语义，不是持续滑动窗口计数不清零。固定 App 冷却与随机冷却取较晚截止时间。降低配置不会缩短已经记录的冷却。

领取与完成依据 PG 数据库时钟及同模式短事务锁。PostgreSQL 是任务、占用、冷却的事实来源；未引入 Redis 倒计时。以后 Redis 可用于提示/唤醒，不能仅凭 key 不存在就授予设备执行权。

005 迁移新增 `task_definitions`、`loop_policies`、`execution_commands`，种入 8 个 v1 定义，并增加每设备单指令、每设备单大循环、每任务单活动 Attempt、机架槽位唯一索引。既有 001–004 迁移保持不变。

## 指令与完成条件

| 指令 | 本地模拟完成条件 | 真机接入情况 |
| --- | --- | --- |
| `app.open` | 回执中的前台 App 匹配 | 旧服务有 open app 动作；独占与回执待接入 |
| `weibo.list/search`、`xhs.list/search/next` | 身份/关键词/页码一致、非空结构化结果 | 微博待适配；小红书旧 PoC 已有独立接口，尚未用于新组合流程 |
| `weibo.like` | 目标一致且 liked=true | 仅合成演示；旧服务动作不能代替目标/结果核验 |
| `xhs.note.detail`、`xhs.get_note_detail.ocr` | 目标一致、完整标志和非空正文 | 仅合成正文；截图能力不等于 OCR/完整正文取数 |
| `session.home` | 明确 home 回执 | 旧服务有 home 动作，收尾核验未接入 |
| `session.back` | 明确 backed 回执 | 旧服务有 back 动作，页面状态核验未接入 |
| `session.restore` | 保存步骤及 App 匹配 | 内部指令；仅模拟器，不能由用户任意插入 |

所有回执还校验 commandId/jobId/attemptId/deviceId/appId/code/stepIndex 以及执行停止标志。只有全部展开步骤验收后 Job 才成功；重复成功回执不重复累加冷却。运行指令的回执未知、身份错误或租约过期时，子任务与保留中的父任务一并未知并隔离设备；迟到证据保留，但不自动复活任务。仅在已确认的 yielded 检查点可直接恢复；执行中崩溃不伪装为安全检查点。

定义支持同 App 的有限顺序组合（1–12 组，每组 1–10 次；小循环最多 4 条，大循环最多 30 条），不执行任意 Shell/URL/脚本。第一条必须是 app.open，下一页必须有前置搜索。参数目前是 keyword/target；支持「给定目标的搜索＋详情/OCR」，**尚不支持从搜索结果动态逐条展开详情、任意分支/DAG、每组不同关键词、可编程完成表达式或自动跨请求合并**。home 是否需要执行由定义显式决定。更严格的条数、去重、正文覆盖率/滚动结束证据是下一步完成契约，不以模拟 complete 标志证明真实正文完整。

## 工作台调试与手机展示增量

- **设备工作台 → Adapter 调试**：指令目录覆盖打开 App、返回、Home、小红书/微博列表与搜索、小红书下一页/详情/OCR，以及模拟微博点赞。真实模式集中提供单次截图、状态、旧 PoC 连接检查；只读观察设备的 PoC 按钮不可用，真实控制指令只展示待接入能力。
- **模拟试运行**：选择设备、App、指令、关键词/目标后显式提交。准备步骤可见，自动先打开 App；下一页会先搜索。走普通小循环 Job/Attempt/Command，遵守全部占用与节奏规则，不抢占当前指令。点击试运行记录查看完整回执；同一幂等键可安全查询原结果。试运行会计入真实的模拟任务/冷却统计，不能用调试入口绕过调度。
- **编辑为任务定义**：把当前准备与执行步骤送入同一个版本化定义编辑器，可增删、重复或增加返回/Home 后保存。试运行自身不污染定义目录；只有保存才生成新版本。定义目前仍是有限的同 App 顺序组合，动态结果引用及自定义业务验收是后续工作。
- **调度实验室 → 点击插槽**：打开手机展示层；左侧显示最近已确认回执生成的合成投影，右侧显示当前指令、已执行时间、父大循环进度、已插入小任务与累计等待、各 App 冷却/上次处理、指令流水与匹配的排队任务。运行中指令与最近确认画面分别展示；打开/关闭仅读取本中心快照，不启动截图或手机操作。
- 弹层可跳转所选设备工作台，指令可打开任务证据；关闭按钮/Escape 恢复原插槽焦点。窄屏改为上下排列。手机投影明确标记「合成投影 · 非真实截图」，OCR 文本/点赞均为模拟结果。

## Mobile-Agent 与下一步

此前源码核实见 [Mobile-Agent 能力](mobile-agent-source-review.md) 与 [完成契约](execution-completion-contract-2026-10-10.md)。旧系统可以启动不同 App、组织逐设备任务，但已核实的快照没有提供本轮所需的持久 App 独立预算、可恢复检查点插入、业务完成证据和设备侧 owner/epoch 契约。保留 mx-device 作为调度与流程验收中心，Mobile-Agent/adapter 负责设备执行的分工有实际必要。

下一步优先完成：

1. 定义的输入/输出引用及业务验收参数：搜索至少 N 条、不进详情；或消费搜索结果逐条详情/OCR，正文完整且去重。
2. 独立 adapter 契约测试：能力发现、稳定命令 ID、执行查询、停止/取消确认、同机唯一入口、恢复能力显式声明；先 mock，后获准真机。
3. 把 App 启动、搜索、详情、收尾逐项映射到可核验的能力；不把任意 ADB 拼接开放给调用者。
4. 观察真实 workload 后再做调用方公平性/配额、账号或出口预算、历史归档、负载与故障切换验收。当前仍为有界实验调度器，不是已验收高并发 HA；冷却也不能保证账号不会触发平台风控。
