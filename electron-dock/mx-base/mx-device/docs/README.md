## 一分钟结论

- 最新本地增量：模拟机架已增加独立虚拟时钟实验与可选自适应池策略；软放置可重算，实际领取仍重新核验单设备互斥、冷却和资源约束。默认使用相同负载的 spread 作为对照，没有“对任意流量最优”的承诺。
- 产品目标是稳定、高可用、高性能的手机机架/集群基础设施，小红书采集是首个参考业务；8787 的设备池等通用产品能力可以统一到 mx-device，但当前实现仍是单机实验版，不是已验收 HA。
- 最新定位：任务调度是中心核心，完整模拟不以手机/adapter 为前置。mx-device 负责接单、资源与节奏、流程完成判定；执行端负责设备操作和结构化证据。已补任务间冷却、历史/耗时排序，以及有限顺序组合、指令回执与十槽实验室；已补有界前序结果引用，下一步完善业务验收和真实控制。
- 最新冷却设计：同一手机可顺序执行不同 App，物理设备保持单写槽，App/账号/操作类别分别记账并叠加整机限制。先用 PostgreSQL 持久截止时间并在领取事务中核验，不以 Redis key 过期作为执行授权；本轮已实现 App/固定账号和整机两层任务间冷却，操作类别与更广预算仍是后续设计，见 [增量说明](app-pacing-2026-10-10.md)。
- 项目路径：`electron-dock/mx-base/mx-device`，独立 Docker Compose、独立 PostgreSQL、管理端口 18891；不是 Hub 内置模块，也不是 mx-rig 的部署前置依赖。
- 服务器 `mobile-agent` 是一个容器，发布多个端口。8765 是内嵌的侵权处置业务子服务；8787 是设备/业务管理 HTTP 服务；8788 是视频；宿主机 18081 映射容器 18082，接入手机上的旧 PoC，**不是仅凭端口就能认定的另一 mobile-agent 实例**。
- 通用手机观察/控制不以 PoC、VPN 或旧侵权业务为基础依赖。现有 PoC 搜索/详情取数则是另一条可选能力，截图/点击不能自动替代结构化 JSON。
- 当前 mx-device 已有真实截图、过滤后的设备/runner 报告、模拟调度和旧 PoC 兼容；真实点击、全局独占抢占、复位、自动跨机重试尚未开放。
- 前阶段已实现且用户反馈已部署：独立机架总览与任务调度页、持久机架/主机限额和排空、设备归属编辑、模拟任务机架/主机约束。当前分组仍是中心登记信息，不能当作可信硬件拓扑或 HA 证据。
- 冷却已支持配置，App 额外间隔初始为 0；旧搜索/详情表单仍分两次创建任务；新增模拟定义支持同一 Job 的有限顺序组合。旧 Mobile-Agent 已有逐设备队列/定时/批次/接力，但其导出执行框架主要据进程退出码判成功；不能据此认定具备完整资源池调度、业务完成证明或设备侧 fencing。
- 补充核实：旧脚本有自身完成条件，内部有 `on_finished` 回调，HTTP 可查 task 状态和采集明细；但未见可靠对外完成订阅，task 明细可能混合多次 run。中心需分别验证业务完成、执行停止、收尾和冷却，不能用“runner 空闲”或旧数据总条数代替本次任务成功。
- 手机 PoC 长期 `isBusy:true` 的根因仍未证实。手机曾被确认亮屏、未锁屏且能打开小红书，不得继续把锁屏当成已确认原因，也不得把旧 page=1 当作当前物理屏幕。
- 当前只允许适配原服务。不能为了方便演示重启手机、mobile-agent、ADB 或 VPN；不能影响 Hub、Launcher、MX-H2I 登录/联网。
- `/tmp` 源码是用户从服务器导出的不完整快照，不是已确认的开源 Git 仓库；路径与哈希见源码核实文档。它们可能被系统清理，不能视为永久档案。
