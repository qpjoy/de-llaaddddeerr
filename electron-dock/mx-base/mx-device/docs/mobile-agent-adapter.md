# Mobile-Agent 适配：观察先行，控制分层

本轮只更改 mx-device，不修改或重启现有 mobile-agent、手机、VPN、ADB、Hub、Launcher 或 mx-rig。源码审阅基于用户导出的 `mobile-agent-review.Tc1Yq5/web_server.py` 及 `mobile-agent-core.nweAZc/mobile-agent-core.tar.gz`；服务器是否与这份导出完全一致，仍需部署后只读验收。

## 当前这一台怎么接

在 mx-device 目录更新代码，沿用原命令：

```bash
TMPDIR=/data/tmp \
MX_DEVICE_BUILD_PROXY=http://127.0.0.1:7789 \
bash scripts/manage.sh deploy
```

仅部署本中心，自动应用 `002_latest_frames.sql`（独立数据库新增最新截图表），保留原配置、任务与凭证；仍使用 Compose 管理端口 18891。无需给旧容器加端口、装软件或改转发。

1. 登录后切换「真实设备」，选原先登记的「外设手机 01」。不要重复登记同一手机。
2. 在「手机工作台 → 真实画面 → 配置画面连接」填写 `http://127.0.0.1:8787` 和 `8ad5ef10`，批准保存。执行器继续使用原来的 `mx-internal-server-worker`（以连接设置心跳为准）。
3. 点击「单次截图」，确认画面；再「开始观看」。若接口失败，检查执行器心跳和本机 8787 的连通性，不要重启 mobile-agent。
4. 对比「接口投影」：旧接口可以继续显示 busy/page=1，但真实截图可能显示首页。两者独立呈现，不将旧状态当成实时屏幕，不伪造清 busy。
5. 「停止观看」、切换设备/页面后不再发新截图请求；已经派发的一次请求可能继续完成。页面隐藏也暂停请求。保留最后画面，但超过 10 秒明确标为旧画面。

若没有登记过，添加设备选择 Mobile-Agent，只登记只读画面即可。此设备不能发送采集任务，也不会自动接管现有控制端。

## 已有服务到底支持什么

| 入口 | 导出源码行为 | 本轮适配 |
| --- | --- | --- |
| 8787 `/api/screen.png?device=序列号` | 对指定设备执行一次 screencap | 复用；低帧率、原比例、可放大 |
| 8787 `/api/screen.mjpeg` | multipart PNG 截图序列，不是实际 MJPEG 编码 | 暂不接，避免长连接和多观看者放大负载 |
| 8788 `/ws/video?device=序列号` | H.264 视频；断开清理包含 `pkill screenrecord` | 暂不接，避免影响其他录屏消费者 |
| 8787 `/api/devices/{serial}/action` | 点击/滑动/应用等动作，不检查 PoC busy，也不受中心租约约束 | 不调用；绕过 busy 不代表安全 |
| 宿主机 18081 PoC | 全局状态和分页会话，无设备选择参数 | 原适配保留；busy 仍阻止真实采集 |

屏幕使用低帧率 PNG 而非伪造小红书 UI。浏览器约每 2.2 秒请求一次，但完成冷却、执行器轮询和快照刷新会增加延时，不承诺 FPS。截图通过带认证的 mx-device 同源端点读取，浏览器不直连 8787/8788，不需要 WebCodecs 或视频解码。它不能证明已登录、任务正确结束或没有其他操作者。

## 预留、解除、复位与抢占

真实设备可「预留执行槽」：立即停止本中心新任务领取，等待本中心当前任务完成，再显示预留成功。另一窗口不能取得该会话；只有持有内存令牌的窗口可续期/解除。窗口离开后最多 60 秒到期，仍保持暂停；排队任务不清空，释放后也必须显式重新启用才会领取。

**这是本中心的调度锁，不是手机全局锁。** 旧页面、旧任务 runner、脚本和直接 ADB 都不识别这个令牌。旧服务缺少暂停整个任务池、外部所有权租约和 fencing token 校验；仅在 mx-device 增加锁，无法证明外部控制者已经停止。因此真实强制接管、复位、点击均在服务端禁止。截图读取可在 PoC busy 时进行，采集操作不能借此绕过 busy。

模拟设备可演示「申请模拟接管 → 等当前工作结束 → 模拟复位 → 解除」；也可强制抢占：撤销旧会话、递增执行代次、中断旧 Attempt，任务保留，6 秒后才允许重新领取。旧尝试/旧令牌不再生效，迟到结果只作为证据，不覆盖新结果。需要继续演示时显式启用设备；可选择另一个窗口观察锁冲突。

将来提供真实抢占必须先有统一写入口：每个宿主机设备代理校验租约/代次、支持安全点取消、报告执行回执，旧写入口经明确授权隔离或参与同一所有权协议。该工作涉及部署与旧控制链变更，本轮不实施，不能把模拟成功宣传为真机独占保证。

## 增加手机：端口还是设备控制

| 场景 | 身份与接入 | 当前范围 |
| --- | --- | --- |
| 同一宿主机、同一 Mobile-Agent、新增 USB 手机 | 同一个 8787 + 不同真实 ADB serial；每台独立设备记录 | 源码支持多设备；mx-device 可登记与观察，真实多机仍待服务器验收 |
| 同一宿主机、多个既有服务实例 | 各自现有端口（允许 8787–8797）+ serial | 只登记，不创建/改动旧实例 |
| 第二台宿主机/机架 | 新 workerId + 新宿主机本地服务 + serial | 模型和按 worker 派发已支持；远程 worker 的私网/TLS/凭证部署尚未一键提供 |
| 旧 18081 PoC 多手机采集 | 每个隔离 PoC 会话需要独立可验证入口 | 不能只填写新 serial 就复用一个全局分页接口；本轮不新建转发 |

不自动扫描网络/USB，不隐式调用旧服务 `/api/state`（它含完整配置）。当前只做人工登记和定向截图核验。增加第二台服务器时不要公开 18894 数据库或手机控制端口；需另行设计私网连接/受认证代理后再部署工作节点。当前 Compose 仍是单宿主机，不是完整机架集群。

## 隔离与数据边界

- API 的快照、列表、健康检查、缓存图片 GET 都不触发手机 I/O。显式 POST capture 只入库；所选宿主机 worker 领取后请求固定只读路径。
- 同设备多个观看者合并一个在途请求，完成后冷却至少 2 秒；同 worker 最多一项截图在途，避免观察挤爆执行器。不同 worker/设备身份隔离；手机 I/O 始终在数据库事务之外。
- 截图有 10 秒网络超时、6 MiB 上限、PNG 尺寸校验；请求 20 秒过期、配置版本变更或旧回执都不能覆盖当前画面。失败保留最后画面并标旧，不改变 PoC busy/enable 状态。
- 每设备数据库仅保留最新一张 PNG，配置改变后旧图不再可读；完整图片不进入事件或列表 JSON。旧字节可能仍存在于数据库/备份，不声称安全擦除；截图可能包含个人资料、消息等，按敏感数据保护独立数据库和备份。
- 当前数据库事务仍使用本实验中心的模式级串行锁，适合小规模演示；大量机架需细化行级领取、观察专用限流/存储、任务队列与容量验收，不将当前 64 设备保护上限当作吞吐保证。

## 验收边界

本地单元、假接口、浏览器固定截图与临时 PostgreSQL 验收只能证明适配和隔离逻辑，不等于服务器真机验收。服务器先完成单次截图，再短时间观看并停止；确认原服务、VPN、旧 PoC 状态没有被本中心重置。若只读路径不存在或序列号未识别，请保留失败证据，不运行恢复/重启命令。
