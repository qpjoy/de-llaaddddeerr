# 机架与调度：现状分析及本轮实现

日期：2026-10-10。范围仅 `electron-dock/mx-base/mx-device`。本轮基于仓库、交接文档和用户截图实施；未访问服务器，未修改、重启或调用现役 mobile-agent、ADB、USB、VPN、手机。截图所示服务器版本不等于下述本地新版本。

## 1. 为什么此前主要看到手机画面，看不到机架与调度

| 层面 | 核对出的原实现 | 缺口与本轮决定 |
| --- | --- | --- |
| 机架 / 主机 | `Device.rack/host` 两个字符串，设备卡按文字分组 | 增加独立总览，将层级、执行状态、心跳、领取限制放到同一页面 |
| 资源治理 | 每部设备的暂停、会话、隔离；每进程 4 个工作槽 | 增加持久机架/主机并发上限与排空，并纳入原子领取；不另建调度器 |
| 调度引擎 | 已有 Job / Attempt、优先级、等待提升、搜索依赖、冷却和未知隔离 | 复用原引擎，不把已有功能重新实现一份 |
| 任务展示 | 主要按入池时间展示，queued 的 reason 多为提交时固定文字 | 展示实时阻塞原因、等待时长、有效优先级与当前排序；依据与领取共用的条件计算 |
| 调度范围 | 真机必须指定设备，模拟可选具体设备或全池 | 模拟新增指定机架/宿主机，真机继续显式设备/账号绑定 |
| 拓扑维护 | 只在登记时输入分组，后续缺乏调整入口 | 增加暂停且空闲设备的中心名称/归属编辑，保留不可变设备 ID 与全部关联 |
| 历史证据 | 列表最近 100 条可能不含仍被排队任务引用的老来源 | 快照额外保留活动依赖与所有 running Attempt；完整结果仍按任务 ID 查询 |

因此，此前的主要问题是“已有底层调度没有形成清楚的资源管理与解释界面”，同时缺少分组级治理。真实截图、runner 报告是观察证据，不能直接转换成执行槽可用、物理独占或机架高可用证明。

## 2. 本轮可使用的功能

### 机架总览

登录后先看到当前模式的登记数、候选设备数、执行数、排队数、隔离数，以及机架 → 主机 → 手机层级。可按机架与设备状态筛选；点击手机进入现有工作台，保留截图、Mobile-Agent 状态、旧 PoC 通道与会话功能。

“候选设备”表示当前中心条件与执行器心跳条件通过，不是承诺可以同时开多少任务。比如机架剩余一个名额、两台空闲手机都可作为该名额的候选，候选数为 2；最终领取由事务内限额决定。Worker 心跳 10 秒内且无错误才显示新鲜；它证明执行器上报，不能证明手机在线。真实组显示指定 Worker，模拟组显著标记合成资源。

### 机架 / 主机调度策略

每层可设置 1–64 的并发上限，留空不另设上限。**机架与主机限制同时满足**，再加上设备自己的单写槽、暂停、预留、隔离、能力与冷却限制。额度计算来自该模式下组内 `state=running` 的设备，占用在创建 Attempt 时开始，包含派发前核验阶段。

所有策略修改与任务领取沿用同一个模式级数据库短事务锁。多个 Worker 不会各自拿到一整份机架额度；降低额度也不取消已有 Attempt。每进程 4 个在途工作仍包含截图/状态/探测，因此机架限额不是 Worker 吞吐承诺。

排空操作写入持续生效的分组策略，并暂停现有成员：

1. 停止新领取；在途有界任务继续收尾，Job / Attempt / 结果不删除。
2. 排队任务保留，界面解释正在等待资源排空解除。
3. 排空期间新登记或移入的设备也不能领取；模拟场景不能绕过排空重置它们。
4. 有在途时显示“排空中”；无在途时显示“已排空”。这只表示本中心调度，不代表外部手机操作停止。
5. 解除排空只移除分组闸门，设备仍保持暂停，之后到工作台逐台启用。真机沿用新鲜空闲证据和独占确认要求。

分组策略不阻止显式截图与状态读取，不触发真机输入、手机取消或物理复位。

### 归属编辑

设备须暂停、空闲且没有正在执行或持有的中心会话，才能编辑 `name/rack/host`。修改保留 deviceId、serial、Worker、入口、账号资源、任务及尝试关联；保存后仍暂停。

这是中心分组调整，不是 USB 迁移或全组改名。策略绑定原分组名称，新分组不继承原组策略；原组没有设备时策略仍保存，日后同名分组再次出现会沿用它。明确绑定设备的排队任务继续跟随 deviceId；限定旧机架/主机的模拟任务继续等待旧范围中的兼容设备。

### 任务池与调度

独立页面提供状态/机架筛选、提交、取消未派发任务、查看尝试证据与调度事件，以及三个现有模拟演练入口。

排队项显示有效优先级、等待秒数、排序号、调度范围，以及依赖、延迟领取、排空、额度、隔离、预留、暂停、只读能力、通道关闭、占用、冷却、离线、执行器无新鲜健康心跳/工作槽满等原因。对多个候选设备可汇总多项原因；并非每个设备都同时具有全部原因。

排序号只是此刻优先级排序，不是固定发车序列。调度器会跳过暂不满足条件的任务选择下一个可执行项；来源链接与真实手机空闲状态仍须领取核验。不会凭这些信息编造 ETA 或推断物理 exactly-once。

模拟任务可选任意机架、指定机架、指定主机，及可选的明确设备，范围参与幂等指纹和实际领取。已有不带范围的任务兼容。真实旧 PoC 任务拒绝这类自动池化范围，保持明确设备与账号绑定，不自动跨机切换。

## 3. 实现与数据升级

| 文件 | 职责 |
| --- | --- |
| `server/scheduling.mjs` | 纯函数：优先级、范围匹配、资源/设备闸门、只读队列解释与汇总 |
| `server/resources.mjs` | 有版本校验的分组策略、排空与设备归属编辑 |
| `server/model.mjs` | 原领取引擎调用共享条件；登记、启用、演练尊重排空 |
| `server/store.mjs` | 原模式短事务内保存策略；只读一致快照保留活动依赖和尝试 |
| `migrations/003_resource_policies.sql` | 独立策略表，模式与分组键唯一，旧设备/任务无需重建 |
| `server/http.mjs` | 鉴权策略/归属接口；快照附加 scheduling，不调用上游 |
| `src/Racks.jsx` | 总览、策略表单、归属表单 |
| `src/Tasks.jsx`、`src/Forms.jsx`、`src/App.jsx` | 独立调度页、范围提交、导航与旧工作台连接 |

策略按 `(mode, scope, rack[, host])` 标识，用 JSON 元组编码避免字符串拼接碰撞；策略自身有 UUID 与 revision。当前仍没有独立可信 Host 注册、物理 Rack ID、USB 槽位、空机架库存或电源管理。已有设备按旧字段自动呈现，不必重新登记手机。每模式策略最多 512 条（包含暂时空组策略），设备与活动任务仍分别限 64 / 200。

部署仍使用本项目 `bash scripts/manage.sh deploy`。新版多一条 003 迁移，脚本按原顺序先让本中心旧 Worker 收尾，再迁移和更新 API/Worker；不要只替换前端或让未包含策略的旧 Worker 与新版长期混跑。迁移不删除旧表或数据；既有迁移校验机制会拒绝旧版本越过新版迁移记录。生产回退仍需规划对应版本/数据库，不能承诺任意降级。

## 4. 验证与证据边界

测试覆盖机架/主机交叉限额、多 Worker 原子领取、限额调低不抢占、排空保留队列/在途、解除后暂停、新成员与演练不能绕过排空、真实/模拟隔离、版本冲突、参数边界、范围/幂等/解释与领取一致、归属变动保留身份历史、鉴权和只读快照。

使用独立本机临时 PostgreSQL 验证 001→003 升级、重复迁移、连接重建后的策略保留、12 个竞争领取最多取得两个机架名额、每主机最多一个、历史来源查询。它不连接线上数据库，不代表经过数据库故障切换或生产压力验收。

浏览器验证路径：登录 → 机架总览 → 编辑归属 → 设置限额 → 排空/解除 → 逐台启用模拟设备 → 提交范围任务 → 查看等待原因 → 提高限额并行 → 排空等待收尾 → 窄屏筛选/尝试详情 → 切真实观察模式。使用本机假设备，真机调用钩子禁止访问上游。具体结果见 [verification.md](verification.md)。

## 5. 后续建设顺序与验收门槛

| 阶段 | 下一项交付 | 验收门槛 |
| --- | --- | --- |
| P1a 本轮 | 可见层级、持久资源治理、可解释的调度 | 本地事务/HTTP/浏览器验收；现役服务无改动 |
| P1b 下一步 | 能力版本与白名单命令/持久回执协议，隔离 mock Host Agent | 双 owner 仅一个成功；旧代次拒绝；相同 commandId 不重放；取消未确认不接管；重启与迟到回执可核验 |
| P2 | 稳定 rackId/hostId、配对、设备发现候选→人工绑定；获准的新设备输入链路 | 可信宿主机身份、单一写入口与回退已明确；从单台设备串行证据开始 |
| P3 | 两台真机/一机架容量与账号策略、持续观察限流、人工恢复 | 不同 serial 并行、无串机、未知无盲重试；宿主机失效仍有其他故障域容量 |
| P4 | 中心与 DB 可用性、备份还原、故障切换、容量测量/告警 | 实测 RTO/RPO、等待时长、未知率与吞吐；不以登记上限作为已验收容量 |
| P5 | 小红书参考流程插件与结果契约，业务系统按需接入 | 业务流程通过统一调度入口；Hub/Launcher/Rig 各自生命周期保持独立 |

P1b 与后续真实 Host Agent 本轮未实现。当前没有新增真实点击、取消确认、全局 fencing、自动物理接管、跨机分页恢复、连续视频、自动发现或 HA。旧 PoC busy 根因继续视为未证实；它阻止该旧能力的真机执行，不阻止机架管理和调度平台继续建设。
