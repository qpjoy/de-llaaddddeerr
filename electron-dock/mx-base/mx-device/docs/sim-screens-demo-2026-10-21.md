# 模拟手机画面按平台重做、聚焦演示与一键演示

日期：2026-10-21。只改 mx-device。**没有部署，没有连接手机、PoC、ADB 或服务器**，不影响 MX-H2I 登录与联网。同一轮的 PoC adapter 见 [V2-6 PoC adapter](v2-6-poc-adapter-plan-2026-10-21.md)。

## 1. 结论

- **画面像真机**：工作台墙上的每台模拟手机、单机工作台的大屏，都改成按平台绘制的手机画面（`src/phone/`）：
  - 有状态栏，以及锁屏、桌面和应用启动页；
  - 小红书、微博、闲鱼、拼多多各自的首页、搜索页、结果页、详情页；
  - 执行中的指令有对应的动态：输入框打字、加载下一页、下拉刷新、滚动、详情骨架屏、OCR 扫描线、点赞动画、返回提示；
  - 设备状态盖在画面上：冷却倒计时、待核验、失联、暂停、离线、会话预留。
- **数据也像真的**：模拟回执的标题、价格、正文按平台生成（`server/sim-content.mjs`），例如"露营装备真实测评｜用了一个月说说感受""【百亿补贴】充电宝 新款爆款 ¥39"。每页从 3 条增加到 6 条。演示场景的关键词改为各平台常见的搜索词。
- **直观演示**：
  - 工作台新增第五种视图「聚焦」：大屏自动跟随正在操作的手机（每台停留 8 秒，在执行中的手机间轮流），旁边逐步显示任务步骤、当前步骤进度、最近回执、"为什么是这台"，以及现场解说；下方是整个机架的缩略图条，点一下可以固定。
  - 工具栏新增「一键演示」：新建一个独立机架，四个平台的 15 个内置模板各跑一遍，指令间隔放慢到 2.6 秒，然后切到聚焦视图。
- **始终标明是合成的**：画面右上角有"模拟"水印，下方写"合成投影 · 非真实截图"。PoC 驱动的手机改标"PoC 接口结果"。
- **测试**：新增 `tests/phone-screens.test.mjs`（5 项），覆盖各指令、各状态下应显示的画面，以及新的模拟回执仍能通过回执校验。`npm run test:pg` 共 289 项全部通过。

## 2. 逐平台、逐操作对照

画面由两部分决定：最近一次**已核验的回执**说明了手机上已经发生什么；**正在执行的指令**说明此刻在做什么（`src/phone/screen-model.mjs`）。

| 操作 | 小红书 | 微博 | 闲鱼 | 拼多多 |
| --- | --- | --- | --- | --- |
| 打开 App（执行中） | 品牌色启动页 + 加载点 | 同左 | 同左 | 同左 |
| 首页 / 列表 / 刷新 | 关注·发现·附近，双列瀑布流（配图、标题、作者、点赞） | 关注·推荐·热门，微博卡片（头像、昵称、时间、正文、三图、转评赞） | 黄色顶栏搜索框、分类，双列商品（价格、想要人数、信用） | 红色顶栏、百亿补贴横幅，商品行（配图、标题、补贴标签、价格、已拼件数、去拼单） |
| 搜索（执行中） | 搜索框里逐字输入关键词，历史记录、猜你想搜、"搜索中…" | 历史、微博热搜（热/新标记） | 历史、大家都在搜 | 历史、热门搜索 |
| 搜索结果 | 搜索框 + 全部·用户·商品·图片 + 瀑布流 | 综合·实时·用户·视频 + 卡片 | 结果网格 | 综合·销量·价格·品牌 + 商品行 |
| 下一页 | 底部"加载第 N 页…"，完成后显示页码角标 | 同左 | 同左 | 同左 |
| 滚动浏览 | — | — | — | 列表持续上移 |
| 详情（执行中） | 骨架屏 | 骨架屏 | 骨架屏 | 骨架屏 |
| 详情 | 作者行 + 关注、大图与轮播点、标题、正文、话题、评论栏 | 微博正文卡片 | 卖家与信用、价格、标题、描述、大图、"聊一聊 / 我想要" | 大图、红色价格条（券后价、已拼）、标题、服务标签、"单独购买 / 发起拼单" |

| 点赞 | — | 心形跳动，完成后变为"已赞" | — | — |

| 回到桌面 | 桌面：时间小组件、各平台图标、相机/相册/时钟/设置、底部常用栏 | 同左 | 同左 | 同左 |

**设备状态**：

| 状态 | 画面 |
| --- | --- |
| 空闲 | 停在最后的页面；两分钟没有新动作后自动锁屏（大号时间和日期） |
| 冷却 / 整机休息 | 画面变灰，中间是计时器和剩余秒数 |
| 待核验 | 红色"需人工核验 · 执行结果不明 · 已隔离" |
| 失联待确认 | Agent 心跳中断时的提示 |
| 暂停、离线、会话预留 | 各自的图标与说明 |
| 大循环停在检查点 | 底部橙色"检查点等待" |

图标和颜色使用各平台的品牌色和文字标识，没有使用各平台的官方 logo；商品图是按品类挑选的图标（鞋、帐篷、耳机、充电宝等），不是照片。

## 3. 聚焦视图

| 区域 | 内容 |
| --- | --- |
| 大屏 | 跟随最近开始执行的手机；在执行中的手机之间轮流，最久没展示过的优先，每台至少停留 8 秒。可以"固定这台"或"恢复自动跟随"，也可以直接打开手机工作台 |
| 任务卡 | 平台图标、任务名、关键词、调用方、第几步 / 共几步、已执行时间；步骤列表（已完成 ✓、执行中带进度条、下一步），长计划只显示当前步骤附近；最近回执（如"第 3 页 · 6 条结果已核验""识别到 3 段文字"）；"为什么是这台"（调度器的原因）；"解释"按钮打开计划解释面板 |
| 现场解说 | 把最新事件写成句子："PoC 插槽 1 开始执行「小红书 · PoC 搜索前 3 页」""演示手机 005 回执已核验：小红书下一页 · 11/12""演示手机 010 完成「拼多多 · 搜索前 5 页」，全部回执已核验" |
| 缩略图条 | 整个机架的手机，执行中的带绿色边框；超过 24 台时只列出执行中的手机 |

嵌入 Hub 的运维视图（V2-5）也有聚焦视图，但是只读的（不能打开手机工作台）。

## 4. 一键演示

- 「一键演示」新建一个名为"全平台演示 HHMMSS"的独立机架，10 台或 20 台模拟手机。场景 `showcase` 先跑各平台的小模板，再跑大循环，15 个内置模板都会出现。
- 指令间隔 2.6 秒，冷却 2–4 秒，10 台大约 1–2 分钟跑完。
- 不影响现有机架和真实设备。也可以通过 `POST /api/workstation-demo` 发起，参数为 `scenario: "showcase"`。

## 5. 实现与验收

- `src/phone/synth.mjs`：作者、点赞、价格、配图、时间与电量，都由 ID 确定，每次渲染、每个观察者看到的都一样。
- `src/phone/screen-model.mjs`：纯函数，测试和三处界面共用（墙上缩略图、单机工作台、聚焦视图）。
- `src/phone/PhoneScreen.jsx`、`phone.css`：所有尺寸都相对于外框宽度（容器查询），墙上缩略图和大屏共用一套布局；遵守"减少动态效果"系统设置。
- 设备投影额外保存价格、OCR 文本块和点赞结果，都有长度上限，只用于显示。
- **浏览器验收**（`npm run dev:sim`，1440 宽与 390 宽）：
  - 墙上和大屏的各平台画面都正常；
  - 一键演示能新建机架并切到聚焦视图，大屏在执行中的手机间轮流；
  - 解说为可读的句子；
  - 手机宽度下五个视图按钮在一行内，页面没有横向滚动；
  - 控制台只有登录前会话检查的 401。
- **验收中修复**：
  - 返回操作后的提示一直不消失；
  - 窄屏下机架标题被挤成竖排；
  - 搜索页的建议列表为空；
  - 搜索历史中关键词重复，导致 React 键重复；
  - 自动跟随总停在同一台手机上。
