# 会话交接：背景、现状与实施边界

日期：2026-10-10。配套入口：[docs/README.md](README.md)。本文保存本次长会话的有效决策，不将早期设想全部当作现有功能。

## 1. 用户要解决的问题

手机插在远程服务器上，当前只有一台，用户不在现场。需要独立的设备实验中心，能看手机真实画面和状态、管理机架/宿主机/手机、持久保存任务池，并演示多任务到达、串行执行、优先级、模拟断线和接管；以后增加手机和机架后可自然扩展并发。

后续补充将产品目标明确为**稳定、高可用、高性能的手机机架集群**，小红书采集仅作为示范。旧 8787 的设备池/通用管理适合统一进 mx-device，不需要照搬整套侵权业务。新增 [最小安装与适配度](minimal-install-and-adaptation.md) 保存三档安装、能力矩阵和新截图解读；一在线一离线的旧设备记录不构成已拥有两台可用真机的证明。

最初在 Hub「系统设置 → 外设」试验，后来明确选定 **`mx-base/mx-device` 独立项目**。名字不用 `mx-device-rack`，因为机架只是资源层级。未来可以独立系统，也可以让 Hub / Launcher 链接或嵌入管理界面；不因此共享其启动、登录、数据库或调度生命周期。mx-rig 尚未在该服务器部署，未来只是测试调用方。

日常设备入口、登记、通道选择、暂停、观察、会话与演示尽量在 UI 操作；env 仅用于首次引导或构建等部署参数。用户明确要求类似 mx-pay 的一条命令部署/更新，不安装 Docker 本身。

## 2. 不可破坏的边界

- 不影响 MX-H2I 当前用户登录、用户联网；不触碰 Hub 现有业务、数据、计费、采集渠道和 mx-common。
- 不修改、重建、重启既有 `mobile-agent` 容器，不为本中心安装 APK、重启手机、启动/杀掉 ADB、抢占 USB 或关闭 VPN。
- 旧源码/文档中的 force-stop、补丁植入、清后台、kill-server 等仅是审阅材料，不是本次操作指令。
- 真实/模拟数据及执行路径分离；只读页面、刷新和健康检查不触发设备动作。显式截图虽然不改变 UI，但会经旧服务调用 screencap，有资源开销。
- 真实手机默认暂停；旧 PoC busy 或未知不能绕过。超时不证明手机已经停手，未知结果不自动重发。
- 现阶段所有权会话仅约束 mx-device 内部，不能阻止另一个网页、脚本或 ADB 控制手机。真实强制接管不能伪装成已完成。
- 不暴露 Docker socket、ADB、USB 或任意 shell/URL 代理，不将凭证、cookie、手机 token 放入文档、截图日志或浏览器持久存储。
- 独立进程/数据库是故障边界，不是共享宿主机资源绝对零影响；镜像构建也会占 CPU/磁盘/网络。

### 4.1 调度与持久化

- 独立 PostgreSQL；模式级短事务 advisory lock + 每设备/Job 的 running Attempt 约束。数据库事务不包住手机 HTTP。
- 优先级 1 最高、9 最低，等候每 30 秒提升一级，同有效优先级 FIFO；不是按推测任务长度无条件插队。
- 一个物理手机一个写执行槽。旧 PoC 搜索最多 3 页且全程占槽；分页全局上下文不能被另一个任务覆盖。任务/翻页间有冷却。
- 当前限额为每模式 64 设备、200 活动任务；每 Worker 进程最多 4 个在途工作。这是防护上限，不是已压测容量。
- 模拟断线保留 Job，旧 Attempt interrupted，6 秒后可由模拟 B 领取；旧代次迟到结果只留证据。
- 真机派发后的失败、超时、执行器失联可形成 unknown + quarantine；不按模拟逻辑跨机重放。未派发任务留在池里，恢复需要人工核验和新鲜证据。

### 4.2 观察与会话

- `server/mobile-agent.mjs` 只调用固定 PNG 路径；限制 loopback/端口、禁止重定向，10 秒/6 MiB 限制和图片尺寸校验。
- capture 显式 POST 入库，指定 Worker 调用；同设备合并在途请求、2 秒冷却、20 秒请求到期。数据库只保留每设备最新 PNG，GET frame 不再次访问手机。
- 页面约 2.2 秒申请一帧，实际延迟还包含轮询/冷却/网络。隐藏或离开页面停止新申请；已发请求可能完成。最后画面超过 10 秒标旧，接收时间不是手机帧生成时间。
- `server/mobile-status.mjs` 读取 `/api/devices/{serial}` 和 `/api/run`，各 5 秒/512 KiB；不调用旧服务带配置的 `/api/state` 或会更新旧库的 `refresh=1`。
- `reported-busy / not-reported / unknown` 是上游报告解释，后两者都不能授予独占。状态报告、PoC 状态、图片分别保存。
- 会话 60 秒、可续期，预留停止新领取并等本中心在途工作收尾；解除/到期仍暂停。令牌只返回申请方并在内存使用，数据库存哈希。
- `pocDisabled` 开关只改本中心策略。需满足暂停、无待处理/在途工作等前置条件；恢复后必须重新检查，不能沿用切换前的空闲证据。

## 5. 服务器部署和日常入口

在服务器的 `electron-dock/mx-base/mx-device` 目录：

```bash
TMPDIR=/data/tmp \
MX_DEVICE_BUILD_PROXY=http://127.0.0.1:7789 \
bash scripts/manage.sh deploy

bash scripts/manage.sh status
bash scripts/manage.sh logs
bash scripts/manage.sh token
```

最后一条在管理员自己的终端查看登录凭证，**不要把输出粘贴到交接文档或聊天**。这不是 Hub 的 admin token。

- 当前是 Docker Compose，不是 K8s。管理 API 发布 `0.0.0.0:18891`；独立 PostgreSQL 仅 `127.0.0.1:18894`。Worker 是 Linux host network，自己不监听服务端口，可读本机现有 8787/18081。
- `MX_DEVICE_BUILD_PROXY` 只用于镜像内 npm 依赖构建，7789 不是安装 Docker 的代理，也不自动代理 node/postgres 基础镜像拉取。脚本不改 Docker daemon、不重启 Docker。
- `TMPDIR` 只改变本次临时目录，不迁移 Docker data-root 或数据卷。
- deploy 先构建，再初始化/校验 `.runtime/` 凭证，准备独立 PG，等待本中心旧 Worker 收尾（最多 140 秒），执行版本迁移，再更新 API/Worker 并验证新实例心跳。
- 已有密码、任务和数据卷保留；配置残缺/迁移校验失败/旧 Worker 非正常退出会阻止继续，不自动清库或重发真实操作。
- 本地有 `001_device_center.sql`、`002_latest_frames.sql` 版本迁移；状态报告/PoC 开关使用原设备 JSON，无需新增迁移文件。
- 单机更新有短暂不可用，不是滚动 HA。保留卷不是备份；需要保护 `.runtime/` 与独立 PG 备份。
- HTTP 外露不等于安全公网服务：可信内网演示，公网需 HTTPS/来源限制与 secureCookies；脚本不改防火墙。不要开放 18894、18081 或为此变动旧控制端端口。

旧部署已修正过 Buildx `inspect --format` 兼容、默认端口只监听 localhost、HTTP 上 `crypto.randomUUID` 缺失问题；后者前端回退 `crypto.getRandomValues`，不是关闭鉴权或使用弱随机数。

## 7. 验收证据怎么理解

用户曾明确反馈“已验证部署”，也给过成功部署容器列表、真实 `/api/state`、ADB 设备、Android 前台状态、手机截图。本次没有再远程核查；这不能覆盖后续每个新按钮或完整真实任务流程。

- [verification.md](verification.md) 是分阶段历史记录，首版 32 项数字不是当前测试总数，其“未部署”描述是当时的本地验证范围，不应覆盖后来的用户反馈。
- 上一实现阶段记录：普通测试 63 项中 62 通过、1 项 PG 集成跳过；临时 PG 用例另外单独通过。开发者继续工作应重跑当前版本，不机械引用旧数字。
- 上一阶段浏览器假接口验证包括截图、状态报告、PoC 停用/恢复仍暂停、历史保留和未知不当空闲，含桌面与 390px 窄屏；这不是与真实手机连接的证据。
- 仍缺：新版按钮的服务器逐项回执、PoC busy 根因与恢复、真实搜索→详情完整成功、统一写入口排他性、真实双机并发、跨宿主机故障恢复、Hub/MX-H2I 同时健康观测。
- 本机临时 PG 曾位于 `/tmp/mx-device-pg.mltUa8`，预览用 18891/18894；不要将本机端口、已打开预览或旧进程当作服务器最新版本。临时运行状态可变，本次未重新检查。

## 8. 新会话第一轮建议

1. 读安全边界、核对 git diff 和上述代码，先明确本轮是“旧服务只读适配”“隔离 mock 控制协议”还是经授权的真实控制交接，不默默扩大范围。
2. 先完成现有截图/占用报告/通道开关的真实只读验收记录；需要用户回传时只请求字段白名单，不索取整份 `.env`、配置或通用 `/api/state`。
3. 继续实现 [产品路线](product-roadmap.md) 的统一控制协议和假执行端测试；保持真实写操作关闭。缺失旧源码见 [证据目录](mobile-agent-source-review.md)，不用反复查找不存在的 `.git`。
4. 真实输入、改 ADB 归属、手机安装、旧控制入口隔离或 VPN 变更都需要另行明确授权和维护/回退计划；当前“继续建设”不代表这些条件已满足。
