# Agent 工作台：看得见的过程、看得见的手、可以回放

日期：2026-09-30。代码基线：0.8.0 Preview（`feat/mx_insight_hub`）。

## 0. 结论

以前在桌面端看 Agent 做浏览器测试，是两个窗口来回切：
- 一个独立的 Chromium 窗口，页面一步一跳，看不到鼠标；
- 一条平铺的事件日志，每步一段 JSON，截图要点按钮用系统看图软件打开。

现在参照 Codex / Claude Code 桌面端的交互改成了下面这样：

| 以前 | 现在 |
| --- | --- |
| 平铺的事件日志，每步一段 JSON | 对话式的「工作过程」：Agent 边做边说的话，加上折叠成一句话的工具步骤（「读取了 3 个文件，运行了 1 条命令」「打开了 1 个页面，点击 1 次，填写 1 处」），展开看每一步的参数、结果和截图缩略图 |
| 截图用系统看图软件打开 | 缩略图点开是灯箱，左右键翻页 |
| 页面一步一跳，看不到鼠标 | 被操作的页面上有「领航光标」：动手之前，光标先移到目标元素，元素被框出来并写着「点击『保存』」，点击时有涟漪 |
| 浏览器是另一个窗口 | 任务右侧「浏览器」页签实时显示被操作的页面（带光标）；去了别的页面，右下角有画中画小窗 |
| 确认框只列参数 `{"ref":"e1"}` | 确认框写「填写『昵称』：Rig」，同时在实时页面上把这个元素框出来，标着「待确认」 |
| 事后只有一堆截图 | 回放：光标从一步的目标移到下一步的目标，框选、说明、点击涟漪，然后渐变到结果；断言显示 ✓ / ✗。可以暂停、单步、调速，可以导出成一个自己会播放的 HTML 文件 |
| — | 改了文件的任务有「N 个文件已更改 +a −r」 |

截图如下（桌面端冒烟测试自动截取，在 `.runtime/qa/` 下）：
- `desktop-live.png`：等待确认时，实时页面标出要填写的字段；
- `desktop-replay.png`：折叠的步骤、缩略图，以及右侧的回放；
- `desktop-pip.png`：在「总览」页时右下角的画中画；
- `desktop-lightbox.png`：灯箱。

## 1. 领航光标（`packages/runtime/pilot.mjs`）

每个被自动化的页面里都注入了一只「手」，由 Playwright 的 init script 注入。在一次点击、填写、选择或勾选之前，依次发生：

1. 把目标元素滚到视野里；
2. 框出元素，并写上要做什么；
3. 真的把鼠标移过去（悬停效果会像人操作时一样出现）；
4. 有人在看（有窗口运行）时停约 0.4 秒；无头运行（工位、测试、CI）不停。

它不能改变被测的东西：
- **不进入可访问性结构**：它挂在 `<html>` 上的 closed shadow root 里，并标记 `aria-hidden`。可访问性快照、定位器和页面自己的查询都看不到它，测试验证了 `getByText` 找不到它的说明文字。
- **不受页面 CSP 影响**：全部样式通过 CSSOM 设置，不用 `<style>` 或 `innerHTML`。严格 CSP 加 Trusted Types 的页面上，测试确认零报错。
- **不进入证据截图**：截图前它自己隐藏。一开始用的是 Playwright 截图的 `style` 选项，结果在严格 CSP 的页面上被拦截，框线留在了截图里；测试按像素查出了这一点，现在改成调用它自己的接口来隐藏。
- **不接收指针事件**：它不拦截任何点击。

## 2. 实时画面与画中画（桌面端）

- **来源**：`BrowserTools` 通过 DevTools 协议的 screencast 拿到页面画面（JPEG，每秒最多 4 帧）。
- **传递路径**：worker 进程 → 主进程 → 窗口，是单向的纯数据。
- **节流方式**：只丢中间帧，不丢最后一帧。一个静止下来的页面不会再产生新画面，所以最后一帧必须送到。最初按「间隔内直接丢弃」节流，实测时画面停在了 `about:blank` 上，已经改过来。
- **显示位置**：
  - 在任务页：右侧「浏览器」页签。任务一开始用浏览器，这个页签会自己切到前面，除非你已经手动选过别的页签。
  - 在其他页面：右下角画中画，点它回到这项任务的浏览器页签。
- **确认前的标记**：等待确认时，Runtime 会按上次看到的页面把 `ref` 解析成真实的元素，确认框写出元素的名字，实时页面上框出这个元素。
- **停留时长**：任务运行期间，画面一直停在这项任务上，包括等人确认时。

## 3. 回放（`apps/web/replay.js`）

**数据**：每一步浏览器写动作都会记下两样东西：
- 动手前的干净截图（`<n>-intent.png`）；
- 目标框和点击点。

这些和动作之后的截图一起，放在任务记录的工具结果里（`frame`）。`replayFrames(events)` 把它们读成一帧一帧的步骤；执行失败的步骤也是一帧，并写明原因。

**播放**：
- 用 SVG 的属性和 class 绘制：工作台的 CSP 不允许内联样式，导出的文件里内联的也是同一份代码；
- 每一帧：光标从上一目标缓动到这一目标，框线和说明出现，点击涟漪，然后渐变到结果；
- 断言帧在左下角显示 ✓ / ✗；
- 空格键播放 / 暂停，左右键单步，速度 0.5 / 1 / 2 倍，下方有步骤列表可以跳转。

**导出**：`replayDocument` 把播放器、样式和截图内联成一个 HTML 文件，双击就会自动播放。截图可能含被测系统的业务数据，文件里写明了这一点。
- 桌面端：浏览器页签里的「导出回放」，弹出保存对话框。
- 终端：`/replay` 写到 `~/.mx-rig/workspaces/<…>/replays/<任务>.html`，并用系统默认浏览器打开。

**范围**：网页工作台上看不到桌面任务和终端任务的截图，因为截图留在执行它的电脑上。网页端只列出步骤，并说明去哪里回放。

## 4. 工作过程（`apps/web/activity.js`）

**来源**：Runtime 多记两样东西：
- 工具开始时的参数（长字符串截短，保留总长度）；
- 模型在调用工具时顺带说的话（`say` 事件）。

对话本身仍然只留在执行它的机器上。

**展示**：
- 事件被读成：你的话、Agent 的话、折叠的步骤组、结论、状态行；
- 步骤组的一句话摘要按类别计数，同一个文件改两次只算一个；
- 每一步有：✓ / ✗ / !、可读的一行说明、简短的结果（退出码、行数、匹配数、+a −r），以及缩略图（仅桌面端）；
- 命令步骤可以展开看输出末尾；
- 底部贴着「处理中」胶囊，写着此刻在做什么。

**稳定性**：页面每次轮询都会整体重绘。展开状态、正在播放的回放、灯箱、实时画面都存在渲染之外，重绘时重新挂回去，不会被打断。

**终端**：
- Agent 的话照常显示；流式输出过的部分不重复打印；
- 每次回答后有一行「改动 N 个文件 +a −r」。

## 5. 验证

- **`tests/pilot.test.mjs`**（真实 Chromium，严格 CSP + Trusted Types 的页面）：
  - 光标框线出现在实时页面上，不出现在证据帧里，用像素读数判定；
  - 不在可访问性快照里，定位器找不到；
  - 页面零报错；
  - 滚动到视野内以后才瞄准；
  - 实时画面有帧；
  - 规程重放时同样有光标，判定不变。
- **`tests/replay.test.mjs`**：
  - 从任务记录读帧，失败的步骤也是一帧；
  - 真实浏览器生成回放文件，在另一个浏览器里打开后自动播到最后一步，光标位置、断言 ✓、单步跳转都正确，零报错。
- **`tests/terminal.test.mjs`**：`/replay` 生成的文件内联了截图和播放器。
- **`npm run test:desktop -- --browser`**（Electron 桌面端，真实 Chromium，替身模型逐页读快照取 ref）：
  1. 三次确认；等待确认时实时画面在显示；
  2. 切到「总览」出现画中画，点它回到浏览器页签；
  3. 步骤组摘要为「打开了 1 个页面，点击 1 次，填写 1 处」和「断言 1 条」，有 4 张缩略图；
  4. 灯箱打开，Esc 关闭；
  5. 回放共 4 步，播放推进到第 3 步。
- **`npm run test:browser`**（网页端）：通过。这次顺便修正了一条过期的断言：质量报告页后来加了 Agent 分区的指标块，原来的断言把它们也数了进去。
- **修掉的测试不稳定**：钩子测试在「定级任务已启动」之后立刻读第一次模型请求，负载高时请求还没发出。已改为等待，六个进程同时跑都通过。
