# 演示一遍：可自动化的教学关卡（方案，2026-10-07）

## 1. 用户的设想

既然 Rig 内置了 Playwright，教学流程也可以和现有的游戏化（系统任务、经验、悬浮面板）和自动化结合起来。

例如用户想看罗盘 Web 冒烟：

- 冒烟之前的步骤都自动完成：建任务、填表、设置项目等，这是第一轮“教学”；
- 后面的冒烟由用户自己发起，是“正式流程”。

这部分要做成非侵入式的，不影响用户手动操作。

## 2. 评估：方向对，三处调整

| # | 设想 | 建议 | 理由 |
| --- | --- | --- | --- |
| 1 | 用 Playwright 驱动教学 | **教学在用户自己的窗口里由页面内的“关卡脚本”驱动；Playwright 用来验证这些脚本** | Playwright 接不上用户已经打开的桌面端窗口。要接，就得给桌面端开调试端口，本机任何进程都能借此操作已登录的 Rig。换成在另一个浏览器里演示，用户又看不到按钮在自己界面的哪里，而且得把登录态交给自动化浏览器，浏览器工具本来就拒绝碰密码框 |
| 2 | 冒烟前全部自动 | **三种速度：跟做、演示、快速准备** | 第一次学，最好是光标指着、你自己点；看别人点不如自己点记得住。第二次只想要结果，就是“一键准备到冒烟前” |
| 3 | 教学和正式流程分开 | **正式流程的第一步（立即执行）一定由人按** | 和“定时前先验证”是同一条原则：第一次执行是你自己确认参数后发起的。系统任务的奖励也按这条分：看过演示是一项，自己跑出结论是另一项 |

## 3. 怎么做

### 3.1 关卡脚本：一份数据，两处使用

每个关卡是一份步骤清单（`apps/web/tours/*.json`），每一步包括：

- 在哪一页、哪个页签；
- 指向哪个元素（稳定的 `id`，冒烟脚本已经在用这些 id）；
- 做什么：指给你看、点击、填写、选择；
- 说什么：旁白；
- 做完后等什么：页面上出现什么，或平台状态变成什么；
- 会不会写入：会建东西的步骤要标出来。

这份清单有两个用处：

- **工作台里**：`apps/web/tour.js` 逐步执行。光标移到目标元素上，加高亮和旁白，然后像人一样点击或填写，走的是同一批按钮，没有任何专用接口或后门。光标的样式沿用回放里 Agent 浏览器的光标（`pilot.mjs`、`replay.css`）。
- **冒烟里**：新增的检查用 Playwright 按同一份清单真实点一遍。界面改了、某个 id 没了，冒烟当场失败，教程不会悄悄过时。

这也是 Rig 测自己：教程本身就是一条用例。

### 3.2 三种速度

| 模式 | 谁点 | 适合 |
| --- | --- | --- |
| 跟做（默认） | 光标指着，旁白说明，**你点**；关卡看到预期的变化后自动进到下一步 | 第一次 |
| 演示 | 光标按阅读速度替你点，每一步停一下 | 想先看一遍再自己做 |
| 快速准备 | 不讲解，直接做到冒烟前 | 已经会了，只要结果 |

三种模式都停在同一个地方：「立即执行」按钮被高亮，由你来按。

### 3.3 非侵入：不影响手动操作

- **只在你主动开始时运行**：入口在系统面板、新手引导和验收包卡片上的「演示一遍」。从不自动弹出。
- **不运行就不存在**：`tour.js` 挂在 `#view` 之外，和系统面板一样。不运行时不画任何东西，也不挂任何监听。现有页面的代码不改行为，只是有的元素补上稳定的 id。
- **你一动就让出控制**：关卡运行时，你在关卡指向的地方以外点击、按键或按 Esc，关卡立即暂停，提示「你接手了」，可以继续或结束。它从不和你抢鼠标。这跟 Agent 浏览器的人工接管是同一个思路。
- **写入先说清楚**：第一次写入前，一次列出它会建什么。以罗盘为例：
  - 项目 `luopan`；
  - 本机源码快照；
  - QA 仓库；
  - 两个执行计划；
  - 本机执行机。
  
  你确认后才开始。
- **只增不改**：每一步先看现状。项目已经存在就跳过「建立」，并说明“已经有了，沿用你的”。不删除任何东西，不修改你改过的配置；验收包的建立本来就是幂等的。
- **服务端不变**：没有“教学模式”开关，也没有特殊数据。关卡建的东西就是普通的项目和计划，和手动建的没有区别，审计照常记录。
- **按角色裁剪**：查看者只能走只读的关卡（看结果、读报告）。需要管理员的步骤，非管理员会看到“请管理员做这一步”。

### 3.4 关卡做不到的地方

- **系统对话框**：例如选择 `po-frontend` 目录，页面内的脚本点不到。关卡在这里停下，请你自己选，这本身也是要教的一步。
- **网页端**：建快照、启动本机执行机只在桌面端。网页端的罗盘关卡只做到登记项目，然后说明剩下的步骤要在桌面端完成。

### 3.5 和系统任务（游戏化）怎么接

- 每个关卡在系统任务目录（`apps/server/system.mjs`）里对应一条关卡链，判定仍然只用已有的三种来源：
  - **看过演示**：界面上报，界面上如实写明来源；
  - **建好项目和计划**：平台状态；
  - **自己跑出第一个结论**：平台状态，执行由你本人发起。
- 奖励仍然只来自「领取」。演示替你建好的东西，不算成“你亲手做的”；你自己按下「立即执行」并拿到结论，才算正式流程那一项。
- 顺手更新已经过时的任务文案，例如「接入一个被测应用」里还写着旧管理台的“接入 / 对齐 Compass”。

## 4. 关卡目录（第一批）

| 关卡 | 端 | 走到哪里停 |
| --- | --- | --- |
| 罗盘 Web 冒烟 | 桌面端 | 1. 项目与任务 → 从验收包创建 → 选择 `po-frontend` 目录（你来选）→ 固定的提交（默认验收包里的）→ 建立；<br>2. 执行计划 → 启动本机执行机；<br>3. **停在「罗盘 Web · 主路径冒烟」的立即执行** |
| 试验场：第一次执行（并入 M8b 的「新项目」，见 §5） | 桌面端，网页端也可 | 1. 用内置试验场登记项目、建执行方式和计划（被测地址指向本机试验场）；<br>2. **停在立即执行**。<br>不需要任何外部仓库，适合作为第一个关卡 |
| 新项目：从用例到测试代码 | 桌面端 | 1. 建测试任务 → 写两条用例并确认 → 让 Agent 起草测试实现 → 批准 → 写入本机测试仓库 → 建立本机执行计划；<br>2. **停在「用本机测试仓库执行这个提交」** |
| 读懂一次执行 | 两端 | 打开最近一次执行 → 失败用例 → 拖动录像 → 对外版报告 → 让 Agent 分析（草稿，不自动开始）。全程只读 |

  - 关卡执行器 `tour.js`，支持三种速度、接手、写入前确认；
  - 「罗盘 Web 冒烟」和「读懂一次执行」两个关卡；
  - 桌面端和网页端冒烟都按同一份清单回放；
  - 入口放在系统面板、新手引导和罗盘验收包卡片上。
- **M8b**（已交付，见 §8）：
  - 关卡接进系统任务目录：关卡链、奖励的划分、更新过时文案；
  - 「新项目：从用例到测试代码」关卡，以「试验场」为被测对象（桌面端一键启动本机试验场）。
  - 「试验场」关卡从 M8a 挪到这里：没有测试代码时，试验场的第一次执行说明不了任何事；而写测试代码正是「新项目」关卡要教的。两个关卡合成一个。
- **M8c**（已交付，见 §9）：
  - 每次发版时由冒烟按关卡清单录一遍屏，自动生成最新的教学录像，放进新手引导；
  - 录像始终和当前界面一致，不需要人工重录。

## 6. 风险

- **界面一改关卡就失效**：由冒烟回放兜住，失效会在发版前发现，而不是被用户撞上。
- **页面重画时元素被替换**：每一步都等目标元素重新出现后再动作，和冒烟脚本的做法一样。
- **定位叠加层与内容安全策略**：光标和高亮框画在一层全屏 SVG 上，用 SVG 属性定位，不写内联样式，符合现有的 CSP（`style-src 'self'`）。这和经验条、编排图的做法一样。

  录像里只有替身数据，临时目录不在任何人的主目录下，执行机名叫「演示电脑」。桌面端为此新增一个可选的环境变量 `MX_RIG_PROVING_GROUND_DIR`，录制时指向试验场的副本。
- **服务端**（`apps/server/tour-videos.mjs`）：
  - `GET /api/rig/v1/tour-videos`：任何已登录成员可读；
  - `GET /api/rig/v1/tour-videos/<关卡>.webm`：支持按字节范围读取，录像可以拖动；
  - `PUT /api/rig/v1/tour-videos/<关卡>`：只有管理员能发布；只认关卡目录里的关卡；必须是 WebM，不超过 32 MB；同一个关卡只保留最新一段；不挤占磁盘保留区。
- **桌面端**：`rig-media://tour/<关卡>.webm` 由主进程带上登录凭据去取，和执行录像同一个机制。只认关卡目录里的关卡和 `.webm`，其余一律拒绝。
- **新手引导**：每个关卡卡片上放它的录像，写明是哪个版本的界面、什么时候录的；和当前版本不一致时会提示「界面可能已经变了」。网页端走不了的桌面端关卡，也能看录像。

**实测**（本机 macOS）

| 关卡 | 时长 | 大小 |
| --- | --- | --- |
| 罗盘 Web 冒烟 | 20 秒 | 2.6 MB |
| 新项目 | 44 秒 | 4.9 MB |
| 读懂一次执行 | 20 秒 | 1.7 MB |

- 一次录制约 3 分钟，其中「新项目」之后那次真实执行通过了。
- 三段合计 9 MB；每发一版只是覆盖，不会累积。

**逐帧看过之后修掉的问题**

- **面板里出现「null」**：`replaceChildren` 会把空位写成文字「null」。这是 M8a 就有的界面缺陷，之前的截图恰好都没碰上空位。已修好，冒烟脚本也加了检查。
- **录像下方和右侧有灰边**：先是窗口在这台显示器上撑不到 900 像素高；改成 720p 后，录到中途右侧又出现灰边。把窗口固定为不可调整大小之后就没有了，脚本每段都会打印窗口和页面的尺寸。
