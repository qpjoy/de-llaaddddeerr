# 出网通道

状态：MX Rig 0.6 已实现；2026-09-16。

0.5 的「出网观测」是只读的，理由写在模块开头：MX Rig 不拥有网络。这条边界没有变。变的是把"Rig 自己那两个出网请求"从"由环境随便决定"变成"可以明确选一条通道，并且能实时切换"。

## 两半，永远分开显示

| 半边 | 归谁 | 能不能改 |
| --- | --- | --- |
| 环境观测 | 部署环境：`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`，以及运行时到底读不读它们 | 不能，只读 |
| Rig 通道 | Rig 自己的两个出网面：服务端的模型调用、桌面 Runtime 的隔离浏览器 | 管理员可增删并实时切换 |

上半页在启用通道后**不会被改写**。理由就是这一页存在的理由：「模型连不上」和「模型配错了」必须能分开，如果启用通道会顺手把环境观测也涂成绿色，这一页就废了。

页面顶部给四个读数：模型调用走哪、隔离浏览器走哪、环境变量观测、以及"其他一切由部署环境决定"。

## 为什么要自建隧道

Node 22 的全局 `fetch` 根本不读代理环境变量，`NODE_USE_ENV_PROXY` 从 Node 24 才有——这正是 0.5 的观测页一直在说的那句话。所以"设个环境变量希望它生效"不是实现，`apps/server/proxy-fetch.mjs` 用 `node:https` 加一个 HTTP CONNECT 代理自己发请求：

- 只实现模型网关真正用到的那部分 `fetch`：method、headers、字符串 body、`redirect: 'error'`、AbortSignal，以及带 `cancel()` 的异步可迭代响应体。面小才审得动。
- 只代理 `https:`；回环与直连列表里的主机保持直连；非本机的 `http:` 目标直接拒绝，而不是悄悄发出去。
- 隧道里只说 HTTP/1.1（ALPN 固定），不开 keep-alive——切换通道后不该有旧连接还在复用。
- 407 单独报「通道要求代理凭据」，和"连不上"分开。

浏览器那一侧不需要隧道：Playwright 启动时接受 `proxy`，Chromium 在启动时解析代理。所以通道变了就**关掉旧浏览器**，下一次 `browser_open` 用新通道重开。留着旧进程说自己在走新通道，是对一个页面说谎。

## 通道的数据模型

存在 `settings.json` 的 `egress`，校验在 `apps/server/egress-profiles.mjs`。

| 字段 | 规则 |
| --- | --- |
| `id` | 小写标识，和 Provider、Agent 同一套字符集 |
| `proxyUrl` | `scheme://host:port`，只允许 http / https / socks4 / socks5；**必须写端口**；不许带凭据、路径、查询或片段 |
| `bypass` | 主机名或 `.suffix` / `*.suffix`，最多 30 条；回环永远直连，不用写 |
| `authEnv` | 代理凭据的**环境变量名**（大写），值由服务端读取，格式 `user:password` |
| `appliesTo` | `model`、`browser`，至少一个 |

两条互相咬合的限制，都在保存时就拒绝：

- **socks 通道不能作用于 `model`。** 模型那一侧走的是 HTTP CONNECT，实现里没有 SOCKS 握手。想用 socks，就只给浏览器用。
- **带 `authEnv` 的通道不能作用于 `browser`。** 桌面 Runtime 是另一台机器上的另一个进程，不该收到服务端凭据，更不该把它写到命令行上。

界面只显示通道地址与变量名，以及那个变量**在服务端到底设了没有**——"通道配好了但变量没设"就是这一页要抓的故障。凭据本身不进 UI、不进日志、不进任务记录。

## 切换的语义

切换走的是普通的配置更新路径：重新校验、写盘、**换一个策略版本号**。于是：

- 下一次模型调用立即走新通道，不用重启服务。传输按通道指纹缓存，改了地址就重建。
- 待确认的动作**失效**，需要重新发起。这不是副作用，是这套确认机制的本意：那次确认是针对"这组参数、这条策略、这条出网路径"给的，路径换了就不再是同一件事。
- 隔离浏览器在下一次打开页面时重开。

只有管理员能增删与切换（`POST /api/rig/v1/admin/egress:activate`）。`/api/rig/v1/config` 只给通道 ID，不给地址；桌面 Runtime 需要地址才能启动浏览器，所以地址只在 operator 起步的 `/api/rig/v1/execution-config` 里下发。

## 仍然不做的事

不设置系统代理、路由表、DNS、PAC、NRPT；不接管其他应用的网络归属；不申请网络 lease；不碰 MX-H2I 的登录与联网。需要私网连通性时，仍由管理员在部署层提供，或通过 standalone launcher 的既有能力接入。`scripts/check.mjs` 依然会因为 Runtime 里出现 `netsh` / `route` 之类的调用而失败。

## 未验证

真实企业代理（含需要凭据的那种）、socks5 下的隔离浏览器、以及 TLS 校验失败之外的完整 HTTPS 往返都没有对真实网关跑过。本轮的隧道验证是：CONNECT 目标与 `Proxy-Authorization` 到达了代理、407 被单独报出、以及 TLS ClientHello 确实穿过隧道到了上游（见[验证记录](04-verification.md)）。
