# 在实时画面里接管：人来做 Agent 不该做的那一步

日期：2026-09-30，2026-10-01 更新（放宽了 §9 里的大部分限制，见 [docs/17](17-sites-and-page-behaviour.md)）。代码基线：0.8.0 Preview（`feat/mx_insight_hub`）。

## 0. 结论

以前要亲手操作被测页面，得先点「暂停并接管浏览器」，再切到那个独立的 Chromium 窗口里操作。碰到密码框时，Agent 只能报一个错然后停下。

现在：
- **在画面里直接操作**：桌面端任务右侧「浏览器」页签的实时画面就是一块可以操作的屏幕。鼠标、键盘、中文输入法、粘贴、滚轮、文件选择都转发给页面，不用切窗口。
- **Agent 会主动请人**：Agent 碰到不该由它做的一步（密码、验证码、扫码、支付、第三方授权），不再报错停下。它调用 `browser_handoff`，写一句要人做什么，并在页面上框出那个元素，写着「请你来：…」。人在画面里做完，点「交还给 Agent」，可以附一句话。Agent 先重新观察页面，再接着原来的目标做。
- **人输入的内容哪里都不记**：任务记录、回放、发给模型的内容里都没有。只记「点击 1 次、输入 1 段文字、按键 1 次」这样的计数，以及交还时页面的截图（密码类字段被遮住）。
- **修掉了一个已有的泄露**：做这件事时发现，Playwright 的可访问性快照会带上文本框的值，**包括密码框**。所以页面预填的密码、浏览器自动填充的密码、人刚输入的密码，都会原样出现在发给模型的快照里。现在已经修复，见 §5。

截图（桌面端冒烟测试自动截取，在 `.runtime/qa/` 下）：
- `desktop-takeover.png`：Agent 请人输入密码，人在实时画面里输入完、登录成功，还没交还；
- `desktop-takeover-done.png`：交还后任务完成。工作过程里有一段虚线框的「人工操作」和缩略图；回放里第 2 步是 ✋。

## 1. 两种进入方式

| 谁发起 | 怎么发起 | Agent 此时 |
| --- | --- | --- |
| 成员 | 任务运行中点实时画面上的「接管」，或确认框里的「暂停并接管浏览器」 | 在下一步之前停下 |
| Agent | 调用 `browser_handoff`：`reason` 必填，写要人做什么；`ref` 可选，指要人操作的元素 | 任务暂停。光标框出 `ref` 指的元素，写着「请你来：reason」 |

`browser_handoff` 的属性：
- 效果是「只读」：它自己不碰页面，只是把页面交给人。
- 只在有东西可交的地方提供：桌面端的页面、Electron 应用、原生应用，或终端的有窗口浏览器。
- 必须和 `browser_open`、`electron_launch`、`native_launch` 中的至少一个一起允许才会出现。单独允许它没有意义，Agent 市场也不会因此把一个浏览器 Agent 显示成「可用」。
- 新部署默认允许。已有部署保留原来的允许列表：升级时悄悄放宽别人的允许列表，正是这个产品不做的事。
- 页面检查员、测试工程师、规程修正员三个内置 Agent 都带着它，人设里写明：碰到密码、验证码、扫码、支付、第三方授权时，调用它请人来做；不要让人把密码告诉 Agent。

## 2. 在画面里操作

点一下画面就进入输入状态，画面四周出现高亮边框。

| 操作 | 说明 |
| --- | --- |
| 鼠标 | 移动、点击、双击、三击、右键、滚轮。坐标按画面的实际尺寸换算成页面坐标 |
| 键盘 | 编辑和导航键（回车、退格、Tab、Esc、方向键、Home/End、翻页），以及带修饰键的单个字母或数字（全选、撤销等） |
| 文字 | 直接打字；中文输入法在上屏后整段送出，组字过程不会发给页面 |
| 粘贴 | ⌘V / Ctrl+V 把剪贴板里的文字送给页面 |
| 复制 | ⌘C / Ctrl+C 把页面上选中的文字（或输入框里选中的部分）放进这台电脑的剪贴板。从密码框复制会被拒绝；复制的内容不经过窗口进程，也不记录 |
| 拖拽 | 按住拖动，滑块、拖拽排序都按页面自己的方式响应。接管期间画面每秒 10 帧（平时 4 帧） |
| 文件 | 页面弹出文件选择时，面板上出现「选择文件…」。系统对话框里选中的文件交给页面；记录里只有「上传 N 个文件」 |
| 对话框 | 页面弹出 alert / confirm / prompt 时，面板上出现「页面提示 / 页面要你确认 / 页面要你输入」卡片；页面等你点「确定」或「取消」 |
| 去别的站点 | 接管期间不受站点范围约束；交还时页面停在哪个站点，这项任务就可以继续用它（生产禁区除外），见 [docs/17](17-sites-and-page-behaviour.md) |
| 新标签页 | 页面开了新标签页（登录弹窗、`target=_blank`），画面跟过去；关掉后回到原来的页面 |

有窗口运行时，独立的 Chromium 窗口仍然可以直接操作，效果一样。

**Electron 应用**：和网页一样，应用的窗口就是被接管的页面。

**原生应用（macOS 预览）**：人直接用应用自己的窗口，不经过画面转发。确认框里写「在应用窗口里完成后，点『交还给 Agent』」，交还时同样可以附一句话。Agent 交还后收到的提示是先 `native_snapshot` 重新观察。

**路径**：窗口 → 主进程（白名单 IPC `browser-input` / `browser-files` / `browser-dialog` / `browser-copy`）→ Runtime worker → `BrowserTools`。
- `input` 在接管之外一律拒绝（`not_in_takeover`）；
- 按键只收上表里那些，坐标、滚动量和文字长度都有上限；
- 输入按到达顺序排队发送，不会乱序。

## 3. 交还

- **交还给 Agent**：可以附一句话，比如「已经登录了，接着检查欢迎语」。Agent 收到的是：
  - 当初请人做什么；
  - 人做了什么（计数）；
  - 附的那句话；
  - 一句明确的说明：人输入的内容不会告诉它，先 `browser_snapshot` 重新观察页面。
- **结束这一段**：任务以「用户接管后结束了这一段」收尾。

附的那句话会原样给 Agent。输入框的提示里写着：别在这里写密码。

## 4. 记录什么、不记录什么

| 记录 | 不记录 |
| --- | --- |
| 点击、按键、滚动的次数，上传了几个文件，回答了几个对话框，复制了几次，下载了几个文件 | 输入的文字、按的是哪个键、粘贴和复制的内容、选的是哪个文件、prompt 里填的内容 |
| 输入了几段文字 | 输入了多少个字 |
| 交还时的页面截图（密码、验证码、银行卡字段被遮住）和地址 | 接管过程中的实时画面 |

「一段」指一次连续的输入：从点进输入框开始，到点击别处、滚动、按回车或 Tab 为止；中间改错字不算新的一段。一开始是按每次输入事件计数的，逐键发送时就成了「输入 27 段文字」，等于把密码长度写进了记录。冒烟测试截图时发现了这个问题，已经改掉。

这段人工操作在各处的样子：
- **工作过程**：一段虚线框，✋，写着计数和附言，带交还时的缩略图。Agent 的请求是一行黄色的「✋ Agent 请你来操作：…」。
- **回放**：一帧 ✋「人工操作：…」，画面是交还时的页面。
- **固化为规程**：会提示「这项任务里有人工操作（例如输入密码、验证码），规程不包含这些步骤」，并建议重放前准备好登录状态，或者让规程从登录之后的页面开始。规程是给机器重放的，不会重放一个人的密码。

## 5. 安全：这一轮查出并修复的问题

**问题**：`ariaSnapshot()` 会把文本框的当前值写进快照（`- textbox "密码": hunter22`），`type=password` 的输入框也一样。这不是接管带来的问题，以前就存在：

| 密码怎么进了输入框 | 结果 |
| --- | --- |
| 页面预填，或浏览器自动填充 | 原样进入发给模型的快照 |
| 人接管后输入，Agent 再观察页面 | 同上 |

**修复**（`packages/runtime/browser.mjs`）：

| 环节 | 处理 |
| --- | --- |
| 快照 | 先从页面读出敏感字段现在的值，再从快照里换成 `••••••`。敏感字段指 `type=password`，以及 autocomplete 为 `current-password`、`new-password`、`one-time-code`、`cc-*` 的输入框。4 个字符以上的值出现在哪里就换在哪里（页面可能回显它）；更短的只换文本框的值，免得把正文里的「42」也换掉。读不出来时（页面正在跳转），**所有**文本框的值都换掉，宁可多遮，不漏一个 |
| 填写 | `browser_fill` 指向敏感字段时，在请人确认**之前**就拒绝。以前要等人点了「执行」才报错。拒绝理由里告诉 Agent 改用 `browser_handoff` |
| 断言 | `value_equals` 指向敏感字段时拒绝，免得 Agent 用断言一位一位试出内容 |
| 截图 | 遮罩的范围从 `type=password` 扩大到上面同一组字段 |
| 界面 | 这类拒绝在工作过程里显示为「⊘ 按规则拒绝」，不算「未通过」 |

## 6. 终端

`mx-rig` 里 Agent 请人来操作时，终端打出一行黄色的「✋ Agent 请你来操作：…」，然后提示 `交还 ›`。
- 在弹出的 Chromium 窗口里做完，回到终端：
  - 直接回车：交还；
  - 写一句话再回车：交还，并把这句话给 Agent；
  - 输入 `q`：结束这一段。
- 用 `--headless` 启动，或者没有图形界面时，没有页面可以交给人：`browser_handoff` 返回 `handoff_unavailable`，Agent 应当说明这一步要人来做。
- `mx-rig exec` 没有人可以接手：Agent 请人时直接停下，退出码 2。

## 7. 覆盖的场景

| 场景 | 谁发起 | 说明 |
| --- | --- | --- |
| 登录密码 | Agent | 冒烟测试和 `tests/takeover.test.mjs` 实测的就是这一条 |
| 短信 / 邮件验证码、图形验证码、滑块 | Agent | 同上。滑块靠画面里拖拽，没有专门测过 |
| 扫码登录 | Agent | 人拿手机扫画面上的二维码 |
| 支付、第三方授权（整页跳转或弹窗） | Agent | 接管期间可以去任何站点，弹窗会被跟过去 |
| 靠 WebSocket 推送结果的扫码登录 | Agent | WebSocket 按页面自己的请求处理，不再一律断开 |
| 上传文件 | 任一方 | 页面弹出文件选择时，面板上出现「选择文件…」 |
| 「确定删除？」这类对话框 | 任一方 | Agent 用 `dialog: "accept"`；人接管时在面板上回答 |
| 滑块验证 | Agent | 在画面里拖动；`tests/takeover.test.mjs` 实测了拖动滑块 |
| 桌面应用里的登录、授权 | Agent | Electron 应用同网页；原生应用由人直接在应用窗口里完成 |
| Agent 走偏了 | 成员 | 点「接管」，把页面带到正确的位置，交还时说一句「设置在右上角头像菜单里」 |
| 先手动走一段 | 成员 | 比如先把一个复杂的筛选条件设好，再让 Agent 接着检查结果 |

## 8. 验证

- **`tests/takeover.test.mjs`**（真实 Chromium）：
  - 接管之外的输入被拒绝；逐键输入加一次改错，仍然记为「输入 1 段文字」；非法按键、越界坐标、未知输入类型都被拒绝；
  - 文件选择：`onChooser` 收到通知，文件交给页面；
  - 敏感字段：填写在确认前就被拒绝，`value_equals` 被拒绝；
  - 一项完整的终端任务，替身模型按脚本驱动：
    1. 填密码被拒绝；
    2. `browser_handoff`；
    3. 人在页面上输入密码并登录；
    4. 带附言交还；
    5. 重新观察页面，断言「欢迎回来」通过。
  - 断言密码不在任何一次模型请求里，也不在任务记录里；快照里是 `••••••`；回放里有 ✋ 那一帧；工作过程的摘要是「打开了 1 个页面，请你接手 1 次，按规则拒绝 1 步」；
  - `redactSecrets`：长值、短值，以及读不出值时全部遮住；
  - `usableTools`：只允许 `browser_handoff`、不允许 `browser_open` 时，它不会出现。
- **`npm run test:desktop -- --browser`**（Electron + 真实 Chromium）：
  1. Agent 请人输入密码，实时画面上出现横幅和交还按钮；
  2. Playwright 点实时画面里的密码框，再用键盘输入密码、按回车；
  3. 画面里出现「欢迎回来，tester」；
  4. 写附言，交还，任务完成；
  5. 工作过程里有人工操作那一段；
  6. 通过 `mxRig.request('missions')` 读出的任务记录里没有这个密码。
- 实测中发现并修复：
  - 输入层继承了全局的 `font: inherit`，`line-height` 变成 0，输入法和打字都进不去，靠提高选择器优先级修掉；
  - 按事件计数泄露密码长度（§4）；
  - 被拒绝的填写在摘要里被算成「1 处未通过」；
  - 回放里「观察页面」显示成了工具名 `browser_snapshot`；
  - 实时画面在负载下偶尔会发出一个空帧：帧已经按时发出后，迟到的节流定时器又发了一次。这是上一轮留下的问题，整套测试连跑时暴露。

## 9. 限制

2026-10-01 放宽的部分：

| 原来的限制 | 现在 |
| --- | --- |
| 允许的 origin 之外照样拦截 | 接管期间去哪里都行；Agent 自己去新站点时问发起人一次 |
| 弹窗被关掉、WebSocket 一律断开 | 跟到弹窗；WebSocket 按页面自己的请求处理 |
| 普通文本框里的验证码不遮 | 按标签、placeholder、name / id 识别 |
| 画面每秒 4 帧，拖拽没测过 | 接管期间每秒 10 帧；拖动滑块已实测 |
| 不能从页面复制 | ⌘C / Ctrl+C 复制到本机剪贴板 |
| 原生应用不支持接管，Electron 没实测 | 原生应用由人直接用窗口；Electron 应用的接管已实测 |

仍然存在的限制：
- 浏览器自己的右键菜单不会出现在画面里，页面自己做的右键菜单可以用。
- 网页工作台没有实时画面：浏览器在执行任务的电脑上，服务端只协调，不转发画面。终端在独立窗口里操作，接管时页面的对话框自动点确定。
- 原生应用里人做了什么无法计数，交还时没有截图。
- 测试账号密码每次都要人输入；下一步见 [docs/17 §6](17-sites-and-page-behaviour.md#6-限制)。
