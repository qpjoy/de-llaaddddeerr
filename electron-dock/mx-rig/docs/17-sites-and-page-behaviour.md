# 站点范围与页面自己的行为：开箱即用

日期：2026-10-01。代码基线：0.8.0 Preview（`feat/mx_insight_hub`）。

## 0. 结论

以前要让 Agent 测一个网页，管理员得先做两件事：
1. 在「Internal 配置」里勾上浏览器工具；
2. 把要去的 origin，连同页面用到的每个资源域名，一个个填进允许列表。

漏了一个，页面就以各种方式坏掉：
- 脚本没加载；
- 接口不通；
- 登录弹窗被关掉；
- 「确定删除？」被悄悄取消；
- 导出的文件被拒绝下载。

Agent 往往只拿到一句「导航超出允许范围」。功能一多，这些前置条件很容易忘。

现在：

| 以前 | 现在 |
| --- | --- |
| 浏览器工具默认关闭 | 新部署默认开启，每一步写操作仍然逐条确认。已有部署在「Internal 配置」里点一下「开启浏览器测试」 |
| 只能去管理员列出的 origin | 管理员的列表变成「不用再问的站点」。其他站点在任务里第一次打开时，确认框里多一行「这是这项任务第一次去的站点」。同一次确认既打开页面，也让这项任务可以使用这个站点 |
| 页面用到的其他域名（CDN、接口、登录框、验证码框）都要加进列表 | 页面自己加载的东西直接放行，只有标签页本身的跳转受站点范围约束 |
| WebSocket 一律断开 | 和页面的其他请求一样处理 |
| `target=_blank` 的链接、登录弹窗被直接关掉 | 浏览器跟到新标签页；新标签页关掉后，回到原来的页面 |
| `confirm` / `prompt` 一律取消，Agent 也不知道 | 结果里写明弹了什么、怎么回答的。Agent 点击时带 `dialog: "accept"` 表示要点「确定」；规程和导出的 Playwright 脚本按同样方式回答 |
| 下载被拒绝 | 存进任务证据，结果里写文件名和大小 |
| 页面跳到范围外时，工具报「导航超出允许范围」 | 不跳转，留在原页面。结果里说明页面想去哪里，以及接下来怎么办：用 `browser_open` 请发起人确认，或用 `browser_handoff` 请人来 |
| 规程只能在管理员列出的站点上重放 | 规程带着自己的站点（基础地址和打开过的页面）。保存规程的人已经看过这些步骤 |
| 管理员没有选择 | 「没有列出的站点」有两个选项：由发起人确认（默认），或者一律不打开（以前的行为） |

**不变的部分**：
- **生产环境禁区始终拒绝**，对 Agent 打开页面、页面自己的请求、规程重放都一样。Agent 想打开生产环境的地址时，在确认之前就拒绝，不会变成一个确认问题。
- 每一步写操作仍然逐条确认。
- 任务级预授权不覆盖新站点：新站点总要问人。

截图（桌面端冒烟测试自动截取，在 `.runtime/qa/` 下）：
- `desktop-site.png`：确认框里的新站点提示；
- `desktop-dialog.png`：接管时页面弹出「确定清除登录记录？」，人在面板里回答。

## 1. 站点范围（`packages/runtime/sites.mjs`）

Agent 要打开一个地址时，有三种结果：

| 结果 | 条件 | 发生什么 |
| --- | --- | --- |
| 直接允许 | 在管理员的列表里，或者这项任务已经确认过这个站点 | 照常确认这一步 |
| 问发起人 | 不在列表里，也不在生产禁区，管理员选的是「由发起人确认」 | 确认框多一行站点提示；确认后记进任务的 `sites`，并留一条事件「本任务可以访问 X（发起人确认）」 |
| 拒绝 | 生产禁区；地址带账号密码；不是 http(s)；管理员选的是「一律不打开」且站点不在列表里 | 不问人，直接把原因告诉 Agent |

一次确认只对那一项任务有效，下一项任务第一次去同一个站点时还会再问。

**接管**：人接管期间，浏览器的任何请求都放行，因为是人在操作。交还时页面停在哪个站点，就把这个站点算作这项任务确认过的，记为「接管时由人打开」。比如走了一遍第三方登录，最后停在登录中心，Agent 接下来可以在那里继续。生产禁区不会这样被加进来；页面停在那里时，Agent 收到的说明会写清楚它不能在这里操作。

**规程**：规程的站点包括基础地址，以及步骤里打开过的完整地址。重放时这些站点算作允许，生产禁区照样拒绝。工位上的回归批次会带上管理员选的站点模式。

**已有部署**：存储里没有这个设置时，按「由发起人确认」处理。这样做不会扩大任何自动化的权限，因为任何新站点都要有人点确认才会打开。想要以前的行为，在「Internal 配置」里选「一律不打开」。

**为什么放行页面自己的请求**：站点范围约束的是 Agent 去哪里，防止页面内容诱导它去别的站点，或者把数据拼进地址带出去。页面自己的脚本、接口、内嵌的登录框和验证码框，属于被测系统本身的行为。以前拦掉它们，页面就坏了，却并没有约束 Agent 能控制的任何东西。生产禁区对这些请求仍然有效。想让测试浏览器只能连列表里的域名，选「一律不打开」。

## 2. 页面自己做的事

每一步工具结果里可能多出这些字段，`notice` 是写给 Agent 的一句话：

| 字段 | 什么时候出现 | Agent 收到的说明 |
| --- | --- | --- |
| `dialogs` | 页面弹出了 alert / confirm / prompt | 弹了什么、怎么回答的；被取消时告诉它用 `dialog: "accept"` 重做 |
| `downloads` | 页面下载了文件 | 文件名、大小、保存位置（任务证据目录下的 `downloads/`） |
| `blocked` | 标签页想跳到不在范围内的站点 | 页面想去哪里、为什么没去、下一步怎么做 |
| `notice` | 以上情况，或者开了、关了标签页 | 一句话汇总 |

`notice` 在桌面端的工作过程里，显示在那一步的说明后面；在终端里显示为一行黄色的 `↳ …`。

**对话框怎么回答**：

| 对话框 | 自动化时 | 人接管时 |
| --- | --- | --- |
| alert | 确定 | 桌面端：面板上出现「页面提示」卡片，人来回答。终端（独立窗口，没有面板）：自动确定 |
| 离开页面的询问 | 离开 | 同上 |
| confirm | 这一步带了 `dialog: "accept"` 就点确定，否则取消 | 同上 |
| prompt | 同上，填 `dialogText` | 面板卡片里有输入框 |

实时画面是截图流，看不到浏览器自己画的对话框，所以由面板把它画出来。页面会一直等到人回答。

`dialog` 参数只在 `browser_click` 和 `browser_press` 上有。确认框里写成「点击『删除』；弹出确认框时点『确定』」。它会跟着这一步进入规程（`{"do": "click", …, "dialog": "accept"}`），也会进入导出的脚本（`page.once('dialog', (dialog) => dialog.accept())`）。

**标签页**：
- 新标签页成为当前页面，实时画面跟过去；旧标签页里的元素引用作废，要重新观察。
- 当前标签页关掉后，回到上一个。
- 新标签页如果要去不在范围内的站点，直接关掉，在 `notice` 里说明。
- 一项任务最多同时开 8 个标签页。

**跳到范围外**：Chromium 拦下跳转后会显示一个错误页。Runtime 退回到原来的页面，Agent 看到的仍然是原页面的快照。

## 3. 没有标注的验证码框

以前只认 `type=password`，以及 autocomplete 为 `current-password`、`new-password`、`one-time-code`、`cc-*` 的输入框。现在还按字段自己的描述识别：标签、placeholder、`aria-label`，以及 `name` / `id` 里出现「验证码、校验码、动态码、短信码、安全码、支付密码、交易密码」或 `otp`、`captcha`、`sms code`、`verification code`、`cvv` 等词。

这些字段的值从发给模型的快照里换成 `••••••`，证据截图里遮住。它们**仍然可以由 Agent 填写**：测试环境常有固定的验证码，例如由发起人在目标里写明「验证码填 123456」。有标注的密码、验证码、银行卡字段，仍然在确认之前就拒绝填写。

## 4. 界面

- **确认框**：新站点多一行黄色提示，`#approval-site`。
- **Internal 配置**：
  - 「没有列出的站点」二选一；
  - 浏览器工具没开时，顶部出现「开启浏览器测试」，点一下勾上全部浏览器工具，保存后生效；
  - 原来的「允许访问的 origin（含资源域名）」改成「预先允许的站点（不用再确认；可以留空）」。
- **修掉的旧问题**：设置页内的「重新绘制」以前画进了一个已经被搬空的 DocumentFragment，所以 Provider 的「上移」「删除」「＋ 新增 Provider」点了之后页面不变。改成在页面上的容器里重画后，这些按钮也恢复正常。
- **页面检查员的人设**：不再说「只能访问允许列表里的 origin」，改成「第一次去的站点会请发起人确认；生产禁区不能去」，并说明怎么读 `notice`、怎么用 `dialog`。
- **终端 `/status`**：「浏览器站点：预先允许 …；其他站点第一次打开时问你」，或者「只允许 …」。

- `tests/sites.test.mjs`（真实 Chromium，一台服务器用 `127.0.0.1`、`other.localhost`、`sso.localhost`、`prod.localhost` 扮演四个站点）：
  1. 三种判定、按任务累加的确认、规程站点的提取；
  2. 「由发起人确认」模式下：
     - 另一个站点的脚本、接口、WebSocket 都通；
     - 生产站点的一张图片也没有发出请求；
     - 没有标注的验证码不在快照里；
     - 跳到别的站点被拦下，页面留在原处，`notice` 提示用 `browser_open`；
     - 新标签页跟过去，关掉后回来；
     - 确认框默认取消、带 `dialog` 时确定，并写进 `action`；
     - 下载的文件内容正确；
  3. 「一律不打开」模式：页面引用的其他站点的脚本和 WebSocket 都被拦下；打开别的站点在确认前就被拒绝；
  4. 接管：
     - 人可以去任何站点；
     - confirm 等人在面板上回答；

## 6. 限制

- **标签页之外不受站点范围约束**：页面内嵌的 iframe 可以加载任何非生产站点。它的内容会出现在快照里，和页面其他内容一样，属于不可信的观察。
- **网络层面的约束**：页面自己的请求不受站点列表约束。如果你的网络要求测试浏览器只能连特定域名，选「一律不打开」，或者用[出网通道](09-egress-channels.md)。
- **终端接管时的对话框自动点确定**：终端没有面板可以画对话框。
- **下载**：没有大小上限，存在执行任务那台电脑的证据目录里。
- **空白弹窗**：先以 `about:blank` 打开、再由脚本写入内容的弹窗，会被当成空白页关掉。
- **网页工作台**：没有实时画面。浏览器在执行任务的那台电脑上，服务端只协调和记录，不转发画面。
- **原生应用的接管**：人直接用应用的窗口，Runtime 数不出做了什么，交还时也没有截图。
- **测试账号密码**：仍然每次要人在画面里输入。下一步可以做「本机测试凭据」：
  - 凭据只存在执行任务的那台电脑上；
  - Agent 只能按名字引用，模型看不到内容；
  - 规程重放时也可以用它登录。
