# 12 · 界面与新人上手

目标写成一句可验收的话：**新来的测试同学拿到网址，用自己的 mx-launcher 账号登录，
不看文档就能跑通一次测试、看懂结果、并登记一条自己的用例。**

## 技术选择：无框架

界面用原生 JS + `@qpjoy/ui-design-neon-void` 的 CSS，没有构建步骤。

设计系统本身就是纯 CSS + tokens，它自己的 demo（`mx-launcher/demos/ui-design-neon-void`）
也是无框架的。视觉与 mx-insight-hub、mx-launcher 完全一致——因为用的是同一份
`styles.css`，不是「照着做的相似风格」。

代价是没有组件复用机制，页面多了会重复。当页面数超过十几个、或者出现复杂的
表单状态时，再换 React 不迟；现在为了七个页面引入打包链路不划算。

> `dist/` 是生成的，全新检出里没有。`manage.sh dev` 和 Dockerfile 都会先跑
> `ui-design/scripts/build.mjs`——漏掉这步的表现是界面完全没有样式，且**没有任何报错**。

## 页面

| 页面 | 给谁 | 回答什么 |
| --- | --- | --- |
| 概览 | 所有人 | 最近怎么样；四步引导指出下一步该做什么 |
| 测试任务 | 测试 | 有哪些任务，点一下跑 |
| 执行记录 | 所有人 | 历史，点进去看详情 |
| 执行详情 | 测试/开发 | 哪条用例失败、失败在第几步、跳到录像那一刻 |
| 应用与用例 | 测试 | 有哪些用例、哪些还没实现；**在这里写用例** |
| 执行机 | 测试 | 桌面测试怎么用自己的电脑跑 |
| 新手指引 | 新人 | 四个概念、三件常做的事、三个易误解的点 |
| 成员 | 管理员 | 谁能做什么 |

## 引导写进布局，不写进文档

新人不看文档。所以引导是页面的一部分：

- **概览的四步条**：注册应用 → 登记用例 → 建任务 → 看报告。已完成的打勾，
  未完成的第一步高亮。这一条同时是进度指示和操作指引。
- **空状态即教程**：没有任务时，列表位置显示的是「怎么建第一个任务」的四步说明，
  而不是「暂无数据」。
- **错误带 `hint`**：`找不到应用 "nope"` 后面跟着「现有应用：compass」。
  一个只说「错了」的错误，等于把人推回去问同事。
- **表单标签解释含义**：`mock —— 用假数据，安全可重复`，而不是干巴巴一个 `mock`。

## 测试同学怎么提供用例

这是 [ADR-0003](adr/0003-git-owned-case-source-of-truth.md)（代码以 git 为真相源）
与「测试同学要能提供用例」之间的解法。它们并不冲突，因为这是两件事：

```
测试同学写「要验证什么」        工程师写「怎么验证」
（界面上登记用例）      ──────>  （仓库里写 spec 代码）
      │                                  │
      │  编号 · 标题 · 前置条件            │  认领同一个编号
      │  每步做什么 / 期望看到什么          │
      ▼                                  ▼
   目录里立刻可见                    执行时产生真实结果
   报告里显示「未执行」        ──────>  报告里显示通过/失败 + 录像
```

**不需要新状态机。** 一条没有代码认领的用例，执行时自然报 `notRun`——平台本来就
在算目录与实际执行的差异。所以「已登记、待实现」不是一个新字段，是既有机制的
自然结果。

流转：

1. 测试同学在「应用与用例」页点「写一条用例」，填编号、标题、前置条件、
   分步的「做什么 / 期望看到什么」
2. 保存即进目录，每份报告里都带着它，标「未执行」，不会被忘掉
3. 点「导出给开发」拿到仓库格式的目录文件（自然语言步骤作为 `_steps` 一并带上）
4. 工程师提交进 git、实现 spec，然后 `catalog:sync`
5. 之后这条用例就有真实结果和录像

两个来源互不覆盖：界面登记的用例 `catalog_file` 是 `__platform__`，
仓库同步只会退役它正在同步的那个文件里消失的用例。仓库来源的用例在界面上
**不可编辑**，改了会返回 409 并说明真相在 git 里。

## 权限

账号来自 mx-launcher，权限由平台自己管（[ADR-0005](adr/0005-federated-identity-and-runner-tokens.md)）。

| 角色 | 能做什么 |
| --- | --- |
| `viewer` | 看执行、报告、录像 |
| `operator` | 加上：写用例、建任务、跑测试、注册自己的执行机 |
| `admin` | 加上：注册应用与套件、调整成员权限 |

**首次登录只给 `viewer`。** 有账号就能看，要动手得管理员显式提升——
这是一次可审计的动作，不是默认值。

## 会话为什么用 cookie

`<video src>` 和 `<img src>` 无法携带 Authorization 头。所以登录后会话放在
httpOnly cookie 里，录像和截图与 API 用同一套凭据。

把 token 放进查询串是另一条路，但它会泄漏进访问日志、浏览器历史和 Referer，
所以没有采用。
