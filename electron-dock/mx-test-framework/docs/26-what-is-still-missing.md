# 26 · 全局复盘：流程通了之后还差什么

写在第一条真实执行跑通、平台部署到 k8s 之后。这时候最容易犯的错是继续加功能，
而不是先看清楚：**已经做好的东西里，有多少是白做的。**

一句话结论：**平台现在只有写它的人能用，而且没有人在看着它。**

## 1. 先看数字，不看文档

| 事实 | 数字 |
| --- | --- |
| 后端接口 | **48 条** |
| 界面真正调用的 | **约 15 条** |
| 界面页面 | 8 个 |
| 配置过的通知渠道 | **0** |
| cron 任务 / 全部任务 | **0 / 7** |
| 趋势图 | **0**（`app.css` 里有一个 `.mxt-spark` 迷你图，JS 里零处引用） |
| 自动清理产物 | **0 → 已修**（`purgeOlderThan()` 曾经唯一的调用者是它自己的测试） |
| 自动备份 | **0**（三份文档写着「每晚的 `pg_dump`」，仓库里没有一行实现） |

**从未有过界面的子系统**：通知渠道、密钥库、审计轨迹、webhook 触发、用例历史、
用例导出、取消执行、编辑/删除任务、**新建与修改套件**。

这些不是没做——服务端全都实现了、都有测试。它们只是**没有入口**。

## 2. 三个「让已经做好的东西白做」的缺口

排序原则就一条：**先补会让既有功能失去意义的洞**，再谈新功能。

### 2.1 一个通知渠道都没配 → 定时任务白做

[18](18-notifications.md) 自己写的：「没有通知的定时任务等于没跑」。适配器、outbox、
只在状态跃迁时通知——全实现了，**零个渠道**。所以现在把任务改成每晚两点跑，
第二天没有人会知道结果。

顺带解释了为什么 cron 任务是 0：**没人敢设**，因为设了也没人看。

### 2.2 没有备份、没有自动清理 → 数据白攒

- `manage.sh clean` 要人手动跑。产物默认留 30 天写在文档里，**没有任何东西在执行它**。
  PVC 迟早满，满的那天所有执行一起变红。
- 「每晚 `pg_dump` 进 OSS」在 [14](14-ci-runners-and-stack.md)、[20](20-secret-store.md)
  和 `manage.sh` 的注释里各写了一遍，**仓库里没有实现**。

  第二条尤其要命：**密钥库「加密落库」这个决定，理由就是那份 pg_dump 会离开机器**
  （[20 §1](20-secret-store.md)）。加密是真的，它防的那个威胁模型是假的——不是说加密
  没用，而是说**我们以为已经在做备份，其实没有**。哪天数据库炸了才会发现。

### 2.3 建套件只能写 curl → 自助接入白做

README 第一句是「测试同学在界面上登记用例」。实际上：

| 动作 | 界面 | 接口 |
| --- | --- | --- |
| 注册应用 | ✅ | ✅ |
| 写一条用例 | ✅ | ✅ |
| **登记套件**（框架、命令、仓库、在哪跑） | ❌ | ✅ |
| 改套件 | ❌ | ✅ |
| 删套件 | ❌ | ✅（今天才加） |

接入一个新项目，**必须有人写 curl 或改 `onboard-luopan.mjs`**。这让 [16](16-multi-stack-platform.md)
「接入新项目零平台代码」只对写平台的人成立。执行机自助接入做得再顺，
下一步还是卡在工程师身上。

## 3. 按角色看

### 3.1 测试同学（每天用它的人）

1. **接新项目要工程师。** 见 §2.3。
2. **用例页只有一个平铺列表**：没有搜索、没有按状态/优先级/模块筛选、没有批量操作。
   罗盘 27 条还能忍，第二个应用进来就废了。
3. **失败之后没有下一步。** 看到红的，答不出三个问题：上次什么时候开始红的？
   是不是已知问题？归谁？`GET /apps/:app/cases/:caseId/history` 已经有了，**界面没接**。
4. **没有 flaky 的概念。** 重试转绿会记 `flaky`，但没有标记、没有隔离、没有
   「这条最近 10 次红了 3 次」。于是不稳定的用例只能靠人记。

### 3.2 项目经理

1. **没有趋势。** 一次执行是一个点，十次执行还是十个点。平台的价值主张里
   「第 5 天能看到趋势」（[09](09-roadmap.md) P1 出口）**没有实现**。
2. **没有版本对比。** run 上钉着 gitSha，但没有「这个版本 vs 上个版本」的视图。
3. **需求覆盖率永远是 0%。** `requirementRef` 字段在、分母算得对，
   **没有人填，也没有界面可填**。
4. **没有可以直接发出去的东西。** 想跟老板汇报只能截图；`?redacted=true` 的脱敏
   报告是单次执行的，不是周报。

### 3.3 程序总监 / 质量负责人

1. **质量信号进不了研发流程。** 不做门禁是 [ADR-0001](adr/0001-standalone-platform.md)
   的决定，我认同；但「不拦截」不等于「不告知」。现在 webhook 只进不出：
   代码推上来会触发执行，**结果不会回到 PR 上**。
2. **没有跨应用总览。** 一个应用一个页面，没有「全部应用一页纸」。
3. **没有成本视角。** 执行时长在涨吗？哪条套件最贵？占了多少机器时间？
   数据都在 `mxt_runs.duration_ms` 里，没有一个视图读它。
4. **没有 MTTR。** 红了多久才有人管——这个数字才是质量文化的温度计，现在测不出来。

### 3.4 运维

1. **平台自己没有监控。** `/healthz`、`/readyz` 有，**没有人在看**；没有 Prometheus
   指标、没有告警。调度器线程死了，你会在第二天早上发现——如果那时有通知的话。
2. **备份、清理**：见 §2.2。
3. **没有并发控制。** 十个任务同时到点就是十个 Job 一起抢资源。runner 上有
   `concurrency`，但**全局没有、按 suite 也没有**。
   （Job 的 CPU/内存 requests/limits 是有的，这点没问题。）
4. **Job 日志随 Job 删除而消失。** `manage.sh clean` 会删掉成功的 Job；
   现在有 `run_events` 兜住了一部分输出，但完整日志仍然是易失的。
5. **恢复没有演练过。** 我今天为了改迁移账本手动 `pg_dump` 了一次——那是这个库
   **第一次**被备份。

### 3.5 安全

1. **所有人共用一个密码。** mx-launcher 登录[至今没有对过真实服务]（[09](09-roadmap.md) 开放项 #6），
   实际用的是 `MXT_ADMIN_TOKEN`。后果是**审计轨迹里的 actor 全是 `service-admin`**——
   [19](19-audit-trail.md) 那套「放开命令白名单之后的保障」因此只剩一半：
   记得下发生了什么，答不出是谁干的。
2. **权限只有全局三种角色**（viewer/operator/admin）。文档设计的「应用级权限」
   （谁能看/能跑哪些应用）没有实现。
3. **审计没有界面。** 有接口、有数据，没人看得到。

## 4. 优先级

按「失效顺序」排，不按「做起来爽」排。

### P0 · 让它不会悄悄坏掉（一周内）

| 事 | 为什么是 P0 |
| --- | --- |
| 自动 `pg_dump` + 一次恢复演练 | 现在有三份文档在描述一件不存在的事 |
| ~~产物清理挂到调度器上~~ ✅ | 已做：调度器每 6 小时扫一次，产物与进度事件同时按 `MXT_ARTIFACT_RETAIN_DAYS` 过期 |
| 配一个通知渠道（飞书/企业微信） | 没有它，下面所有自动化都没有意义 |
| 平台自身的存活告警 | 谁来告诉你调度器停了 |

### P1 · 让红的有人管（两周）

- 用例详情页：接上 `caseHistory`，答出「上次什么时候开始红的」
- flaky 计分与隔离（[09](09-roadmap.md) P5 里躺着的那条）
- 失败归属：一条用例有 owner，通知@到人
- 结果回写 PR（不拦截，只评论）

### P2 · 让非工程师能用（两周）

- **套件的界面 CRUD**——这一条单独就能把「接入新项目」从工程师手里拿走
- 用例页的搜索、筛选、批量
- 任务的编辑与删除（接口有，界面没有）
- 取消执行（接口有，界面没有）

### P3 · 让它产生趋势（两周）

- 应用维度的通过率/耗时曲线（先把那个写好没接的 sparkline 用起来）
- 版本对比视图
- 跨应用总览
- 可发出去的周报

### P4 · 规模化（之后）

- 全局与按 suite 的并发上限
- 分片（现在一个 Job 串行跑完整套）
- socket.io 替换 claim 轮询（[25 §14](25-live-runs-and-runner-onboarding.md) 的 E 步）
- 应用级权限

**P0 之前不要做 P3。** 一个没有备份、没有告警的平台上画的趋势图，是在给一堆随时会
消失的数据做可视化。

## 5. 明确不做

写下来是为了以后不再讨论：

- **不做门禁**——[ADR-0001](adr/0001-standalone-platform.md)。平台是增益，不是前置依赖。
- **不做自研 CI**——[ADR-0006](adr/0006-mxt-absorbs-builds-jenkins-deferred.md) 的条件没变。
- **不做实时录屏推流**——[25 §11](25-live-runs-and-runner-onboarding.md)。带宽和隐私都不划算。
- **不做「AI 自动修复失败用例」**。失败分诊可以辅助，改代码不行：一个会自己改测试
  让自己变绿的系统，比没有测试更危险。
- **不做移动端 App**。这是一个内网工具，浏览器够了。

## 6. 一条贯穿所有角色的话

这个平台目前**所有的价值都发生在有人主动打开它的时候**。P0 和 P1 做完之后，
它才第一次具备「你不看它，它也在替你看着」的能力——那才是「自动化测试平台」
和「一个能跑测试的网站」的分界线。
